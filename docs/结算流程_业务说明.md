# 月末结算流程 · 业务说明（人看）

> 配套档：代码级路径 + 行号 + 通道闸表见 [`结算流程_代码地图.md`](结算流程_代码地图.md)。
> 本档不出现文件名/函数名/行号，只讲「业务上发生了什么、问题在哪」。
> 范围：web 真实运行形态（走真实 LLM 后端 codex），从皇帝颁旨到落库。挖掘日期 2026-06-23。

## 一句话

皇帝下旨后，先把固定财政自动结了；然后由一个 LLM「裁判」推演**本月究竟发生了什么**、写成给皇帝看的月末奏章（月报）；再由一个 LLM「档房」把月报里发生的事翻译成一条条账目；最后「账房」把这些账目落进数据库。

## 三个角色

- **裁判（推演官）**：读当前盘面 + 本月圣旨 + 在办密令 + 候选情势，判定旨意落地后**世界发生了什么**，写成月报。后果是它现判的，不是盘面算出来的——这是这游戏的灵魂（任意圣旨都能被裁决）。
- **档房（书办）**：读月报，把「发生的事」翻成结构化账目（哪笔钱、哪支军、谁升谁黜、哪个局势推进）。它**只翻译、不创作**——理论上月报没写的不该落账。
- **账房（落库）**：把档房翻出来的账目逐条记进数据库（国库、军队、人物、局势……）。

## 流程两幕

### 幕一　颁旨 → 月报

1. 皇帝在诏书台「盖玺颁布」。
2. **固定财政先自动结**：本月的税收、官俸、军饷、宫廷开支、建筑产出，全部按既定规则自动入账——这一段是确定性的、稳的，不经 LLM。同时该硬触发的史实情势也在这步立起来。
3. **裁判推演**：把盘面、圣旨、在办密令、候选情势喂给裁判，它写出本月的月末奏章（月报）。月报边推演边往皇帝屏幕上流（设计意图；实际是否真流式见下「已知问题」）。
4. 月报里若蹦出**需皇帝亲裁的重大抉择**，结算暂停、弹给皇帝选，选完再续。

**月报写完 = 幕一结束。**

### 幕二　月报 → 落库

5. **档房抽账**：读月报，分四个领域（内政 / 军事外敌 / 局势 / 人事密令）并行抽，合成一份完整账目。
6. 账目若整体格式损坏 → 响亮中止、存错误包、可重试（不会半落库）。
7. **账房落库**：逐条把账目记进数据库；坏掉的单条会被拒收、并在月报第二页「窒碍未行」如实告诉皇帝，不连累整批。

## 现在的设计问题（这是要重设计的原因）

把前面那套流程跑起来，会出现一类**靠圣旨刷资源**的漏洞。三个典型例子（玩家社区常用）：

- 圣旨「抄魏忠贤九族」→ 裁判写「抄出家产折银三千万」→ 但游戏里魏忠贤的家产**设计上只值百万**。
- 圣旨配合，翻出「太祖密函」→ 裁判写「某地皇家宝库藏银五千万」→ 这座宝库游戏里**根本不存在**。
- 类似手法还能刷出新军、飞机大炮、蒸汽机火车。

**为什么拦不住，根子有两条：**

1. **裁判手里没有「底数」**。它判「抄某人家能抄多少」时，盘面里根本没有「这人有多少家产」这个数据，于是它只能凭历史印象拍一个（魏忠贤=巨富→三千万）。底数这个东西，全链路目前都不存在。

2. **账房只验「格式」和「指称」，从不验「经济合理性」**。账房会拦「指向一个不存在的人」「金额写成了文字」这种**格式/指称错误**，但它**从不问**：这笔钱有没有合法出处？这个量级合不合理？建这支军扣没扣国库？所以裁判写多大，账房就落多大——一笔格式完好的「内库进银五千万，缘由：太祖宝库」会被照单落库，还会在月报里显示成一笔合法横财。

**关键判断：靠写 prompt 规则叮嘱 LLM「别乱编」是不可能拦住的。** 玩家社区玩的就是和我们一模一样的这套 prompt，照样刷出飞机大炮。规则写得再好，LLM 也会被「有理有据」的故事绕过去。真正的闸只能在**账房那一层**（确定性代码），而要建这道闸，需要两样现在没有的东西：

- **底数据**：游戏里要有「某人家产多少、某库存量多少」这类**可数存量**，裁判和账房才有得对照。
- **经济闸**：账房落每一笔钱要查「有没有合法来源」，建每一支军要查「成本和规模上限」——而不是只看格式对不对。

## 重设计的方向（一句话）

把「世界里有什么、有多少」的定义权**留给设计**（盘面/候选情势/诏书），裁判只负责「在既定世界里判后果、判成败、判比例」，**绝对数量由引擎按底数算、并封顶**。裁判可以判一次进攻成功，但不能往世界里凭空加一座金矿、加一支飞机营。

> 这条原则的完整推演（含「软上限/硬上限都要有」「LLM 判比例·盘面供基数·引擎算 clamp」）应在后续重设计的 ADR 里定稿，本档只记录问题与方向。
