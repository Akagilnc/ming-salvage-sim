- **裁判盘面无「存量」字段**。`build_simulator_payload`（`ming_sim/simulation.py`）喂裁判的公共字段：year/period/decree_text/current_state/treasury_brief/factions_brief/classes_brief/powers_brief/active_issues/candidate_events/previous_narrative_tail/historical_anchor/victory_status/regions/armies/buildings/court_roster/offstage_ministers/deaths/debuts/relevant_memories/**due_commitments**/hitl。**不含 `secret_orders`**（#883：密令分组只进 personnel_secret extractor 独立 rail；simulator 永不预读密令正文，只见派生扁平 `due_commitments`）。

## D. Keystone：所有闸都是「指称闸 + 形状闸」，独缺「经济闸」

把四条通道的闸归类：

- **指称闸**：owner_power 在不在 powers 表 / account 合不合法枚举 / issue id 存不存在 → 拦「指向幻觉实体」。
- **形状闸**：是不是 dict / 是不是整数 / 顶层 key 认不认识 → 拦「格式垃圾」。
- **经济闸**：钱有没有合法来源 / 量级合不合理 / 建军扣没扣库 → **一条都没有。**

⇒ 系统能拦「抄一个不存在的人」「delta='很多'」，**拦不住「抄一个存在的人、抄出天文数字」**——因为没有任何代码问过「这个数字合不合法」。

**这是 prompt 成为唯一防线且必然失败的根因**：apply 层从设计之初只验指称+形状，从没验经济。`cheat_directive`（Ctrl+~ → `CHEAT_NARRATIVE_PREFIX` 拼邸报最前喂 extractor「按字面当既成事实落库」，`decree.py:603`）就是这套信任的官方接口——**作弊控制台与正常颁旨在 apply 层是同一条路。**

---

## E. 重设计靶子

要拦 exploit，只能在 apply 层加经济闸，而经济闸需要两样现在不存在的东西：

1. **可数存量进数据模型**：simulator payload（phase1）无「魏家产/某库存量」，apply 层无「可抄上限」。**封套全链路不存在，须先造。**
2. **绝对量权威从 LLM 收回引擎**，二选一或叠加：
   - apply 层对每笔 money-in 要求「授权来源 token」（无来源即拒）、对每次建军要求「扣库成本 + 规模上限」；
   - 或更彻底：extractor 输出词表砍掉自由绝对量（`economy_moves` 自由 delta / `new_armies` 自由 manpower），改「引用既有实体 + 比例」，绝对数引擎算。

闭合到既有原则：**LLM 给定性+比例，盘面给基数，引擎算绝对值 + clamp**（软上限/硬上限都要有）。代码已确认这不是 prompt 能补的——是 apply 层缺一整类闸 + 数据模型缺「存量」概念。
