# 省级财政基座 · 第二轮外部评审(codex)

> 评审对象:FISCAL_PROVINCE_SUBSTRATE.md(v2)。codex exec,2026-06-09。原文如下。

---

我只基于你贴的 v2 文本评审，不查文件、不运行命令。

**结论**
v2 比 r1 明显进了一大步，六个硬伤里有 4 个是真的修到了结构层，2 个还停在“方向对但账没闭”。最危险的新问题是：**单位制宣称统一成万两/月，但核心公式仍按年额在算**；其次是**存留/起运优先级和“解运到京 - 存留”仍有会计口径冲突**。

**逐条复核**
1. **火耗分账：基本修对了，但还差一个闭账字段。**  
   “火耗进民负担、不进国库公式”这个方向是对的，终于把火耗从“国库折损”里拿出来了。逻辑上也成立：火耗直接增加民侧负担，间接推高逋赋。  
   但现在只写了“入地方官绅”，没有进任何账本字段。它既不进国库，也不进本省可支，那它到底沉淀为 `官绅私囊`、`地方灰色可用财力`、还是只作为腐败压力变量？如果游戏里不能追赃、不能转化成地方动员资源，那“清账追赃/整肃吏治”会缺对象。建议补一个非预算 stock：`地方截留/灰色库藏` 或明确声明“不入可用财政，只影响腐败与追赃上限”。

2. **单位制：没有真修好。**  
   表头说钱流统一 `万两/月`，但公式 `官民田 × 亩率` 是 `万亩 × 两/亩·年 = 万两/年`，少了 `/12`。  
   `三饷应征 = 三饷率 × 官民田` 也有同样问题：三饷率如果是“辽饷九厘”，它不是 0-1 系数，而是 `两/亩·年`。所以“率/系数 0-1”这条会继续误导实现。  
   这是 v2 最大未闭账硬伤。必须统一成：所有年额公式先算 `万两/年`，再除以 12 入 tick；或者全表字段改成 `万两/年`，tick 时再折月。

3. **欠账库存 stock：修对了，但缺“新增欠账”的结算公式。**  
   有 `军饷欠/宗禄欠/官俸欠/民欠旧赋`，方向正确，已经不是只有压力指数了。  
   但还没写每月如何累进：`应付 - 实付` 进哪个 stock，是否允许偿还，偿还优先抵本金还是本月缺口。现在能看出账本意图，但实现者还不能直接写结算器。

4. **存留/起运优先级：方向修了，口径仍冲突。**  
   第 1 节写：`解运到京 = 实际征得 × (1 - 漂没率)`，`本省可支 = 存留份额; 起运 = 解运到京 - 存留`。  
   第 4 节又写优先级第一是“起运定额”，第二才是本省驻军饷。这里有两个矛盾：  
   - 存留到底是在解运前先截留，还是解运到京后再减？现实和游戏账本都更适合先分配：`实际征得 -> 存留池 + 起运池`，起运池再受漂没影响。  
   - “起运定额优先”会把省内军饷拖欠合理化，但第 1 节的 `本省可支 = 存留份额` 像是固定比例，不像优先级分配。  
   建议改成一个明确 waterfall：`实际征得` 先按旨意/定额分配为 `起运应解` 和 `省内可用`；短缺时按优先级决定谁欠；漂没只作用在起运途中，不吃掉省内存留。

5. **AI → 有限 action：修对了。**  
   这次已经从“AI 任意改 delta”收紧成 `action_id + 力度 + 投入资源`，引擎负责算术和 clamp。可以进入实现前的 action schema 设计阶段。

6. **结构化 clamp：修对方向，但还缺 reason_code 枚举。**  
   返回形状是对的：`reason_code/requested_delta/applied_delta/...`。  
   还不能直接实现的点是：`reason_code` 需要枚举，例如 `INSUFFICIENT_FUNDS`、`DISASTER_FLOOR`、`LOW_ADMIN_CAPACITY`、`GENTRY_RESISTANCE`、`TRANSPORT_BOTTLENECK`。否则结构化只是壳。

**v2 新引入的矛盾**
最明显是“率”的滥用：`火耗率/逋赋率/漂没率` 是 0-1 比例，但 `亩率/三饷率` 实际是银额税率，不是 0-1。建议把后者改名为 `正赋亩额`、`三饷亩额`。

另一个是 `漂没/中饱率` 被写在同一行，但前文已经把它们分成“解运口”和“拨付口”。实现时必须拆成两个变量，否则又会把京运损耗和地方拨付贪污混回去。

**剩下的真硬伤**
1. 月/年单位没闭，这是现在最硬的。  
2. 财政 waterfall 没闭：`应征 -> 实征 -> 存留/起运 -> 漂没 -> 到账/欠账` 需要一张唯一口径表。  
3. 火耗截留没有落账对象，导致追赃、腐败、地方灰色财政缺闭环。  
4. 欠账 stock 缺每 tick 累进/偿还规则。  
5. 粮价、粮仓、运输还只是轴，没有进入“粮转银/银买粮/运粮损耗”的结算路径。

**离能开始写引擎还差哪两步**
第一步：先写一张不可歧义的月度结算顺序表。最少要覆盖：年额折月、应征、火耗民负担、逋赋、实征、存留/起运 waterfall、漂没、中饱、实付、欠账 stock 更新。

第二步：把 action/clamp schema 定成枚举。包括 `action_id`、输入资源单位、effect 向量字段、clamp reason_code、每个 action 可触碰的状态白名单。

做完这两步，就可以开始写账本引擎；具体函数 `f(...)` 可以先用占位线性/分段函数，不必等历史校准全完成。
