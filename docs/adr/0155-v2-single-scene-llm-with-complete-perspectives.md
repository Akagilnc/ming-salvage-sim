# 重构首期：一个 LLM 演整场召对，可读材料备齐后自主取阅

Status: proposed（2026-09-09；owner 已拍首期取舍，设计待评审，未实施；本次游戏重构，非独立版本）

首期由一个 LLM 演整场召对，中间层按职责备齐可读材料、由 LLM 需要时自主取阅，而非将全部原文预先塞入上下文，优先还原北极星的连贯演出，不采用每人一个模型或独立导演调用，也不预建长期记忆整理或摘要机制，待实际出现上下文影响后再讨论。
这是重构时对 [0034](0034-minister-audience-fed-perspectival-knowledge-not-omniscient.md) 的多人同场实现所作的明确取舍：同一次调用可看见各在场人物的材料，由 LLM 维持人物视角，但不把全局实况无差别提供给角色，职责区分仍依 [0153](0153-v2-world-record-and-two-way-mediation.md)。
本决定不把世界推演和所有辅助处理合成一次调用，原话及被替代的前案见 [召对取舍依据](../design/game-v2-architecture.md#召对取舍依据)，「一次给全」的含义澄清与不做记忆整理的裁定见 [记忆供料保持简单](../design/game-v2-architecture.md#记忆供料保持简单)，读取形态已定（见下）。
读取形态（2026-09-09，决策票 [#1819](https://github.com/Akagilnc/ming-salvage-sim/issues/1819) owner 拍，原话「给一个地方它自己读」）：每次调用由中间层备一个目录，把该 LLM 可读范围内的材料写成人读文本文件（按人物 / 事务 / 公开说法分列，推演者另有盘面，根目录一行一项索引）；CLI 后端以它为 cwd、用自带只读工具读，API 通道以「列目录 / 读文件」两个工具读同一目录，读材料上两通道一致；目录里只有中间层放的加工材料，角色仍不越过中间层碰 DB。开场默认在上下文里的只有最小集（人物：本人身份与职位、在场诸人、当月日期、正经手事务的名字与当前情况一句、本场已说的话；推演者：当前盘面全量与开着的事务清单），其余想读再读；见闻最近 20 条、章节记忆最近 6 月、上月邸报尾 1500 字、每回合 5 次工具调用等硬上限一并撤除，旧的按需查询工具退役进目录，动作类工具归 #1815 / #1821。已读 = 本场上下文里已取的，跨场不记已读状态。推演者三层全看（实况 + 人物经历 + 公开说法）；人物按职位只读衙门底账（[0034](0034-minister-audience-fed-perspectival-knowledge-not-omniscient.md) 后出注记）；递话人同大臣规则（[0046](0046-message-contract-four-diegetic-roles-thin-system-layer.md) 后出注记）；P4 投影照 [0143](0143-p4-input-side-qualitative-projection-only.md)。未选：无 tool 通道把材料全文放进上下文（owner 明否）；文本信封模拟取阅；只留 API 通道；按月一文件不分人不分事；目录之外再留一套查询工具。
