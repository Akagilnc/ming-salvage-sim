# 哗变状态机：以军心(loyalty)为轴的确定性升降级 + 三振递进伤痕 + LLM 软判恢复

## Context

#299（军事线第一片）= 给「欠饷 → 军心崩 → 哗变 → 补饷滞回解除」一条**最小粗暴**的确定性状态机闭环，不等完整军事系统。设计依据 = [ADR 0023](0023-frontier-pay-source-ratio-and-arrears-reconciliation.md) D11（#287 morale substrate，明文「状态机本体=#299」）+ **CLAUDE.md P2 铁律**（判战永远 LLM 软判、代码只 clamp 不算胜负；软判哲学源 [ADR 0007](0007-province-fiscal-substrate-ai-judged.md)）。**只定设计决策与状态机契约，确切阈值数字 / schema 列名 / 管线落点留 `/tdd`。**

本 ADR 经 `grill-with-docs` 结晶，跑了三道支撑研究：① 晚明兵变史实（≥8 例）；② 代码地基（morale/loyalty 双列实态、现有 trigger_gate、判战软判、结算管线）；③ 中间态台阶数 + 现成机制复用。

**史实结论**：哗变根因 = **持续重欠饷（~4-6 月）侵蚀军心**，非战败（宁远1628 四月欠饷缚帅勒饷却招抚平定未叛、吴桥1631 缺饷哗变据城降金、西北边军半年欠投流寇、己巳勤王军欠饷杀将、1644 京营积欠不战而溃）。战败 → 溃散 / 降敌，非哗变；哗变兵往往能打（**军心崩 ≠ 士气崩**）；客军 / 边军高发；同一欠饷根因按「欠多久 + 有无外部去处 + 主帅威信」分流成 鼓噪(可招抚) / 哗变 / 降敌 三出口。

**关键地基裂缝（grill 实测，附 file:line）**：代码里 `morale`=士气(战斗)、`loyalty`=军心(向背)两独立列；现有哗变门 key 在 loyalty（孔有德 `events.json:83` `dongjiang.loyalty≤42 ∧ denglai.arrears≥6`、李自成 `:351` `jingying.morale≤40 ∧ loyalty≤45`）；但 #287 欠饷公式（`flows.py:509-517`）只扣 `morale`、不碰 `loyalty`，且无任何确定性代码动 army loyalty——**「欠饷→哗变」因果链当前是断的**（欠饷动士气、哗变看军心、军心不被欠饷推 → 哗变门是死门）。且 `constants.py:199` 把中文「军心」别名错指进 `morale` 列。

后出约束：本 ADR 凡「玩家呈现/回流面定性」条款受 **后出** `CLAUDE.md` P7 与 [ADR 0143](0143-p4-input-side-qualitative-projection-only.md) 约束——机制 = 输入侧定性投影；非渲染结构传输**不**授权固定玩家文案；season simulator = 混合调用、按字段分层。

## 决定

单一架构决定：**哗变 = 以军心(loyalty)为轴的确定性状态机，欠饷经新增「军心 tick」驱动，恢复与倒戈交 LLM 软判**。展开为：

1. **（D1）哗变主轴 = 军心(loyalty)，非士气(morale)；本 ADR 修订 ADR 0023 D11 的状态机轴。** #299 新增一条确定性「军心月度 tick」由欠饷驱动 loyalty（与现有哗变门 key 一致）；#287 的 morale tick（欠饷扣士气）不变（欠饷之军确也打得差）——注：ADR 0023 D11① 原以「哗变底料」立此 morale 公式，本 ADR 后 morale 仅 = 战斗士气、**不再是哗变轴**（哗变底料改 loyalty）。**ADR 0023 D11 把触发地板/滞回写成 morale 轴——本 ADR 据 grill 实测正式改为 loyalty 轴**：触发 `loyalty<20 ∧ 欠饷>4月`、滞回 = `is_mutinied` latch + `loyalty≥40 ∧ 欠饷退档` 解闩；**#287 侧 provision 字段为 `is_mutinied(0/1)` 等专用列、不再 provision morale-触发态**（later-doc-wins，仿 0023 修订 0021）。**附带必修（实现期先落，当前代码 `constants.py:199` 仍错指 morale）**：中文「军心」别名从 morale 改指 loyalty（单独 commit）。

2. **（D2）军心 tick = 按欠饷月数分档的确定性月度增量；框架同构 #287 morale tick。** 欠饷月数 = `arrears ÷ army_needed(月应发)`（**不是 ÷10**，`db.py:3848` 双证）；按月数**向下取整 floor 后**分档（floor 示意，精确取整口径留 /tdd——morale tick 用当月 shortfall 比例、无月数取整可对齐，故此口径 #299 自定）：**`arrears==0`（满饷）→ loyalty +5**、`0 < 欠饷 < 3月` → 0(dead-band)、`floor 月数 ≥3` → -5；钳到 `[0, 军心上限]`（+5 严格系于 `arrears==0`、半欠不回血、守「不清欠则不脱困」、与 D6 满饷月同口径）。**框架同构 #287 morale tick**：共用 `owner_power=='ming'` + 非土司守卫，住 `flows.py` 紧邻 morale tick、同一原子事务；**`army_needed==0` 零兵残军（ADR 0023 允许「有旧欠但兵力降 0 的残军」）照 morale tick 短路（`flows.py:491` `needed<=0: continue`）不除零**（零兵的 latch 处置见 D5）。**凡 morale tick 已解的实现 boundary（零兵短路 / projected-SELECT 加列 / 事务边界）军心 tick 照搬，本 ADR 不重复枚举、实现期对齐 #287。** 补饷 / 安抚由 LLM 软判调 loyalty，**单事件 `|Δ|≤15` 且调整后亦 clamp `[0, 军心上限]`**（动态上限是所有 loyalty 写入的唯一硬顶，软判不能突破伤痕 cap）——此钳是对既有 `army_delta.loyalty` 落库路的**新增 gate**、非照搬（现有该路只 clamp `[0,100]`、无 ±15/cap）。**#299 实现范围内全部现有 extractor/season `army_delta.loyalty` 软调 = 空来源，一律 `|Δ|≤15` 再 clamp 军心上限；不存在现行豁免生产路径**（对齐 #318 选项 2 / #320）。伤痕 cap 是所有 loyalty 写入的唯一硬顶、无例外。若未来另票授权真正 event-owned 调用期绑定 id，±15 豁免属该票，非本 ADR 当前交付。阈值示意，精确值 = seed/`/tdd`。

3. **（D3）状态 = 三档 loyalty 实时派生 + 哗变 latch 覆盖（半开区间）。** **派生三档**（未锁存时按 loyalty 现算）：正常（`loyalty≥60`，含死忠 / 优秀 / 一般 战力梯度）/ 不满（`40≤loyalty<60`，软战力 debuff·涣散·行动缓慢，仍听调遣，无事件）/ **鼓噪（`loyalty<40` 未入闩区，含 loyalty<20 但欠饷未达入闩档=鼓噪低端）**（可出事件、仍占军需、勉强听调遣）。**哗变不是 loyalty<20 的自动派生带**——`loyalty<20 ∧ is_mutinied=0` 仍归鼓噪低端；只有 D4 双条件入闩（`is_mutinied=1`）才是哗变。档名 = 状态机/投影词表，**非**固定玩家文案（后出 P7）。

4. **（D4）哗变 = 确定性 latch，唯一持久态。** 进：`loyalty<20 ∧ 欠饷>4月`（`is_mutinied` 0→1）；**锁存**：`loyalty∈[0,40)` 仍判哗变（不弹回鼓噪、**不出 generic 鼓噪事件**——滞回，防「安抚到一半又触发缚帅事件」；**具名历史事件不受此限**，见 D7）；出：`loyalty≥40 ∧ 欠饷退到入闩档以下（示意 ≤4月，/tdd）` → **清 `is_mutinied`，状态回归 loyalty 派生档**（出闩 loyalty 多在 40-60 故通常落不满；2 振 probation 另阻回正常，见 D5）——**LLM 软判 ±15 可抬 loyalty，但欠饷未退档则 latch 续、单独不解闩**（守「清欠才是恢复路、一次砸钱不能秒解」，宁远式补饷+安抚+撑一阵）。后果三条：① **no-op = deny-by-default 白名单**（按字段-效果、非命令意图分类——现有 `军队变化` schema 无 action class，见 Consequences「no-op 意图分类 seam」）：对 latched 军，**除下列放行项外、任何 `army_delta` 字段写入一律 no-op**——**放行白名单**：兵力减（`manpower` delta ≤0 = 裁撤 / 缩编 / 解散，否则零兵哗变军死锁、见 D5）、补饷（economy_moves 清欠）、安抚型 loyalty 软调（恢复路）、`owner_power`（**现行仅经第 3 振确定性转出**、清 latch、经确定性转出适配器施加；**空来源 generic/剧本合并抽取归属对 1/2 振 latched 军 = no-op**，守 D7「1/2振不倒戈」，见 Consequences owner_power 不变式）。**`status` 不在白名单**（也 no-op——哗变叙事由引擎定性适配器出、不许 LLM status 写「已整编 / 移防」污染软判）。即「除解散 / 补救外，哗变军**不可被任何方式重定向 / 强化**」——deny-by-default 一举盖住 兵力增 / `兵种`/`训练`/`装备`/`火器`/`随军大炮`（军备）/`驻扎地`/`commander`（调遣）等一切现有及未来字段、不靠枚举；② 对明 **0 战力**（喂软判 flag、非代码硬判，见 D8）；③ **仍占军需**（继续累欠饷、不补则军心继续 -5）。哗变期间清欠 → 军心仍 +5/月（唯一恢复路）。**确定性 latch 的旨令 no-op 与 [ADR 0011-5](0011-5-four-layer-edict-resolve.md) FF-5 的军队哗变软判正交**：latched 军的旨令后果由本确定性层裁（no-op），FF-5 exec_fidelity 不重复施于已 latched 军（避免双判）。

5. **（D5）三振递进伤痕，由 `mutiny_count` 驱动。** `mutiny_count` **仅在 `is_mutinied` 0→1 进闩边沿 +1**（每次重新入哗变记一次，持续哗变期不重复计）。1 振：标记 + 军心上限 -20（→80）；2 振：上限再 -20（→60）+ **probation**（`mutiny_probation` 存剩余月数，**解闩当月起算、每满饷月 -1、归 0 才可回正常**；probation = **「未转正」flag**——不覆盖 loyalty 派生档、不挡效果，只阻止「回正常」分类：probation>0 时即便 loyalty≥60 也按「不满 / 缓冲」呈现；`mutiny_probation` 与 `full_pay_streak` **同一满饷月一并 --probation / ++streak**、同源累积；probation 期内再哗变 = 直接计第 3 振、probation 作废）；3 振：进哗变即**确定性变流寇**——**同一原子事务内**：先按 [ADR 0023](0023-frontier-pay-source-ratio-and-arrears-reconciliation.md) D7 核销序列（满足 D6 非明军欠饷归零约束）→ **清 `is_mutinied` → 再转 `owner_power`** 到流寇 power id（`bandits` / `bandit_li_zicheng`，**非字面「流寇」串**；合法 power id，FK 现未启用、经 owner_power 写入不变式校验，见 Consequences）——**清 latch 先于改 owner、与 Consequences 写入不变式同序，避免「非明 owner + latch 未清」中间态撞 CHECK**（确定性路与 D7 剧本路同规，防非明军残留 latch / 欠饷未核销坏态）。**零兵残军（manpower==0）：先清 `is_mutinied`（无兵不成哗变）、此清除须在 `needed<=0 continue` 短路之前执行**（勿照抄 morale 短路置于循环顶而漏此清除——`continue` 仅跳过当次迭代、非 break；**且该 `continue` 同样会跳过循环体底部的 `army_logs` 审计写入，故清 `is_mutinied` 与其对应审计日志须一并在 `continue` 之前、同一事务内显式写入提交**，守 P1 审计链完整、勿依赖循环底通用 logger）——防 latched 残军被 tick 跳过而永困 + 整编死锁。

6. **（D6）救赎：满饷连续 12 月 → 军心上限 +10（≤100），`redemption_count` 持久计数。** 「满饷月」= 该月**清欠到 `arrears==0`**（= D2 `arrears==0`→+5 同口径、对齐 flows.py 足额且无旧欠条件）；任一非满饷月 `full_pay_streak` 归 0（连续语义）。**`full_pay_streak` 满 12 → `redemption_count +1` 且 `full_pay_streak` 归 0**（重攒下一个 12，不在第 13 月重复 +10）；和平期可预攒 redemption（well-treated 军更抗哗变、设计认可），cap clamp ≤100 自然封顶超额。`mutiny_count` 与 `redemption_count` 均**终身累计、不因新事件重置**；军心上限 = `clamp(100 − 20×mutiny_count + 10×redemption_count, 下限, 100)`，**下限 = 正常档界（示意 60）**——存活明军第 3 振即转流寇出群、故 cap 对存活明军永不低于正常界，下限只对已转流寇的算术 cosmetic；若伤痕使 cap < 当前 loyalty，下一 tick 把 loyalty 压到 cap。

7. **（D7）倒戈只在第 3 振 = 确定性变流寇；1/2 振哗变不倒戈。** 同一支军第三次哗变即叛出去改换门庭、不可救（同事务序列见 D5）。**1/2 振的哗变不倒戈**——军队赖在原处、不听调遣、无战斗力、仍吃军饷，可补饷安抚救回。既有及未来**具名历史事件（孔有德式）可在事件层作叙事/触发门入口**（建 issue / mark triggered），那是**剧本入口参照、非 #299 确定性后果**；#299 确定性层只第 3 振倒戈。**army_delta 可信降敌特权在现行架构不可达**（普通 situation 无逐事件 army result；`strategic_foreign` 事后分组无调用期 trusted id 绑定）。故 1/2 振不倒戈对**所有空来源**（含 generic 合并抽取、普通 situation/孔有德、strategic 事后分组）一律成立——空来源归属经同一 adapter 对 1/2 振 latched = no-op（见 owner_power 不变式）。若未来另票授权真正 event-owned 调用期绑定来源，特权属该票，非本 ADR 当前交付。**第 3 振 = 永久流寇、同实体不可回明**：既有 `army_delta.归属` 招安 / 归顺通道**不得把 `mutiny_count≥3` 的军改回 `ming`**（owner_power 写入不变式拦截：转入 `ming` 须 `mutiny_count<3`）；招安那势力只能**另建新军**、不复活这支死军。

8. **（D8）一切后果喂 LLM 软判（CLAUDE.md P2 铁律、软判源 ADR 0007），玩家可感通道见定性不见裸值（P4 铁律；另受后出 P7 约束）。** 战力影响是给判定的定性输入（盘面带状态 flag + prompt 正向指引「鼓噪之军战力打折、哗变之军不堪驱使按非战斗裁」），代码只标态、绝不算胜负、不硬改装备数。**P4 边界（中心化钉死）**：season simulator = **混合调用、按字段分层**（不得整体划纯机面；后出 ADR 0143）；纯机面仅指产出不回流玩家的通道（如 extractor / 审计）。玩家可感 LLM 输入通道与非渲染结构传输须去裸数、用档名定性——**非渲染结构传输不授权固定玩家文案**。**大臣 agent 虽是 LLM、但其叙事回流给皇帝**，故喂它的军表也须定性（不能按「LLM-facing=raw」放行）。#299 交付**输入侧定性投影 + 非渲染结构传输**（不示 loyalty 裸值 / mutiny ordinal）；**既有 morale / loyalty 在 LLM 输入侧的裸显是相关 P4 旧债**——#299 投影顺带覆盖输入侧，未覆盖部分作 P4 cleanup 单列（不阻塞本片核心，DoD 以输入侧覆盖为准）。

## Consequences

- **接缝 → #287（`blocked_by`）**：#287 须交付 (a) 哗变状态列 provision、(b) `is_tusi` 字段及 morale 公式守卫；本 ADR 把「军心 tick + 状态机本体」划归 **#299 owns**（住 `flows.py`、紧邻 #287 morale tick、同一原子事务，boundary 同构见 D2）。#287 的 per-source 记欠迁移对本切片透明（触发读欠饷合计），可后于本切片落、不阻塞。
- **月末顺序（钉死，落 ADR 0023 D4 相位图）**：`财政 settle(③④) → morale tick → 军心 tick → 状态判定/latch/count/probation → 事件 gating →（pre_settle commit 后）LLM season_simulator delta（读已提交的 mutiny_count/redemption_count 派生上限、clamp）`。故 **LLM 当月调 loyalty 不影响同月哗变判定**（最早下月起作用）。
- **存储**：新增 armies 列 `is_mutinied(0/1)` latch · `mutiny_count(int, default 0)` · `mutiny_probation`（2 振剩余缓冲月、default 0） · `full_pay_streak`（满饷连续月、default 0） · `redemption_count(int, default 0)`——均**确定性引擎独占写、不入 extractor 别名表、不塞 `status` TEXT**（status 是 LLM 可写自由文本、会被 delta 污染）。军心上限由 `mutiny_count / redemption_count` 派生（见 D6）。**读取路径分两类**：`db.py` restore / roster 是 `SELECT *`、自动带回新列（满足 P1）；**`flows.py` 军饷 tick、`simulation.py` simulator payload、extractor 盘面均是 projected `SELECT`、不自动带新列**——凡要让新状态进 tick 参与或进 LLM 视野（D8 flag 进 TSV），须把相应列**显式加进各自 SELECT**（实现期对齐 #287 同类改动）。
- **owner_power 写入不变式（架构级）**：任何既有军 `owner_power` 变更——第 3 振确定性转出 **+** 剧本 / LLM `army_delta.归属`（投敌 / 归顺，提示词已在用）——须经**同一转出适配器**：校验目标 power id 存在 → 按 0023 D7 核销欠饷 → 清 `is_mutinied` → 再改 owner。**latched 军（`is_mutinied=1`）的 owner-OUT 倒戈现行仅经第 3 振确定性转出（清 latch）**；#299/#318 **不**引入可信 id 载体——落库路按**空来源**消歧：所有现有剧本/LLM `army_delta.归属` 对 1/2 振 latched 军一律拒收 / no-op（守 D7「1/2振不倒戈」）；对非 latched 军照常经本适配器。**唯一现行 latched 转出口 = 第 3 振确定性**（经同一 adapter）。另票授权真正 event-owned 调用期绑定 id 之前，**不得**从自由文本/事后锚点伪造 trusted id（对齐 ADR 0142）。更广的「结构化命令意图分类」（按意图分全类命令）仍 = #311（更重、不同层、#299 不依赖）。**不依赖 SQLite FK**（实测 `PRAGMA foreign_keys=0`、未启用）、不走裸 `army_delta` text 直写绕过校验。**转入 `ming`（招安 / 归顺 / new_armies）须满足 ① `mutiny_count<3`**（拒绝 `mutiny_count≥3` 的军经 `归属` 回明、守 D7「永久流寇不可回明」、招安另建新军）**② [ADR 0023](0023-frontier-pay-source-ratio-and-arrears-reconciliation.md) D6 全部「转入-ming」义务**（同事务设饷源省 + 省/中央比例、fail-loud、防白嫖军）。可加 DB CHECK `owner_power=='ming' OR is_mutinied==0` 作兜底不变式（具体落 /tdd）。
