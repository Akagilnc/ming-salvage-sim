# ADR 0010：呈现适配器 —— 有状态实体的读取端契约

状态：草案（待评审 · 实现排在 ADR 0009 之后）

## 背景

段适配器（ADR 0008）统一了**写入端**：一类有状态实体一个落库单元，接口「items 进 → applied/rejected+原因+来源 出」。

**读取端**——有状态实体渲染成喂 LLM 的文本——没有对应契约，散在 **48+ 处**手拼渲染：

| 实体 | 渲染点数 | 漂移实证 |
|---|---|---|
| 人物 | 6–8 | 两套「你当前扮演」头：`registry.py:437`（后宫路径，内联含 summary）vs `registry.py:494`（大臣路径，经 `context.py:153` `character_context` 渲染、缺 summary）→ 大臣个人简介可见性看代码路径 |
| 军队 | 5 | 同一军队 roster 17 字段 / simulator 19，列序还不同（`db.py` payload 另有变体） |
| 地区 | 4 | payload 16 字段 / simulator 18（多 city_level/cannon/corruption） |
| 建筑 | 4 | report 10 / payload 12 |
| 事项 | 3–4 | |
| 势力 | 3 | |
| 派系 | 2 | 仅 prose，从未结构化 |

已有**半个 seam**：`_auto_table()`（`simulation.py:214`，array-of-dicts → `{cols,rows}` TSV）。六类实体都过它转 TSV，**但每个实体各自手拼 row**（自己的 SQL + dict 映射），row 构造没统一。

## 决定 1：呈现适配器 = 段适配器的读取端孪生，不合并

每类有状态实体一个**独立**的呈现适配器（读），与段适配器（写）**并列、在同一 per-实体 registry 登记**。

不合并成单一「实体适配器」的理由：写（delta items → DB）与读（model/DB → LLM 文本）**数据流相反、输入不同、代码位置不同**，是两个 seam；one adapter ≠ 把反向数据流塞进同一接口（deletion test：硬并是捆两件不相干的事，不concentrate 复杂度）。registry 共置保证「实体 X 的写适配器 + 读适配器」一处可寻，locality 不丢。

## 决定 2：呈现两形状 —— 名册行 + 全档，字段集进契约

- **名册行**：一实体作列表/表格的一行。**列集进契约，但支持按调用点列投影**：契约钉死的是**每列的 canonical 渲染（列名/取值/顺序）+ 可用列全集**，不是「每次返回同一 N 列」。窄（name+status，旧「一句话索引」）、宽（加 office/派系）由消费者取子集——**只取消费者真用的列**，不往 schema 灌冗余（与 ADR 0009 消费者纪律一致）。「一句话索引」= 名册行的最小列集，**不单列为第三形状**。机面，走既有 `_auto_table` TSV。
- **全档**：一实体在焦点时的完整档案（人物标签/忠诚-能力-清廉-胆略/风格，**带数值**），喂扮演 agent 与 `inspect_*` 工具。机面，prose。

字段集进接口 → 军队 17/19/20 三处漂移被接口逼齐，desync 在测试期暴露（**interface 即 test surface**）。

`present_consort_candidates`（后宫选秀候选名单）本质是「一批人的全档列表」，算全档的复数用法，不单列形状；后宫完善时再议。

## 决定 3：P4（皇帝看不见数值）是横切保证，不是渲染形状

**机面 / 人面的界定（先划线，免得误读）**：全档与名册行是**机面**——喂裁判 / 扮演 agent 的 system prompt / simulator payload / `inspect_*` 工具。**机面带数值是设计本意，不算 P4 违规**（数值是驱动 LLM 的隐藏燃料，玩家看不见）。P4 只管**人面**——直接给皇帝看的渲染。

现状：玩家只见 **LLM 输出**（邸报、大臣开口），有状态实体字段**从不直接渲染给皇帝**——唯一**玩家面**漏点 `skills.py:88` 的 debug print（`属性：忠诚X | 能力Y`）。（`db.py` 的 army_brief/army_detail 等也吐裸数值，但消费者是 inspect 工具 / simulator payload = 机面，属允许范畴。）

故 P4 **不做成「人面渲染方法」**（那是空槽，将来 web 人物面板才需要），做成横在所有渲染之上的保证。**守门测试的扫描面 = 玩家面**（CLI 终端 print + 邸报装配路径），**排除** agent system prompt / inspect 工具 / simulator payload 这些机面全档：

- **构造级**：没有任何呈现方法把原始数值吐给玩家面；数值→定性映射（若将来需要人面渲染）是呈现适配器私有。
- **测试级（钉死）**：回归测试扫人面输出 + 邸报装配路径，**出现裸数值即红**——P4 从「prompt 口头纪律」变成 CI 守门。
- 顺手堵 `skills.py:88`（降 dev-only 或迁人面）。

将来真出直渲玩家面板，再加人面方法、强制过数值→定性映射。

## 与既有契约的咬合

- **写入端孪生**：ADR 0008 段适配器。
- **第一个读取端实例**：ADR 0009 决定 9「消费者纪律」（无消费者字段不进 schema、字段跟读取端同 PR 闭环）+ 决定 10「人才池视图 = 读取端」。本契约把那条纪律从一个特例**推广到整个有状态实体家族**。

## 验收（实现 PR 用）

- 48+ 散落点全迁进各实体的呈现适配器；`_auto_table` seam 复用不动。
- 名册行 / 全档字段集有断言测试（钉死列集，咬住军队三处漂移）。
- P4 守门测试：**玩家面**（CLI 终端 print + 邸报装配路径）无裸数值（红/绿）；不扫机面全档。
- 人物两套扮演头（`registry.py:437` 后宫 / `registry.py:494` 大臣，后者经 `context.py:153` `character_context` 渲染）合一 —— 作为安全第一刀（候选 C）。
- 派系有字段（满意度/筹码），迁移时给它结构化名册行档（机面、数值），不留「仅 prose」黑洞；当前无真正无字段的实体，故不需要 prose-only 豁免分支。

## 实现时机

**全量呈现适配器迁移排在 ADR 0009 落地之后**：0009 此刻活在 `simulation.py` 的 court_roster / 人才池里，现重构会正面对撞。

**候选 C（人物扮演头合一）例外，可与 0009 同期顺手带**：它碰的是 `registry.py:437/494` + `context.py` 的格式化器，**不碰 0009 在改的 `simulation.py` court_roster/人才池**，与全量迁移解耦，故不受「排 0009 后」约束。

## Consequences

- CONTEXT.md 收词：呈现适配器。
- 移除 6 实体 × ~4 渲染点 × 多字段集变体 ≈ 48 个手拼点，塌进 6 个深模块（locality：字段决策集中一处；leverage：一接口 N 调用点）。
- 派系首次获得结构化名册行档。
- `skills.py:88` 这类 P4 漏点被守门测试钉死，不再靠自觉。
