# ADR 0010：呈现适配器 —— 有状态实体的读取端契约

状态：草案（待评审 · 实现排在 ADR 0009 之后）

## 背景

段适配器（ADR 0008）统一了**写入端**：一类有状态实体一个落库单元，接口「items 进 → applied/rejected+原因+来源 出」。

**读取端**——有状态实体渲染成喂 LLM 的文本——没有对应契约，散在 **48+ 处**手拼渲染：

| 实体 | 渲染点数 | 漂移实证 |
|---|---|---|
| 人物 | 6–8 | 两套「你当前扮演」头：`registry.py:437`（后宫路径，内联含 summary）vs `registry.py:494`（大臣路径，经 `context.py:153` `character_context` 渲染、缺 summary）→ 大臣个人简介可见性看代码路径 |
| 军队 | 5 | 同一军队 roster 17 字段 / simulator 19，列序还不同（`db.py` payload 另有变体） |
| 地区 | 4 | payload 16 字段 / simulator 18（多 city_level/cannon/corruption） |
| 建筑 | 4 | report 10 / payload 12 |
| 事项 | 3–4 | |
| 势力 | 3 | |
| 派系 | 2 | 仅 prose，从未结构化 |

已有**半个 seam**：`_auto_table()`（`simulation.py:212`，array-of-dicts → `{cols,rows}` TSV）。region/army/building/character/power **过它转 TSV，但每个实体各自手拼 row**（自己的 SQL + dict 映射），row 构造没统一；Faction 仅 prose、Event 走 `issue_to_payload` —— 连「过不过 `_auto_table`」本身都不一致，也是散落的一种。

## 决定 1：呈现适配器 = 段适配器的读取端孪生，不合并

每类有状态实体一个**独立**的呈现适配器（读），与段适配器（写）**并列、按 per-实体 共置**。

> **「共置」是本 ADR 要新引入的实体适配器目录/索引,不是复用现成基建**：① 不是 `registry.py` 的 `MinisterRegistry`（那是 agent 刷新用的运行时登记，别撞术语）；② 0008 的写侧也**没有**「registry」——`applier.py` 是 0008 的契约类型 / `RejectionCollector` / `atomic` helper，而各 section 的落库逻辑仍住在 `apply_score_extraction`（`issues.py`）/ `GameDB` / issue 路径里、由 `decree.py` 桥接（section 原地迁入、未集中）。本 ADR 需明说这些**现有写主**如何登记/包进新目录。共置只是一条**约定**：实体 X 的读+写适配器一处可寻。

不合并成单一「实体适配器」的理由：写（delta items → DB）与读（model/DB → LLM 文本）**数据流相反、输入不同、代码位置不同**，是两个 seam；one adapter ≠ 把反向数据流塞进同一接口（deletion test：硬并是捆两件不相干的事，不concentrate 复杂度）。共置约定保证「实体 X 的写适配器 + 读适配器」一处可寻，locality 不丢。

## 决定 2：呈现两形状 —— 名册行 + 全档，字段集进契约

- **名册行**：一实体作列表/表格的一行。**列集进契约，但支持按调用点列投影**：契约钉死的是**每列的 canonical 渲染（列名/取值/顺序）+ 可用列全集**，不是「每次返回同一 N 列」。窄（name+status，旧「一句话索引」）、宽（加 office/派系）由消费者取子集——**只保留消费者真用的列**，不往 schema 灌冗余（与 ADR 0009 消费者纪律一致）。「一句话索引」= 名册行的最小列集，**不单列为第三形状**。机面，走既有 `_auto_table` TSV。
- **全档**：一实体在焦点时的完整档案（人物标签/忠诚-能力-清廉-胆略/风格）。**两个变体**（决定 3 的 agent 回话漏路所迫）：**带数值版**喂非军事 `inspect_*` / extractor / simulator payload（纯机面、不经 LLM 回话回流玩家）〔2026-07-19 0143 后出为准：simulator 混合调用（判定+写邸报同调用）的**角色属性字段**改档位词，P2/世界事实数值照旧；非军事 `inspect_*`/extractor 全档照旧。**不得**再授权军事 `inspect_army`/`army_detail` 吃军情裸值——二者属 #321 玩家可感 LLM 输入装配（产出经 LLM 可回流玩家，见 0143「产出是否回流玩家」），军心/士气/欠饷走定性〕；**定性版**（忠诚:极高，非 `90`）喂**扮演 agent**——因为 agent 的回话会到皇帝面前，给它裸数值=它能照念（见决定 3 ⚠️）。同一全档形状、两档投影，由呈现适配器出。机面，prose。

字段集进接口 → 军队 roster 17 / simulator 19 等多处漂移被接口逼齐，desync 在测试期暴露（**interface 即 test surface**）。

`present_consort_candidates`（后宫选秀候选名单）是**呈御览 = 人面**（**不是机面全档的复数用法**）。但其御览输出**当前不含裸属性数值** —— 输出块只拼 name/性情/特质/summary，loyalty/ability 仅作 `Character(...)` 构造 kwargs 落库、从不进返回串（`registry.py:390-405`，三家 R5 实核）。故它是个**人面待防点**而非现状漏点：将来御览若改吐属性才会漏。本 ADR 不展开（随后宫工作 defer），但分类归人面候选册、纳入 P4 守门面：迁入时走**人面渲染**（将来加的人面方法，从同字段做**定性化**呈现、无裸属性数值；**不是**机面 TSV 名册行直渲——TSV 是喂 LLM 的，人面要适配前端卡片/对话，cmr 线上 R2 gemini）。

## 决定 3：P4（皇帝看不见数值）是横切保证，不是渲染形状

**机面 / 人面的界定（先划线，免得误读）**：名册行、全档（带数值版）是**机面**——喂裁判 / simulator payload / 非军事 `inspect_*` 工具，这些**不把数值回流玩家**。**机面带数值是设计本意，不算 P4 违规**（数值是驱动 LLM 的隐藏燃料，玩家看不见）。〔2026-07-19 0143 括注：simulator 因混合调用产玩家邸报，角色属性字段除外——见决定 2 括注；**军事 `inspect_army` 产出经 LLM 装配可回流玩家，不得再称纯机面不回流**——军情轴见 0143〕P4 只管**人面**——直接给皇帝看的渲染。**注意扮演 agent 是特例**：它也是 LLM，但**回话回流皇帝**，故拿的是全档的**定性版**（决定 2 / 下方 ⚠️），不是数值机面。

> **⚠️ 一个机面≠安全的漏路（cmr 线上 R1 codex 抓，P2）**：扮演 agent 的 system prompt 拿了裸数值（`character_context_with_db`，`registry.py:494`），而 **agent 的回话经 `web_app.py:1218` / `terminal.py:244` 直接给皇帝**——玩家问「你忠诚几何」，LLM 手里有确切数值就能照念。**扫渲染方法/fixture 抓不到 LLM 复述**，所以「喂 agent 数值=机面=安全」不成立。P4 的保证必须额外覆盖这条。**优先方案 (a)：全档喂 agent 改用定性档**（忠诚:极高，非 `90`）——agent 根本没有可念的精确数，从源头根治。**方案 (b)（对玩家面 LLM 回话运行时脱敏）只作脆弱兜底**：自由文本脱敏既易误伤世界事实数值（崇祯 3 年 / 1000 兵 / 银两），又漏 LLM 变体表述（「九十」「将近九成」「90%」），不能当主防线（cmr 线上 R2 gemini）。机制最终留实现 PR，但本 ADR 钉死：**守门面 = 确定性引擎产物面（上下文构造 / 渲染 / 装配）；源头定性化（方案 a）**。〔2026-07-19 括注，0142/0143 后出为准：方案 (b) 废止；测试级「扫 LLM 回话出现裸属性即红」废止，P4 守门收缩到确定性引擎产物面（上下文构造/渲染/装配）；决定 3 的「simulator payload＝带数值版」在角色属性字段上改档位词，其余字段照旧——见 0143〕

现状：玩家大多只见 **LLM 输出**（邸报、大臣开口），有状态实体字段**几乎不直接渲染给皇帝**——已知**一处真玩家面漏点**：`skills.py:88` 的 debug print（`属性：忠诚X | 能力Y`，`terminal.py:138` 调用）。另一个**人面待防点**：选秀候选 `present_consort_candidates`（呈御览=人面，但御览输出当前不吐属性数值、见决定 2；将来御览若改吐才漏，随后宫工作 defer）。（`army_detail`/`inspect_army`＝#321 玩家可感 LLM 输入装配，军情三键定性，判据见 0143「产出是否回流玩家」。）

故 P4 **不做成「人面渲染方法」**（那是空槽，将来 web 人物面板才需要），做成横在所有渲染之上的保证。**守门面 = 确定性引擎产物面（上下文构造 / 渲染 / 装配，ADR 0143；不分 CLI/web，#96）**——覆盖确定性呈现与 LLM 输入装配路径；**排除** 非军事 / 确实不回流的 inspect 工具与 simulator payload 这些纯机面。**不得**将军事 `inspect_army` 一概排除出玩家边界讨论——按 0143 回流判据，它属 #321 玩家可感 LLM 输入装配面（P4 守门仍落确定性引擎产物/装配，不恢复 LLM 回话扫描）。**扮演 agent 喂定性档（方案 a）**：prompt 里本就无裸数值，不另开回话扫描面。

- **构造级**：没有任何呈现方法把**角色属性数值（忠诚/能力/清廉/胆略等）**吐给玩家输出边界（世界事实数值不在此限，同测试级口径）；数值→定性映射（若将来需要人面渲染）是呈现适配器私有。**并堵 agent 回话漏路**（见上方 ⚠️）：全档喂 agent 用定性档。〔2026-07-19 0143 后出为准：(b) 脱敏路废止，唯一合法路＝定性档〕
- **测试级（钉死）**：回归测试扫确定性引擎产物面（上下文构造 / 渲染 / 装配），**出现裸角色属性数值即红**——禁的是**角色属性**（忠诚/能力/清廉/胆略等）；**世界事实数值（年/月/银两/兵额/城防门数等）是玩家本就该见的，不禁**。〔2026-07-19 0143 后出为准：本测试级条款中「LLM 回话」扫描废止，守门收缩到确定性引擎产物面（上下文构造/渲染/装配）〕**匹配基于结构化角色字段 / 最终渲染结果**——即「这个人物在 DB 的实际属性值出现在给玩家的文本里」就红，**不是脆弱的「字段名+其值」子串**（否则漏 `忠诚度:95`、`张三(95/80/70/60)` 这类变体/无标签裸排，cmr R1 gemini+coderabbit concur）。P4 从「prompt 口头纪律」变成 CI 守门。
- 顺手堵 `skills.py:88`（降 dev-only 或迁人面）。

将来真出直渲玩家面板，再加人面方法、强制过数值→定性映射。

## 与既有契约的咬合

- **写入端孪生**：ADR 0008 段适配器。
- **第一个读取端实例**：ADR 0009 决定 9「消费者纪律」（无消费者字段不进 schema、字段跟读取端同 PR 闭环）+ 决定 10「人才池视图 = 读取端」。本契约把那条纪律从一个特例**推广到整个有状态实体家族**。
- **与 0009 决定 10 措辞调和**：0009 说人才池视图「裁判与玩家都看得见」——指玩家**经 LLM 输出获知**该信息（reason_code 等定性枚举），非把盘面 TSV 直渲给玩家。与本 ADR「盘面 TSV = 机面、玩家不直接见」不冲突：TSV 喂 LLM，玩家只见 LLM 转述。

## 验收（实现 PR 用）

- 48+ 散落点全迁进各实体的呈现适配器；`_auto_table` seam 复用不动。（呈现适配器的具体接口签名留实现 PR 定；本 ADR 只钉契约：两形状 + 列集 + P4 守门面。**接口方法返回类型一致**——名册行 / 全档各自声明确定返回类型，不按运行时入参动态返回 `str`/`list`/`dict`，免调用方解析死分支，cmr R1 gemini。）
- **新建实体适配器目录/索引**（决定 1 的「共置」落地）：定义这个 per-实体目录，**读适配器登记进去**，并明确 0008 的写侧落库主（`apply_score_extraction`/`GameDB`/issue 路径，`applier.py` 提供契约+collector+atomic）如何登记/包入 —— 这条不做，「共置」只是空话。**目录用 lazy import / 仅注册接口路径**，不在初始化同步加载 `issues.py`/`GameDB` 等重模块，防与写侧核心模块循环依赖（cmr R1 gemini）。
- 名册行 / 全档字段集有断言测试（钉死列集，咬住军队漂移；实现 PR 钉 canonical 列集前先枚举 simulator 侧实际列数作可查基线 —— 现 roster 17 已实核，simulator「19」与 `db.py` 第三变体待枚举）。
- **扮演 agent 喂定性档（落实方案 a）**：`registry.py:494` 这条召对路径的全档投影改定性版（无裸数值），agent 没有可念的精确数——这是「源头根治」真正落地的验收点，不是只测渲染边界。
- P4 守门测试〔2026-07-19 0143 后出为准：LLM 回话不扫，面收缩到确定性产物〕：扫**确定性引擎产物面**（上下文构造 / 渲染 / 装配）无裸角色属性数值（红/绿）；agent 在采纳 (a) 喂定性档后不另扫回话。**用哨兵值防假阳**（codex/gemini 线上 R3）：测试库把人物属性设成偏门哨兵数（如忠诚 97 / 能力 83 / 清廉 61），只查哨兵是否泄漏到玩家面——避免常规属性值（90/80）与世界事实数值（崇祯 3 年 / 90 人 / 80 万两）重合导致误红。
- 人物两套扮演头（`registry.py:437` 后宫 / `registry.py:494` 大臣，后者经 `context.py:153` `character_context` 渲染）合一 —— 作为安全第一刀（候选 C）。**合一取并集、保留 summary**：现 437 含 summary、494 缺，统一后的全档必须带 summary，大臣路径不再丢。
- 派系有字段（满意度/筹码），迁移时给它结构化名册行档（机面、数值），不留「仅 prose」黑洞；当前无真正无字段的实体，故不需要 prose-only 豁免分支。

## 实现时机

**全量呈现适配器迁移排在 ADR 0009 落地之后**：0009 此刻活在 `simulation.py` 的 court_roster / 人才池里，现重构会正面对撞。

**候选 C（人物扮演头合一）例外，可与 0009 同期顺手带**：它碰的是 `registry.py:437/494` + `context.py` 的格式化器，**不碰 0009 在改的 `simulation.py` court_roster/人才池**，与全量迁移解耦，故不受「排 0009 后」约束。

## Consequences

- CONTEXT.md 收词：呈现适配器。
- 移除 6 实体 × ~4 渲染点 × 多字段集变体 ≈ 48 个手拼点，塌进 6 个深模块（locality：字段决策集中一处；leverage：一接口 N 调用点）。
- 派系首次获得结构化名册行档。
- `skills.py:88` 这类 P4 漏点被守门测试钉死，不再靠自觉。
