# 0100: 评审交卷契约——穷尽可见面，fixer 首务验真，一切评审模式统一

## 决定

评审腿的交卷标准从「挖到可钉死的发现即可收工」改为**穷尽本轮可见面**：一轮内把看到的所有 blocking 发现全部报出后才算交付完成；发现全数进修复单、不分「已演练/未演练」档，**fixer 的第一个任务是逐条实证发现真伪**（真→修+同类横扫，假→带证据 refute 留痕，由下轮 fresh 复审员对留痕做处置）；本契约适用**一切评审模式**（家族 completeness/correctness、per-slice、doc 模式），落在 ak-cross-m-review skill 单一来源，不在编排器 prompt 层复刻第二份。

## 根因（#860 实证，2026-07-12 夜）

21+ 轮 CMR 的串行不来自任何指令或计时器（prompt 无塑形语言；唯一的钟是 900s 无输出 hang 守卫，流式中的腿永不封顶）——来自交卷契约缺口：`CMR-VERDICT` 只认 findings|converged，报 1 条与报 5 条同为合法交付，理性的腿在凑够 2-3 个演练钉死的类后自主收卷，剩余面留给下一轮（每轮 15-20min 复审+8-35min 修复的整轮开销）。修复侧横扫教义（EXAM-818，6→1）已消灭同类复发；本决定把同一哲学对称到发现侧。残余轮次=递进暴露（修复后才可见的洞），不可消灭、不作为本契约的失败判据。

## 后果

- 单轮复审变重（40-60min 吐全轮），换掉「每类一轮」的 N 轮税；理论地板=找全→修全→验清的 2-3 轮。
- refute 不改 runner 信封语义：复审员按键位收账照旧，同意 refute 记 verified-closed，不同意重新点名。
- fresh 全量复审纪律、#597 无轮上限、复审员自升级出口、doc 模式 ②-⑤ 防加性跑飞纪律全部原样保留（吐全指「发现」不指「建议加字」）。
- 验收按 #860：#786 遥测 review_round 计数，基线=2026-07-12 夜（completeness 12 轮 / correctness 10+ 轮）。
