# 国库帝国修正只作用收入，不放大支出（库出=下令额；修正上游对称代码）

Status: Proposed（2026-06-23 重写——前两版诊断全错，读落账代码 + git blame + 存档物证后定真因）

## 背景（真因，证据齐）

dogfound F11：玩家下令拨 N，库实扣 ≈ N×1.12（西学令 50 → 扣 56、清册 10 → 11、陕西赈抚/关宁 20 → 22）。

**实测 + 读码 + 存档定位（前两版误诊为 LLM markup，全废）：**
- LLM / extractor 存的金额**一直是对的**：`fiscal_config.徐光启三务公费_base = 50`、承诺 issue `ongoing_effects.economy.delta = -50`（存档 turn8 实证）。13 次 codex 实跑 extractor 8/8 = 50。
- 56 是**落账层放大的**：`record_issue_economy_move`（db.py:6926）对每笔国库流水做 `apply_legacy_pct(delta, net_pct)`。国库有 4 个开局负面**帝国修正（legacy）**：阉党专权 -2 / 缙绅坐大 -3 / 隐田蔽课 -4 / 辽东未复 -3 = **国库 -12%**。
- `apply_legacy_pct` 对支出（base<0）做 `base×(1-net/100)` = `-50×1.12` = **-56**（数学与存档完全吻合：10→11、20→22）。
- **git blame：此分支是上游原始代码**（wangwei-ying3 / wangwei.ying，2026-05），探针（Akagilnc）一行未动。**无任何 ADR/文档论证过「支出该被帝国修正放大」。**

## 决定

**帝国修正（国库/内库百分比）只作用收入，不放大支出。** 支出按面值落（库出 = 下令额）。

- 实现：`record_issue_economy_move`（及其它经济落账点）仅对 `delta > 0`（收入）过 `apply_legacy_pct`；`delta < 0`（支出）跳过、原值落账。
- 理由：「国库 -2%」语义 = 收入 100 变 98（赚钱能力打折）。支出有**自己的损耗系统**（中饱/漂没/火耗，拨付侧，ADR 0007）；拿收入侧修正去放大支出 = 与支出自身损耗**重复抽水**、且违背「圣旨说 50 出 50」。
- 范围：经济（国库/内库）。metric 修正（民心/皇威）走别的路径、不在本决定内，实现时勿误伤。

## Considered Options
- **保留上游对称（支出也被修正）**：否决——概念错（-% 是收入侧）+ 违背库出=下令额 + 与支出损耗系统重复。无 ADR 论证过它、纯无注释对称代码。
- **前两版误诊（LLM markup → 库出=圣旨代码绑 / decree_writer 标准化 / dumb extractor）**：全废——读码 + 实测证明 LLM 存的就是 50，markup 在落账层帝国修正、与 LLM 无关。
- **#360 结算反转**：与本票正交、独立（本票是落账层 3 行修，不需要它）。

## Consequences
- 库出 = 下令额（50）；危机仍靠**收入打折**（国库×0.88）咬人，符合「-2%=收入100变98」。
- 所有国库支出（军饷/官俸/拨款/建筑维护）按面值——**游戏比现在松一档**（原来支出额外 +12% 抽血消失，是有意接受的 scope）。
- 范围 #341（小而确定性的落账层修，适合喂编排器 dogfood-2）。ADR 0027（#340 双扣）正交、仍有效。
