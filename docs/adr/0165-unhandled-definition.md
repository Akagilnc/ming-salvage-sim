# 「接不住」的定义与处置

Status: accepted（2026-10-18 owner 答上呈第 2 题；2026-10-30 补记）

owner：「一个字段填不对，没有报错，没有重试修改，全部炸游戏，这他妈叫不合理！」模型写错格式时先带反馈让它重交，用尽才落成一条事实，流程继续。

逐字抄自 #1943 条款 2，只此射程；对 ADR 0155、0158 的替代见 #1943 法源。

- **中间层**：格式规则只定义声明的结构。不合结构，带着哪个字段、现值、期望回给同一转译模型重写，有界，重试只许一层（命令行宿主自带 schema 重试与框架重试不得叠加）。重试过程与字段诊断不进皇帝材料（v2 上呈题 2 甲）。只在一处接住「转译重试用尽」抛出的那一个异常，落成事实。代码异常、传输失败、调用没返回，不接成「接不住」。
- **中间层**：声明不合结构或对不上账本（查无此人、库无此账），带可操作反馈（字段、现值、账本正名与别名、该怎么改）回模型重交整份；重试用尽才是「接不住」：落成一条事实（含模型原文与失败点），交给使用者。不抛到使用者之外，不静默丢。
- **使用者**（召对、过月）：接到这条「接不住」就继续——下一句不等，过月不因这一条停住。代码异常、传输失败、场景回话没生成完、非声明的模型调用耗尽，不收成「接不住」。夜里预推任一步失败不拦过月、不出提示与重试，过月补跑；补跑再失败才停住与续跑。其余按 #1846 各自的射程停住与续跑。本票不另写恢复步骤，不新造夜里重试入口。
- **前端**：声明结构耗尽，不显示系统提示行，不放重试钮。皇帝看见的是一条「接不住」，不是字段对照；失败点留在账本，供回喂与事后对账。场景模型与前端拿到的皇帝材料只含这条「接不住」，不含字段对照。夜里预推失败不出行、不出钮。其余系统失败仍按 ADR 0158 决定 6 未替代的部分。
- 皇帝原话：召对与旨意落账的声明事实一律同时保存皇帝原话，转译模型改了数或意思可事后对账（栈验证实测：「拨负一万两」被转译写成一万或零，无任何校验失败）。
