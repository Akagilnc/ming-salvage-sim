# 召对密令捕获与动作分类：显式按钮权威路由 + 对话上下文取正文 + 确定性 no-op 任免丢弃

Status: Accepted（2026-07-02：随 #470 设计闸一并评审——本地 cmr 十轮收敛（codex xhigh + agy + Opus 4.8）+ 线上 bot 轮收敛，PR #510；含 cmr R1 暂存感知 no-op、R2 对冲双向对称、R8 排除字段捕获修订；2026-06-23 grill #354 结晶）

## 背景

#354 / dogfound F17：召对给大臣下密令会丢失。三根因——① covert 密令意图被「任免分类器」截走（covert 任务里提的既有任命被抓成新任命）；② 任免假阳性（把对话里背景提及的既有任命重抽成新动作、no-op）；③ 密令按钮只读按钮那句、不捞对话正文（正文常在玩家前几轮描述里、按钮轮只是确认）。

这条召对动作分类路正被 **#344** 重做（gate 看玩家消息 + 取回话文本）。#354 **叠在 #344 的新 gate 上、不补已被 #344 删掉的旧三抽取**（独立 ticket：correctness，与 #344 perf 验收分开）。

## 决定

召对动作捕获按以下四条（全程：确定性 > LLM 分类，本仓 keystone）：

1. **显式按钮 = 权威分类**：玩家点「密令／拟旨／任免」按钮即确定性声明该轮类别〔0047 后出为准：composer 前缀钮收缩为密令/拟旨两件、任免钮不设，任免走自然语言+确认闸门〕；那轮按按钮路由。**密令前缀**仍**不再跑其它 LLM 分类器**（密令轮不跑任免）。**拟旨前缀**见 2026-08-28 #1503 修订：可并发一次 typed 动作分类以产出载荷式候选，但仍不跑后置串行 extractor。→ 堵 root ①，且密令轮不再有 root ②。
2. **covert 正文从对话上下文取**：密令按钮确认时，内容从**最近相关对话**（玩家任务描述 + 大臣领命回话）取，不只取按钮当轮。密令保留**轻 LLM 字段提取**（标题/内容/承办人/期限/标签——结构化、纯 parse 会脆），但喂料 = 对话上下文。**捕获字段含排除名单（黑名单）/知情圈**（「瞒某人/不走某衙门」结构化留痕——见闻排除一票否决的上游供料；子结构 schema 真源 = #489 见闻底座最小写入面，#467 评论划转，机构级映射同归 #489/#459；cmr R8）。非载荷拟旨仍取回话原文成 generic 草案（#344）；**载荷式拟旨**（如拨饷/协饷）见 #1503 修订——成案边界一次 typed classifier 产出结构化 payload，复用既有拨款单轨。→ 堵 root ③。
3. **确定性 no-op 任免丢弃**：抽出的任免若目标已在该职（对当前 `court_roster` 比对）→ 不入档。纯数据、零 LLM。→ 堵 root ②（密令轮外的残留）。**比对基准须含同夜暂存任免**（court_roster ⊕ pending 任免，cmr R1 2026-07-02）：暂存免职未提交时名册仍显示在职，皇帝反悔说「留任」抽出的复任若只比名册会被当 no-op 误丢 → 免职照旧执行、反悔失效；含暂存比对时该复任应作为对冲动作接住（撤销对应暂存免职）。**对冲双向对称**（线上 R2）：免职/取消亦冲**暂存任命**——A 有暂存任命未提交、皇帝反悔说「不任了/免去」，只比名册（A 本就不在职）会被误判 no-op 丢弃、暂存任命收夜照旧提交；比对基准含暂存任命侧即接住（对冲撤销该暂存）。

## Considered Options

- **有按钮轮也让 LLM 重分类**：否决——把确定信号又交给不可靠的 LLM。
- **靠 prompt 让 LLM「别把 covert 当任免 / 别重抽既有任命」**：否决——prompt 不可靠（keystone），要确定性闸。
- **密令纯零 LLM parse**：否决——密令是结构化字段提取、纯 parse 脆；保留轻 LLM、但喂对话上下文。
- **补旧三抽取路**：否决——#344 正在删它，#354 叠新 gate。

## Consequences

- **有按钮**（F17 这种）= 确定性修好：密令不被任免截走、正文从对话抓到、既有任命 no-op 丢弃。
- **残留**：纯自然语言、无按钮的 covert 密令 vs 任免 = 靠 #344 的 LLM gate 软判、尽力（keystone：LLM 分类不可靠），+ 第 3 条 no-op 兜底接住既有任命误抽。
- 尊重 ADR 0006：自然语言拟旨/口头派官走 `pending_actions` 暂存、确认靠对话、**前端不新增 UI**。
- 范围：#354（叠 #344）。与 #344 接缝：#344 取回话文本修「按钮不捞对话」一半；本 ADR 第 2 条补「covert 正文从对话上下文取」，两票同路、实现协调。

## 分类器 join 契约（2026-07-08 回注，#388 收口）

分类器与回话并发（gate 只读玩家消息），回话流完后**无上限 join**——不引入会丢动作的 bounded-join/超时降级（静默丢动作违 P1；#344 裁决 F，dogfood-379 ship-pre 用户拍）；残留短黑（分类器超出回话那一小段）可接受。异步 materialize（回话先出、动作稍后补呈）＝future enhancement，仅试玩证明残留黑扰人时启。

## 修订（2026-07-23，owner C 裁决——#516 决策门三选一）

「确定性 > LLM 分类」的「确定性」限缩为**结构性信号**：显式按钮／显式前缀、纯数据比对（如 no-op 名册对照）。**对自由散文的自然语言关键词／正则启发层废除**——语义判断（问/令分界、确认判读等）只许结构化 LLM 判词，判不出则落「无」当聊天（宁漏勿错）。识别兜底链相应改为：显式前缀（确定性）＞ LLM 软判（结构化判词）＞ 落「无」。动因：#516 三代 fix-fix 实证 NL 正则堆结构性发散（218 行 clause grammar 仍挡不住「命东厂密查其家产的是谁」类问句），且与反盯文法（对自由文本禁建机械语义依赖）相抵；判官依法上抛，owner 拍 C。传播面：#513 PRD 兜底链行同步修订；#516/#523/#525 re-fly 依此法。

## 修订（2026-08-28，owner A 裁决——#1503 显式拟旨载荷式 typed 成案）

显式拟旨此前无 typed payload，拨饷不落账。owner A 允许成案边界并发一次既有 typed classifier、复用既有 grant/dossier 单写者，非载荷仍 generic；该修订 supersede #344 的拟旨零分类口径，密令前缀与后置 extractor 不变。详设与验收只引用 #1503。
