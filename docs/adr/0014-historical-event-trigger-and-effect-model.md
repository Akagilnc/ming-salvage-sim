# ADR 0014：历史事件触发与后果模型

- Status: Proposed（2026-06-16 grill-with-docs session 收敛；待评审闭环）
- 关联：#174（16 事件 trigger_gate 全空）、#12（误触发根因）、#93（距离/行程，deferred）、ADR 0009（人事动作＝招安载体）、CLAUDE.md P2 铁律（判战永远 LLM 软判，代码只 clamp）

## Context

`content/events.json` 16 个历史事件 `trigger_gate` 全空 → 照日历硬弹（毛文龙在玩家已安抚前提下仍被误斩，#12 根因）。本 ADR 经一场 grill-with-docs session 收敛「历史事件」这一有状态实体子类的触发与后果模型。领域语言见 `CONTEXT.md`，详细技术设计与逐事件落地见 #174。

## Decision

历史事件 = **触发 + 结果 + 链**，全部依据「世界的真实状态」。

**1. 触发（硬判）** —— **两道关都过才触发**：
- **① 时间窗（最早…可选最晚）**：每个事件有「最早可发生时点」（其史实最早年月）；状态门即便开局即真，事件也**不能早于此时点触发**（故「开局即危」无碍——开局到该时点的所有回合都可破门）。事件**可另带「最晚时点（窗口关闭）」**：过了最晚仍没踩门即进**过期**终态、永久退候选，防史实事件 anachronistic 晚弹（崇祯二年的己巳入塞不该拖到甲申年才弹）。**需要过期的事件须显式声明最晚**；开放窗（永不过期）也**须显式声明**（`open_window` 标记或哨兵值），**严禁靠「缺省/漏填」隐式表达**——否则漏填最晚会让事件意外变永不过期、anachronistic 晚弹；#174 schema 强制最晚字段 + 加载/CI 校验（线上 R3 Gemini 抓）。「过期」终态正由此可达——本模型只定「最早」而无窗口关闭规则时它不可达（本轮 cmr 抓）。
- **② 状态门**：据当前世界真实——相关人物的职任、**在不在那个位置**、态度（忠诚），相关军队/地区的态势，以及**上游事件发生过没、是哪个结局**（事件链，见「3. 链」）。状态门点名的人物须**仍在世且在该位置/职任**——上游软判可能已让他阵亡/失格（己巳软判可死袁崇焕），已死/失格则该门判否、不触发：**状态门隐含一条「被点名人物存活且在位」不变式**。但「点名人物死了怎么办」**按事件分两类**（点名人物在事件里是「主体」还是「席位」，逐事件标注 → #174）：
  - **人物核心事件**（事件主体＝对该人物的处置、**事件存在以他为前提**：袁下狱、斩毛）：点名人物是事件存在前提，其**永久死亡**使门再不可能满足 → 事件进 **作废** 终态、durable 退候选（不留僵尸条目逐回合空判）。
  - **战略/外敌事件**（松锦、己巳入塞、戊寅虏变——后金打不打、灾疫来不来，不取决于我方某将存活）：点名人物是**参战席位/守将**、非触发前提，某将阵亡/罢免**走顶替**（换将参战、软判按新盘面发挥），**事件照常触发、不作废**——否则玩家故意阵亡一将即可取消整场大战（线上 R1 Gemini 抓）。该类事件里**某将的生死本身是这场战役的软判结局**（卢象升在戊寅虏变里殉国/突围由软判定，是结局、非独立事件），**不是**以他存活为门的人物核心事件。
  **判据（一个事件只归一类）**＝**事件的存在是否以该人物为前提**：袁下狱无袁则不存在＝人物核心；戊寅虏变无卢照样清军入塞＝战略，卢的生死是其软判结局。逐事件按此判、避免同一事件两归 → #174（线上 R2 Codex 抓「卢象升殉国」曾被两归）。故「存活→作废」只对**人物核心事件**成立；作废的一般规则见「触发类型与终态」。
- **触发类型与终态（至多一次、防重入）**：每个事件按 CONTEXT「触发门」分**可避 / 半可避 / 天定**三类（可避＝处理掉史实成因即破门跳过，半可避＝外因消不掉但留改写口，天定＝空门到点必触发）。且**每个事件至多触发一次**——一旦进入**终态**（已发某结局 / **避过**＝可避门的史实成因被玩家处理掉 / **过期**＝过了最晚时点仍未踩门 / **作废**＝状态门**引擎可判定地永久不可满足**（**封闭枚举、只认下列两类**，非开放谓词）：①**人物核心事件**的点名人物永久死亡（战略/外敌事件的将领死亡走顶替、不作废，见「② 状态门」）；②**（对正依赖该上游的下游）上游链事件已入非触发终态**（过期/避过/作废）或已发但结局排除了本事件所需的上游条件——如己巳已终态为【挡于边墙】，则袁下狱所需的「实际入塞」结局再不可能产生 → 袁下狱作废；**负依赖下游相反**（要求上游未发生/未达成某结局者），上游进非触发终态恰使其永久可满足、**不作废**（详见下「级联」；线上 R3 Codex 抓主句未分正负、会误退替代分支）；且**级联传导（正负依赖完备覆盖；依赖本身仍单向、自上而下，非图的双向传播）**：上游进入**任一终态**（已发某结局/避过/过期/作废）后其结果即**定格不可变**，沿依赖链**对每个下游按本条②重判其门**、凡因这个定格结果而**永久不可满足**者一并作废（传递闭包、一次清出）；正依赖（要求上游达成结局=X）在上游定格为非触发终态、或已发但结局≠X 时不可满足，负依赖（要求上游未发生/未达成某结局）在上游已发该结局时不可满足——**两类都纳入**；仍可能满足者不动。反之「此刻不满足但可能翻回」的门——地区态势、在不在某位置等——**不算作废**、留候选，作废只认引擎可判定的永久性），就**永久退出候选池**，即便其后原始状态门又恰好为真也不再弹。否则「破门跳过」只在当回合生效——下回合状态门再为真就又弹＝反 #12（安抚毛文龙后又被照门误斩）。防重入靠 **durable 落账的避过/已发终态**（见「3. 链」），不靠「那回合没触发」隐式表达，**也不靠关窗口**（开放窗是有意设计、见 ①，与重入无关）。
- 人物核心事件 = **玩家用人/布置的后果**：袁崇焕、卢象升开局并不在招祸的位子上，是皇帝亲手起复/升迁才把他们放上前线——没放到位就不触发（diegetic：历史经皇帝之手发生）。毛文龙被调离东江去剿匪 → 人不在东江 → 袁砍不到他、不触发。
- 位置现在只判「**对象在不在那个位置**」（军队、人物各有位置属性）。位置只由「**行止（挪人）**」改，**不由任命/调任改**——当什么官 ≠ 人在哪（官印与人腿是两个系统，ADR 0009：任命他当辽东督师 ≠ 他已到辽东，他可先来京城面圣；任户部侍郎与派他去河南赈灾不冲突）；故「调离毛文龙」要一个显式的行止动作，不是改个官职。够得着/时滞这类**距离系统留 #93**，不过早复杂化。

**2. 结果** —— 按事件类型分两种落法：
- **战斗/对抗**（松锦、大凌河、己巳入塞、甲申、卢象升殉国、孔有德兵变…）：**LLM 软判**，喂「**历史结果 + 历史成因**」作锚，按当前盘面发挥——强可改写（明军强 → 松锦可不败；卢有援 → 可不死），弱照史走。代码只 clamp、不算胜负。**软判的结果（打成什么样：哪城丢了、谁死了、军损多少、敌逼到哪）必须落进世界状态那本主账（见「链」），不能只在月报叙事**——否则下游事件的硬门查不到（如己巳被挡在边墙外 vs 逼到京师，决定袁下狱开不开）。
- **天灾 / 人事处置**（华北疫、京师疫、斩毛、袁下狱）：**确定性后果**——触发即引擎强制落、不赌 LLM。「确定性」锁的是**核心事实**（疫情发生了、毛被斩了），保证下游硬门查得到、不断在「LLM 那回合忘了写」上；但事件若另有**可争的程度轴**（疫情蔓延到哪几省，由玩家赈济/隔离驱动），该轴仍可走软判、按盘面落世界状态——确定性锁核心事实，不锁程度。
- **皇太极称帝**单列：后金改国号不由明廷阻止（触发不受玩家门控、近天定），但**核心事实（改了国号）确定性落**（喂下游甲申/士气链），而「明廷承不承认伪号、联蒙抗清」的**外交-意识形态响应轴走软判**落世界状态。列它在确定性后果是就其核心事实而言，非谓整事件无软判空间。（注：触发类型「可避/半可避/天定」管事件进不进候选，与结果「确定性/软判」是两根正交轴，勿混。）

**3. 链** —— **链 = 「上游事件 + 它的结局」决定下游有没有、是哪个事件**。多结局事件的不同结局走不同下游（己巳示意：【挡于边墙＝守住关墙】→ 无袁下狱；【入塞被遏】【长驱直入】＝实际破口入塞 → 有袁下狱——示意而已，逐档→下游的精确映射 + 把 events.json 现有「袁下狱＝己巳之变后必发」这类粗口径细化到「按结局分档」均 → #174）。两本账都要记、各管一摊：
- **事件结果记录（链分支用）**：每个事件结束记**终态 + 结局标签**——① **终态**＝发生过 / 避过 / 过期 / 作废（「发生过」用引擎现成的 `event_triggers`；避过、过期、作废是上面「至多一次、防重入」的终态，**也须落同一本账**，下游才查得到「上游被避过/作废」这条分支）② **是哪个结局**：多结局事件（尤其战斗软判）**必须预声明一个封闭的结局标签集**（如己巳之变＝｛挡于边墙, 入塞被遏, 长驱直入｝，对齐 events.json 已记的三档），软判结果**必须收敛到其中恰好一个离散标签**并存进本账——**软判输出的标签须经 extractor 白名单校验/规范化到该封闭集**（格式/空格/同义词偏差如「挡于边墙 」「成功抵挡」→ 最接近匹配；**仍无法可靠归一到封闭集时 fail-loud + 重试软判**——退回让 LLM 重产一个合法标签，**但重试有上限**（超限即抛 `SettlementAbort` + 错误包、转人工介入，绝不无限重试耗尽 API 额度/卡死结算，线上 R3 Gemini 抓）；**绝不兜底写一个软判没支撑的标签、也不留空**：结局标签是驱动下游链的离散键，编造值会持久错误触发/作废下游、且两账互不推导无从纠错，故宁可 fail-loud 重试也不写未支撑值；规范化/重试机制 → #174）。**标签集须覆盖该事件数据已记载的每一档结局，不漏档**——漏档则那档结果无标签可落、下游对它的门不可达（本轮 cmr：示例曾漏「入塞被遏」中档）。这本「离散标签账」与下面那本「世界状态后果」分开：后者是连续的「打成什么样」，前者是供下游门匹配的**离散键**。下游门查「上游事件 **终态/结局** = X」。**无封闭标签集、或只把结局写进叙事/世界状态而不落离散标签，则下游「结局=X」门无值可匹配＝该链分支不可达**。标签集枚举 / 字段名落地 → #174。
- **世界状态后果（机制用）**：事件的机械后果照常落进世界状态（人死→人物状态、失地→归属、军损→兵力、敌逼→军压），给打仗/财政/判定等机制读。
- **两账真源 + 对账**：一次软判**原子同写两账**（同一结算信封、全有或全无）；**世界状态后果是机制真源**，结局标签是该结果的**离散键/投影**——二者由这一次结算同时写入、**互不推导**（不从世界状态反推结局、也不从结局反推世界状态），杜绝两账日后失同步（线上 R1 Sourcery 抓）。
- **月报/存档 = LLM 的叙事记忆**，不当事件链的记录（太长、是叙事）。

**流寇** = 头目（character）+ 股（power）分层：头目身份给「是不是流寇」，股给城破烈度；**招安 = 易主（主动归附）+ 任命武将**——其中**流寇股削弱不另起一笔，它就是 ADR 0009「易主」条目内嵌的「失方势力削弱」反噬**（0009 决定 3：主动归附此向必记失方削弱，LLM 给值、代码 clamp、随人事/派生管线落），**一处落账、不再额外减一次该股的 `power` 烈度**（否则与易主反噬双减；多股分立下是动作所指那一股的 `power` 实例、非全局 `bandits`）。再叛 = 易主回 bandits（走 ADR 0009 人事动作承载）。头目与股是两个实体，故有**头目已死、股仍存**的中间态（股「可换头目延续」）：此时招安（易主+任命，对死头目违 ADR 0009「不得处置死者」）走不通——**孤儿股不能因头目一死就既招不了也剿不掉、还永久驱动城破**。两条路按**动作类型**分（非按头目死活）：**招安（就抚）**＝易主（主动归附）+ 任命，其削股＝易主内嵌反噬；**剿股（被剿）**＝独立 power 级军事镇压（剿灭、削弱、平定），不经任何头目、无易主反噬故不与招安双减。**活头目的股两者皆可**（玩家就抚或被剿、**同一股同一时段互斥二选一**、不得对同一股并行 apply 防双削，如李自成/张献忠「被剿或就抚」、孔耿「就抚或被剿」）；头目已死的孤儿股没有易主可走、只能剿股。亦可等新头目涌现再招。**多头目/集团并存时流寇股分立**（李自成股、张献忠股各自独立的 `power` 实例，不共享一个全局 bandits 实体），招安/削股/剿股只作用于**动作所指的那一股**，不波及其它仍敌对的股——招安张献忠不削李自成部（线上 R1 Gemini 抓）。动作落地 → #174。

## 为什么（权衡）

- **战斗结果软判 + 史实参考，不引擎算档**：这是 LLM 游戏、判战永远软判（P2 铁律）；引擎按公式算档 = v3/P社数值模型，太死；纯 LLM = 瞎编。喂「历史结果 + 历史成因」→ 锚在史实上、能因盘面破局、又不瞎编。历史成因本身就是玩家可改的杠杆（给卢兵饷、压主和派 → 他可不死）。
- **天灾/处置走确定性后果**：纯 LLM 不可靠、会放空炮——尤其「京师大疫 → 压低京营 → 喂甲申门」这条链，不能断在「LLM 那回合忘了写」上；无仗可软判的灾/处置由引擎保底。
- **触发硬判、据世界真实（含位置）**：防 #12 式照日历误斩（已安抚仍斩毛）；事件是玩家用人/布置的后果，不是日历到点必弹。
- **流寇分层**：招安动头目、城破由股驱动，单实体表达不了「招了张献忠李自成、流寇仍在」和「受抚 → 再叛」。

## Consequences

- **详细技术设计 + 16 事件逐个（触发门 / 确定性后果或软判史实参考 / 链）+ 代码任务清单 → #174**（给开发 session 的 handoff）。本 ADR 按项目文档方法论（CLAUDE.md：精简）只记模型决策与理由，**不含字段名/schema/代码任务**。
- 领域语言（历史事件、触发门、确定性后果、流寇头目·股、招安）在 `CONTEXT.md`。
- 「够得着/距离」= #93，本模型只用「在不在那个位置」。
