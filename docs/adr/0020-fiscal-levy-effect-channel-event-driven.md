# 饷率 effect 通道 = 史实时间线「事件生成器」+ 准奏后确定性后果；加/不加的决策走全局圣旨通道；起运随三饷联动（单定额）

Status: Proposed（2026-06-20 grill-with-docs（#259）决策结晶。待 to-prd 后跨模型设计评审收敛再转 Accepted。）

## 背景

[ADR 0019](0019-fiscal-cutover-all-province-seed-hub-split.md) + [FISCAL_PROVINCE_SUBSTRATE.md](../FISCAL_PROVINCE_SUBSTRATE.md) §#70 把「三饷时间线注入 + 起运定额联动选型」deferred 给 #259「饷率 effect 通道」。#70 只静态 seed 开局辽饷九厘（剿饷 1637 / 练饷 1639 不进 seed），起运定额静态、注「#259 后动态接管」。

#259 grill 揭示一处定调更正：三饷**不是**「到点强制注入、改 `三饷应征`」的确定性背景。三饷是史实里**皇帝的决策**——崇祯逐次拍板加辽饷、开剿饷、行练饷，**加则民变深、不加则边军溃**，两边都有代价。故时间线该把「该不该加这道饷」的两难**摆到皇帝面前**，玩家有 agency，而非被无声改数。

## 决定

1. **（D1）时间线 = 史实事件生成器，不是强制注入器。** 到史实时点生成一个「军费危机 → 是否加这道饷」的**历史事件**（复用 [ADR 0014](0014-historical-event-trigger-and-effect-model.md) 触发门），把两难摆到皇帝面前。**加/不加的决策本身不在本通道**——走全局圣旨通道（#260）、复用 ADR 0014 事件模型 + [ADR 0013](0013-decree-commitment-ledger.md) 决策落库；**准奏后**由本通道落**确定性账本后果**（`三饷应征` 升/降 → v23 `火耗应派=(正赋+三饷)×火耗率` 自动联动 → 起运联动，见决定 4）；**民变/加征反噬是上行通道、交 LLM 软判**（ADR 0007 边界 + ADR 0011 消费）。本通道不自己造皇帝决策机、不直接强改三饷。

2. **（D4b）军费危机的触发门 = 天定。** 辽东战事/流寇/练兵的军费窟窿如期出现（这些根因不在 #259 能解的范围内），皇帝的真两难是「加这道饷，还是另寻财源/硬扛民变」。**破局不在「让战争消失」**（那越界到战略/事件线），而在财政基座已有的上行软判通道（追赃/挪借/招抚/清丈，#260/软判）。守「越努力越无解是压力源、破局可真」——破局口在筹款手段、不在让危机不来。

3. **（D3）通道升降通吃 + 事件链门。** 既生成开征/升率（上行：辽饷 1631 升、剿饷 1637 开、练饷 1639 行），也生成「议停」（下行：剿饷 1640 撤）。**议停事件的触发门前置「该饷已开征且仍在征」**——皇帝当年没加征则该饷不存在、议停事件**避过**（ADR 0014 事件链门 / 负依赖，不空弹）。准奏议停则确定性减掉对应分量、起运定额随之回落。

4. **（D2）起运随三饷联动 = 单一 `起运定额`。** 三饷事件升/降 `三饷应征` 时，本通道**同步升/降同一个 `起运定额`**（保持 ≥ 当期 `三饷应征`，保证三饷全解、不困省内池）。**不拆「三饷起运 / 正赋起运」独立通道**——拆出的字段只有跨省 hub（#261）才有消费方，#259 不提前替 hub 拍字段（boundary 铁律）。字段留可扩展口（FISCAL §扩展性护栏）；将来 #260 真要演「皇帝截留正赋」再拆。

5. **（boundary）#259 全程 shadow、不吞邻项。** 起运到京只算/打印、不汇国库（hub = #261）；不实现「圣旨 → 结构化 action」拆分（#150/#260）、不实现加征反噬消费（ADR 0011）。#259 = 生成事件 + 落准奏后确定性后果 + 保持辽/剿/练分量可按来源归因，止于此。

## Considered Options

- **统一通道（历史事件与皇帝旨意同一套机制）**：否决——会让确定性历史轨迹和「LLM 软判玩家代价（京师缺饷/户部弹劾）」纠缠进一个通道、违 ADR 0007「引擎确定性 vs AI 软判」边界；且把 #259 拖进未完工的 #150 圣旨地基。
- **时间线强制注入（无玩家 agency，到点直接改三饷）**：否决——三饷史实是皇帝的决策，强制注入抹掉核心两难、与本项目「皇帝角色保真」相悖（grill 更正点）。
- **拆三饷-正赋独立起运通道（gemini PR#113 选项 b）**：暂否——预占 #261 hub 的字段决策、违 boundary；联动单定额已足表达三饷史实全解。留可扩展口，#260 需要时再拆。
- **可避/半可避触发门（平辽 → 免辽饷）**：否决——要求 #259 判定辽东/流寇等战略状态，远超财政时间线范围；破局改由上行软判承载。

## Consequences

- **取代 FISCAL doc / #259 issue 把三饷写成「到点直接改 `三饷应征`」的措辞** → 改为「到点生成事件、准奏后落确定性后果」（FISCAL §#259 同步更新）。
- **#259 复用既有机制、不另起炉灶**：ADR 0014 事件模型（触发门/确定性后果/事件链门）+ ADR 0013 决策落库；本通道只是「饷率类历史事件 + 其确定性后果」的特化。
- **#259 可在 #150/#260 未动时独立设计/推进**（纯 autonomous-timeline 的事件生成 + 确定性后果）；但**完整可玩闭环**（皇帝实际加/不加并承受软判反噬）须等 #260/#150——#259 单独的 DoD = 「事件按史实节奏与链门出现 + 准奏后 shadow 末态可断言验证」，勿误判为「shadow 玩家无感 = 功能不足」。
- **起运联动须有不变式断言 `起运定额 ≥ 当期三饷应征`**——漏做则超额三饷静默漏进省内池（`settle_tick` 不 raise、不报错，是静默经济学改变）。
- **精度沿用 #70**（量级定稿、田亩占比折算、`_meta.provisional`、一手《会计录》deferred）；各饷开征/升率/停征的「月份」锚到该年正月（provisional、`_meta` 标注，一手核诏令月 deferred）。
- **cutover 后（#261）** 本通道的确定性后果从 shadow 隔离相位转 fail-loud。
- 触发点/事件数据格式是可逆代码级实现，留 #259 的 `/tdd` 现场长；grill 只钉「走改 `settle.p` 参数注入路径、不走 `actions[]` 动作路径」（后者误踩 #260）。
