# 过月按因果分段，夜里预推但月末才公开结果

Status: proposed

〔2026-09-30 后出注记（#1895，与本 ADR 同送票庭重审）：本决定「按段推演遗漏的整月密令由 LLM 而非代码判断」即 owner「什么时候允许代码拼效果了？」的正面形态，**密令月度选择由已准 #1843 步骤 4a 承接**（owner `6b8bcfea-9d53-403e-bfa8-bb6f8a320636` 批准新增整月供料 run）：4a 在世界段、批红问后效果全部落定后读取本月已落实况与密令材料，承办人据其可及事实决定本月执行态并交完整密奏；代码不再以共用意愿底档／成功率地板替人算这颗心，也不把模型的选择只准往更重方向压。**已落问前／问后效果不重做**；4a 耗尽则停当前过月 run、不越过结案与邸报、不重跑世界段或批红，恢复由 #1846 沿原相位接续。工程现状注记不变（0058 进展轨的逐月持久结构与 0054 效果级 origin 槽仍属**待建**，勿当现成表直接 SELECT）。〕

过月的模型调用等待过长，但旨意的实际办理结果不能在月末前让皇帝或递话人知道（owner：「目前过月等待太久其实是个很严重的问题」，#1812 起居录 uuid `8f410394-1a63-4ad1-8b48-a2cc033d693b`；「王承恩是人。不是系统。他凭什么马上就知道实际的。这样的话我一直问就好了。毫无时间成本。」#1847 起居录 uuid `9d8e3f4a-92fa-4614-9f3a-f651233cff90`）。决定把过月改为夜里逐旨预推并暂存、月末按旨序落账后推世界事件，批红后由模型完成整月密报、据实写现有邸报再推进月份，夜里预推调用耗尽则静默待过月补跑、过月后调用失败才停住报错并可重试（不静默降级）；这样提前消化可并行等待，保留实际账本的因果和人的知情边界，也让按段推演遗漏的整月密令由 LLM 而非代码判断（owner：「什么时候允许代码拼效果了？」#1847 起居录 uuid `42823825-d60b-4c2c-acc9-1fcf94c2c359`；「这个游戏什么时候允许静默降级了？」#1847 起居录 uuid `0efe5ba4-0e71-4914-ae1c-574b6eb37575`）。此决定取代 #1822 的同场分段续演与 #1820 的核算反馈续演循环；步骤契约不在 ADR 重立，施工和恢复见 #1861（夜里预推）、#1843（过月主链及整月密报）、#1847（批红续推）、#1862（邸报）、#1845（机械尾）、#1846（失败恢复），无旨月见 #1848。
