# 过月按因果分段，夜里预推但月末才公开结果

Status: proposed（#1895 同送票庭重审）

过月调用等待很长，但实际办理不能在月末前让皇帝或递话人全知（owner #1812 起居录 uuid `8f410394-1a63-4ad1-8b48-a2cc033d693b`：「目前过月等待太久其实是个很严重的问题」；#1847 起居录 uuid `9d8e3f4a-92fa-4614-9f3a-f651233cff90`：「王承恩是人。不是系统。他凭什么马上就知道实际的。这样的话我一直问就好了。毫无时间成本。」）。因此夜里逐旨预推暂存、月末按因果落账，提前消化可并行等待而保留人的知情边界；整月密报由模型判断，不以代码拼人物选择或静默降级（owner #1847 uuid `42823825-d60b-4c2c-acc9-1fcf94c2c359`：「什么时候允许代码拼效果了？」；uuid `0efe5ba4-0e71-4914-ae1c-574b6eb37575`：「这个游戏什么时候允许静默降级了？」）。此决定取代 #1822／#1820 同场核算反馈续演循环。

步骤不在 ADR 重立：原执行契约见 #1861、#1843、#1847、#1862、#1845、#1846，无旨月见 #1848；本次人物选择及 4a 授权引用 [#1895](https://github.com/Akagilnc/ming-salvage-sim/issues/1895)；单件模型调用重试耗尽＝过月停住不推进、已落的账不动、原地重试只补那一次调用、重开仍同态、不给跳过；恢复契约见 [#1846 现行正文](https://github.com/Akagilnc/ming-salvage-sim/issues/1846)，不重立步骤规格。奏报轨、效果级回指及实况轨已持久可读写，不称待建、不再造载体；人心代算与无效产物越过 4a 的运行时遗留仍待合法改约后处理，不冒称本次文档修订已修代码。
