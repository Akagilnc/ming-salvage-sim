# 重构：模型调用重试耗尽时，保留成功结果并补完本月

Status: proposed（2026-09-09；owner 已拍取舍，设计待评审，未实施；本次游戏重构，非独立版本）

过月期间，其他事务已成功、唯独某件事因模型调用错误且自动重试耗尽而未处理完时，保留已成功结果、留在本月，只补处理失败项，补好后再进入下个月。
这是避免玩家进入缺失后果的下个月所接受的等待，不把剧情中办事失败当系统故障，也不把该决定扩展为所有类型故障的处理政策。
[owner 的限定与选择](../design/game-v2-architecture.md#模型调用耗尽的选择)是本决定依据，重试次数、恢复入口及具体存储协议均未在这里定下。
过月形状与恢复（2026-09-09，决策票 [#1822](https://github.com/Akagilnc/ming-salvage-sim/issues/1822) owner 逐题拍）：过月只起一个推演者场，分段交代、实况回同一场续演，段数由推演者定、它自己声明本月事毕、一段交完是常态、代码不设段数上限；一段的转译 + 核算 + 落账在同一次数据库提交里全有或全无（此处指数据库事务，不是一件事务；一段可含多件事务的交代），段落定即提交、下一段可见，月份推进是最后单独一笔，「部分段已落、本月未推进」即本决定的形态；共同资源不另设占用，账本即占用，扣款顺序 = 交代在段中的先后（人、兵同理先交代先占）。本决定只覆盖丢了就缺后果的调用（推演段、转译、收夜拆旨与背书批、颁布判官），失败项 = 重试耗尽的那一次调用，已落的不动、补 = 重跑它再续演；章节记忆、关系酿制、结局总评、高亮照旧降级留痕、下月补，并改为推进后的后台任务（发生时间与次序不变、不挡前台，下月过月前完成；旧不变式「章节记忆在结局判定前」改为「章节记忆在结局总评前」）。耗尽后核账期停住：[0148](0148-settlement-period-shows-month-open-snapshot-not-engine-mid-state.md) 月初快照 + 核账叙事不变，系统提示行告知可重试，重试只重跑那一次调用后自动续跑到推进，关档重开同一核账期（[0149](0149-enter-settlement-period-on-click-in-flight-continues.md)），错误包照发，不提供跳过本项 / 跳过本月；该段转译反复失败的逃生口 = 丢弃该段、从上一持久化段重演（同 [0036](0036-audience-night-restore-resume-at-last-entry.md) 丢弃半截回话）。段 = 对话轮，生成完即持久化；「本月事毕」由末段的转译声明、与该段落账同一次提交持久化；恢复只看最后一段落没落账，遇到已落账且已声明事毕的末段只做幂等的月份推进、不再起新段，不另存转译产出。逃生口丢段重演时，被丢弃的段从推演卷撤下、重演段接上，重开同态、不静默替换（呈现归 [0158](0158-v2-frontend-receives-audience-month-and-recovery.md)）。本段 supersede [0008](0008-settlement-applier-contract-and-transaction-boundary.md) 决定 2 的整段原子与决定 4 的后半段 LLM 调用边界（章节记忆 / 结局总评移出推进流程，见 0008 后出注记）。未选：按事务多场并行；先总推演再分演；整段原子；按一件事务（affair）或按一笔交代为原子单元；扩到全部调用；失败项按事务撤回重演；后台无限重试；缺着进下月；推演者带记账工具一次调用内往返。重试次数与退避仍不在此定；转译字段与「本月事毕」的声明方式归 #1815。
