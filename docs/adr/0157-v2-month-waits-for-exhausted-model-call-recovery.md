# 重构：旨意夜里预推暂存，过月按序落账、推世界事件、批红、写邸报后推进

本 ADR 是过月形状、落账边界、收尾与失败恢复的唯一规则来源，规格票与切片只引用步骤号、不复述；召对承接见 [0155](0155-v2-single-scene-llm-with-complete-perspectives.md)，呈现见 [0158](0158-v2-frontend-receives-audience-month-and-recovery.md)，数值归属见 [0153](0153-v2-world-record-and-two-way-mediation.md)，颁布关与批红的资格、豁免、待判集、效果分工沿 [0055](0055-promulgation-gate-at-settlement-effects-follow-verdict.md) / [0043](0043-month-end-decisions-as-memorial-rescript-form.md) / [0048](0048-month-end-rescript-as-real-document-page-no-desk-workbench.md) / [0093](0093-rescript-loop-triage-draft-six-actions.md)，本 ADR 只改它们发生的时点。最初取舍依据见 [模型调用耗尽的选择](../design/game-v2-architecture.md#模型调用耗尽的选择)与 [过月与邸报再定](../design/game-v2-architecture.md#过月与邸报再定2026-09-10-grill)。

## 原则：结果只在月末可知

旨意的后果——办成没有、实出多少、谁死谁降——只有过月之后才能被任何人知道：皇帝、递话人、大臣一律如此（owner 逐字：「王承恩是人。不是系统。他凭什么马上就知道实际的。这样的话我一直问就好了。毫无时间成本。反正游戏也不过月」）。夜里的一切预算都不落账、不进任何材料目录、不上界面。

## 夜里（皇帝在召对，后台）

一道旨一被应允（或以中旨下达），后台起它自己的三步：颁布判官 → 顺颁的由推演者写它的后果（一次调用，即「推演段」）→ 转译成账目声明。产物全部**暂存**：不落账、不进目录、HUD 不动。皇帝撤旨 / 改旨，作废该旨的预算（改旨 = 作废后按新旨重起）。预算的某次调用用尽（含 429）= 该旨未预成，静默、不上界面，过月时补跑，不牵连他旨。（owner：「判官 + 推演 + 转译 + 邸报 前面三个是不是都能在按下过月之前 后台做？」；「目前过月等待太久其实是个很严重的问题」）

判官只改时点，不改法：判前快照 = 预判那一刻的盘面；待判集含历史留中回流者（夜始预判）；外廷豁免项不判；中旨仍可打回、可禁强颁；结构化载荷与叙事政令的物化分工、强颁的效果与射程一律沿 0055。

有司请旨（0043 / 0048）：预推中推演者向皇帝请旨时，该旨的推演停在问处，问前的声明照常暂存，问后的等答复。

## 按下过月（颁布 / 退朝）

1. 等召对最后一轮转译（0155）→ 收夜成案 → pre_settle 前半段（[0008](0008-settlement-applier-contract-and-transaction-boundary.md)，不动：固定财政 tick、在途、事件终态、硬立局势、密令到期）。
2. 暂存声明按下旨先后核算落账：有账封顶、拒收、先交代先扣（0153 / #1820 决定 2）；只落各旨问前的声明；未预成的旨在此补跑三步（补跑用尽按下节统一形态停住）。
3. 世界事件推演：一次调用，看到旨意落账后的盘面（灾、贼、战、局势自走；owner「Q16 现在还是甲。真的手段用尽没办法再说改的事情」——因果准优先，世界事件夜里预推留作手段用尽后的备用）→ 一次转译 → 一次提交（#1822 决定 2 / 7 沿用：一段一次转译、一次数据库提交，不按事务拆并行）。世界段里的请旨同样停在问处、问后等答复。
4. 批红页（0048：零待批才不出）：待批项 = 打回的旨三选（强颁 / 收回 / 留中，0055；强颁当月落标记与代价、办理射程沿 0055）+ 全部请旨（旨意的、世界段的，无原旨的世界请旨同样是世界段的请旨）。答复形式 = 票拟选项或亲笔朱批（0043 / 0048）；六动作批出的新旨（0093）归下一夜的预推链，不在本月落。皇帝读、选期间后台只做一件事：为各请旨的票拟选项各预推一份续推（加速，不限亲笔朱批；owner「可以预推。成本看看再说」）。批完：答复持久化为实况 → 该旨 / 世界段从问处续推一次（选项命中则用预推的那份）→ 转译 → 落其余声明；问前已落的一律不动，世界段不重推。（owner：「也不需要马上出现批红页。道理也很简单。同样要等两分钟。两个1分钟比一个两分钟体验好得多」）
5. 写邸报：批红完成、全部结果（含批红效果）落定之后，单独一次调用据实况写——名义（LLM 当初所提）、实入、拒收、各旨预推文、世界段、请旨答复；能流就流，不能则一次落位。邸报就是现有邸报（owner：「月报就是现在的邸报」；「什么叫最终月报？又冒出来一个概念」——不立新概念）：章节框架只作软提示、不限制 LLM 说什么（owner「有也是给llm的软规则不是必须。llm说话本身不受限制」）；不嵌决策块（请旨走批红）；作者供料不含密令，密令另走密报（owner「邸报不含密令。密令这些东西单独出来」）——这是供料边界，不是对输出的检查（[0142](0142-no-semantic-parsing-of-llm-prose.md)）；整份作公开文书进公开层，大臣自己读（[0034](0034-minister-audience-fed-perspectival-knowledge-not-omniscient.md) 后出注记）；引擎不核对、不改写邸报。
6. 结局判定（代码）→ 邸报写成即自动推进月份（[0149](0149-enter-settlement-period-on-click-in-flight-continues.md) / #1822 决定 4，「朕知道了」只关阅读态）→ 机械尾后台（关系酿制、结局总评、高亮；降级留痕、下月过月前完成）。章节记忆退役（owner「去掉这个章节记忆」）：历月邸报以一行索引入材料目录，推演者、邸报作者、结局总评、大臣按需自读，不另压缩。

任何月份同一条链，待办由真实状态决定：无新旨的月份也可能有历史留中案卷回流重判、前月强颁的办理、世界事件与其请旨。推演过程（预推文、世界段）不呈现给皇帝（owner：「现在是把这个反复过程摆给了用户看。好不好我不确定」→ 不摆）。

## 失败与恢复

- 每次模型调用最多 3 次（本身 + 重试 2 次）；HTTP 429 不重试；5xx / 超时 5 秒后重试；统一适用于预推三步、世界推演、转译、邸报、召对回话（现状 simulator 单次尝试、429 可重两处随之改；owner 逐字：「重试2次（加本身调用一共3次，而且要区分 429，直接不重试，500这些才5秒后重试）。重点也是用户体验」）。
- 边界：夜里预算用尽 = 该旨未预成，静默作废、不停任何东西；过月后任一步（步骤 2 补跑、3、4 续推、5）用尽 = 停在这一步，系统提示行报错原文 + 错误包路径 + 「重试」钮（owner：「肯定要放按钮啊……那你让玩家咋办，干瞪眼吗？」）；重试只重跑那一次调用，已落账的一律不动；不给跳过单项或本月；重开同态（0149）；形态归 0158 决定 6。
- 恢复真源 = 暂存声明（含问前部分与已持久化的请旨答复）+ 落账状态：崩在步骤 2 中途 → 已落的不动、未落的接着按序落（逐旨幂等）；世界段文已持久化，崩在其转译 / 提交 → 重跑那一次转译，段文丢一半 → 丢弃重推；崩在批红答复之后的续推 / 落账 → 答复已持久化，重开同态续推续落（幂等）；崩在邸报 → 只重写邸报；夜里预算丢失 → 过月时补跑。暂存声明本身就是转译产出，因此「不另存转译产出」（#1822 决定 7）在旨意预推这一段不再成立，其余仍成立。
- 代码异常沿 [0005](0005-no-broad-except-swallow-loud-failures.md) / 0008 决定 6 响亮中止 + 错误包，对皇帝同一形态；不复活 legacy 整段 ready 重放。

## 取代与未选

取代：#1822 决定 1（一场推演分段续演）→ 夜里逐旨预推 + 月末一次世界推演；#1822 决定 2 / 7 中「不另存转译产出」在旨意预推段 → 暂存声明为恢复真源、过月按序落账（世界段仍一段一次转译一次提交）；#1822 决定 5②「一段交完是常态」随段的消失作废；#1820 决定 1「实况回同一场推演续演」→ 据实的一步由邸报承担、同月内无续演（0153 后出注记）；#1823 决定 5 推演卷 → 0158 决定 5 改；本 ADR 前版的「最终月报」一词与「章节记忆后台尾」；0008 整月后半段原子单元与 ready 重放（沿前版）。
未选：夜里就落账、递话人当场知道（owner 否）；世界事件也夜里预推（备用）；按钮即出批红页；只有打回件时在批红中提前写邸报（强颁当月落效果，邸报须等）；世界段按事务拆并行转译（#1822 决定 7 已否）；无上限自动重试；推演过程摆给玩家看；保留章节记忆；分章并行写邸报（丢连贯）；推演者带记账工具（#1821）；按事务多场并行；整月一次原子提交；「朕知道了」控制月份推进。
