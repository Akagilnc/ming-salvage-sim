# 重构：分段落账，据结果写月报后过月

Status: proposed（2026-09-09 方向及 #1822 决策；2026-09-10 owner 复审修订收尾顺序；未实施）

本 ADR 是分段落账、收尾与恢复的唯一规则来源；召对承接见 [0155](0155-v2-single-scene-llm-with-complete-perspectives.md)，呈现见 [0158](0158-v2-frontend-receives-audience-month-and-recovery.md)。最初取舍依据见 [模型调用耗尽的选择](../design/game-v2-architecture.md#模型调用耗尽的选择)与 [#1822](https://github.com/Akagilnc/ming-salvage-sim/issues/1822)。

## 推演与收尾

一次过月只有一个推演者场，分段交代；一段可含多件事务，段数及事情怎样继续由 LLM 决定，代码不设段数上限或剧情判断。每段生成完即持久化，每段转译、核算与落账作为一个数据库事务全有或全无；共同资源直接按交代先后从账本扣取，不另造占用表。实况结果回同一场，由 LLM 据此编演。

按 [owner 2026-09-10 复审裁决](https://github.com/Akagilnc/ming-salvage-sim/issues/1812#issuecomment-5611335526)，引擎处理完本月结果后，由 LLM 据结果写最终月报，月报保存后才推进月份；推演过程不自动充当月报，引擎也不核对或改写月报剧情。推演者的「本月事毕」声明与该段落账一同持久化，表示推演交代结束，不能跳过月报直接推进。

无新旨月份沿同一链推进。过月先等召对后台转译与收夜处理完成；pre_settle 的独立事务、settling 相位及回滚后的内存重载沿 [0008](0008-settlement-applier-contract-and-transaction-boundary.md) 保留。请旨仍按既有批红流程暂停、批完续演。章节记忆、关系酿制、结局总评及高亮沿既有降级留痕规则处理；机械尾在推进后后台运行、不挡前台，下月过月前完成，章节记忆先于结局总评。结局判定仍在推进前。

## 失败与恢复

持久化的段、落账状态、事毕声明与最终月报就是恢复依据，不另存转译产出，也不保留分段路径的 resolve_context ready=1 重放。未落账的完整段重跑转译；生成一半的段从上一持久化段续演；已落账且未事毕的继续推演。已事毕但月报未完成的只补写月报，账与已完成推演不重跑；月报已保存的只完成幂等的月份推进。

模型调用重试耗尽时留在本月，保留已成功结果，补失败调用后继续；覆盖推演、转译、收夜拆旨与背书批、颁布判官及最终月报，不把剧情办砸算作系统故障。转译反复失败时可丢弃尚未落账的该段，从上一持久化段重演；卷上撤下该段、接上重演段，重开同态，不静默替换。不给跳过单项或本月，也不增加后台无限重试；次数与退避留实现。

代码异常沿 [0005](0005-no-broad-except-swallow-loud-failures.md) / 0008 响亮中止、发错误包，恢复仍用上述分段记录边界，不复活 legacy ready 路径；这不把代码异常改判成模型调用失败。玩家重试与重开形态统一引用 0158。

本决定取代 0008 的整月后半段原子单元、ready 重放及后半段 LLM 收尾边界；其余故障规则不变。未选：按事务多场并行、整月一次原子提交、另存转译产出、已成功结果随失败项重演。
