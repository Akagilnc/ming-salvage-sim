# 重构：按一件事连贯推演，按基础信息落账

Status: proposed（2026-09-09 owner 已拍方向；W1A #1831 已于 2026-09-11 落地事务记录与指向，W1B #1835 已于 2026-09-12 落地声明契约与跨既有能力的分派底座；统一转译与完整推演链仍待后续施工；本次游戏重构，非独立版本）

同一件事的人事、财政、军事因果由综合推演连起来，记录时由推演 LLM 一次向中间层交代相关结果，中间层按 [0153](0153-v2-world-record-and-two-way-mediation.md) 完成必要的 LLM 语义转译后，再分派到人、钱、军队等已有能力，不让推演 LLM 管底层模块、调用顺序及跨模块关联。
世界推演同时考虑多件事共用的人手、钱粮和兵力，保持事务联系，统一记录入口不等于规定每件事只能推演一次或全天下只能一次推演调用。
原话及理由见 [事务与时间依据](../design/game-v2-architecture.md#事务与时间依据)和[统一记录入口](../design/game-v2-architecture.md#统一记录入口)，本决定不预设记录格式、DB 原子性、回滚、重试或重演协议。
事务的身份与关联（2026-09-09，决策票 [#1818](https://github.com/Akagilnc/ming-salvage-sim/issues/1818) owner 逐题拍）：事务是一条自己的记录（名字、起因、当前情况），案卷、流水、人物变动、人物经历、文字事实、公开说法各自指向它，沿 [0054](0054-ledger-cross-links-and-effect-backrefs.md) 族规单向新指旧、事务不复制清单，也不自设经手人名单（从指向它的案卷参与人与人物经历推出）。事务与案卷同在收夜成案时诞生，由拆旨 LLM 说明这几道旨属于哪件事或接到哪件已开着的事上；推演中新起的事由推演 LLM 交结果时新起；事务的边界与了结均由 LLM 声明，代码不判、不按条件自动了结（「了结」与案卷「结案」分开）。银两流水与各类日志照旧以 origin_ref 指案卷、案卷指事务，无案卷的后果直接指事务；局势（issue）保留为事务下的机械载体（承诺按月后果、惯性、到期待办仍由它跑）并指向事务。未选：放大案卷取代拆旨粒度、事务只以关联槽串链、以 issue 充当事务、代码按来源划边界。表布局与引用字段形状不在此定。
过月的场、落账边界、收尾与恢复统一见 [0157](0157-v2-month-waits-for-exhausted-model-call-recovery.md)，本 ADR 不另定义流程。
