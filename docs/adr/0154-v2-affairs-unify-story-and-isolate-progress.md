# 重构：按一件事连贯推演，按基础信息落账

Status: proposed（2026-09-09 owner 已拍方向；W1A #1831 已于 2026-09-11 落地事务记录与指向；W1B #1835 已由 PR #1865 落地声明契约与跨既有能力的分派底座；W2A #1837–#1839 已让召对转译沿该入口登记交办、当场实况及事务关联，完整过月推演链仍待后续施工；本次游戏重构，非独立版本）

同一件事的人事、财政、军事因果由综合推演连起来，记录时由推演 LLM 一次向中间层交代相关结果，中间层按 [0153](0153-v2-world-record-and-two-way-mediation.md) 完成必要的 LLM 语义转译后，再分派到人、钱、军队等已有能力，不让推演 LLM 管底层模块、调用顺序及跨模块关联。
世界推演同时考虑多件事共用的人手、钱粮和兵力，保持事务联系，统一记录入口不等于规定每件事只能推演一次或全天下只能一次推演调用。
原话及理由见 [事务与时间依据](../design/game-v2-architecture.md#事务与时间依据)和[统一记录入口](../design/game-v2-architecture.md#统一记录入口)，本决定不预设记录格式、DB 原子性、回滚、重试或重演协议。
事务的身份与关联（2026-09-09，决策票 [#1818](https://github.com/Akagilnc/ming-salvage-sim/issues/1818) owner 逐题拍）：事务是一条自己的记录（名字、起因、当前情况），案卷、流水、人物变动、人物经历、文字事实、公开说法各自指向它，沿 [0054](0054-ledger-cross-links-and-effect-backrefs.md) 族规单向新指旧、事务不复制清单，也不自设经手人名单（从指向它的案卷参与人与人物经历推出）。事务与案卷同在收夜成案时诞生，由拆旨 LLM 说明这几道旨属于哪件事或接到哪件已开着的事上；推演中新起的事由推演 LLM 交结果时新起；事务的边界由 LLM 声明；事务何时成为往事依下段后出裁定，与案卷「结案」分开。

事务成为往事（2026-09-30，[#1815](https://github.com/Akagilnc/ming-salvage-sim/issues/1815) 后出裁定）：不设「宣布了结」动作及拒绝该动作的守门；底下的事都平息了，事务自然成为仍可查、可问的往事，未平息时仍记得全貌。模型演具体事项，转译记录其结果；世界记录接缝 #1813 据这些事项的实况承接事务成为往事，供料接缝 #1814 保留按身份取阅其来龙去脉的能力。此裁定替代 #1818 原决定 4 的了结声明及 2026-09-11 补充决定的拒绝了结守门，不改变事务身份、边界和单向关联。
