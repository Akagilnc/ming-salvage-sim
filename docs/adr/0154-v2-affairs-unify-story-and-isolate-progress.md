# V2：按一件事连贯推演，按基础信息落账

Status: proposed（2026-09-09；owner 已拍方向，设计待评审，未实施；仅适用于 V2）

同一件事的人事、财政、军事因果由综合推演连起来，落库时才区分人、钱、军队等基础信息，避免各领域各演一份相互矛盾的结果。世界推演同时考虑多件事共用的人手、钱粮和兵力；这不规定「每件事一个 LLM 调用」，也不规定整个天下只能一次调用。

事务保留皇帝原意、附加条件、承办关系、经历和已发生的后果；LLM 可随执行自然展开后续安排，需要皇帝决断时沿批红等既有渠道请示。主要后果按月回合体现，LLM 演出的当场实际结果也可立即记下；不由代码建立「某动作必须即时／某动作必须月底」的剧情分类表。记住一句旨意、某人说过的话，与提前结算其全部后果不是一回事。

一件事的待办或处理失败只影响它自己，不拖垮无关事项，不因本件失败撤销其他已成功结果或让它们重演。此处隔离的是等待与处理故障，不取消事情之间真实的资源竞争和剧情后果；同件事的关联变化、跨事务共享资源及回合恢复怎样落实，留待具体设计，不在本 ADR 发明事务协议。

## 与既有设计的关系

现行 [0008](0008-settlement-applier-contract-and-transaction-boundary.md) 及 [0150](0150-entity-adapter-directory-and-settle-delta.md) 存在整段回滚语义，不能直接称为已经满足本方向；[0015](0015-delta-apply-failure-per-item-rejection.md) 的项级隔离也不能直接当成 V2 的事务级方案。本 ADR 记录 V2 取舍，不授权本轮修改现行结算或批红时点。

原话、月末与当场结果的演变、失败隔离依据见 [讨论依据](../design/game-v2-architecture.md#事务与时间依据)。
