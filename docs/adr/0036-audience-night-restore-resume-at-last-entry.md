# 召对夜 restore = 回到最后一条持久化对话轮续夜；落账即史实；丢失回话给重试不重打

Status: Accepted（2026-07-02：本地 cmr 十轮收敛（codex xhigh + agy + Opus 4.8）+ 线上 bot 轮收敛，PR #510；2026-07-02 #470 grill 结晶；2026-08-14 #612 Owner 方案 A：普通即时抽取 + 收夜一次 endorsement-only 成功才封夜）

## 决定

- **夜跨进程存活**：关档/崩溃后重开，回到那一夜**最后一条完成并持久化的对话轮**接着聊（续夜），不自动落幕。对话轮持久化即史实——纯奏对长段（杨嗣昌四轮问对零账目）寸步不丢；LLM 对话现场从账本 + 对话记录确定性重建。
- **落账即史实**：已落的账与已持久化的对话轮永不因重开回滚；restore 只影响「没落完的那半句」。
- **对话记录与账本的崩溃一致性**：叙事抽取落账以**已持久化的回话**为重试真源（同 ADR 0008 delta ready=1 断点续跑先例）——重开时发现已完成回话但账未抽取（站台/进出账丢在崩溃窗口里），**补跑抽取**，不回滚对话；两个 store 永不分叉。
- **补跑失败不锁档**：restore 时补跑抽取失败（持续畸形输出/接口故障）不得中止恢复——夜照常续、该段账标「待补」、给玩家显眼提示可原地重试（同「密令下达失败」的显眼提示+重试+不阻塞语义）；响亮错误包照发，但**永不进启动致命路径**（否则每次重开都在初始化阶段崩溃 = 存档锁死循环）。**待补期间一切派生只认已落账**（在场推导/见闻取数：缺账 = 尚未发生，不猜、不设额外降级路径），补账落地后自然校正（cmr R4）。待补不挡夜内对话（照常续），但**收夜是史实书写边界、收夜前须清空待补**（线上 R3 修订 cmr R5 口径）：收夜 beat 消费在场名单生成收尾叙事并落账——带着可能含在场变化的待补账收夜，会把过期名单写成史实、补账插回原时序后同一时间线自相矛盾（某人既已告退又参与收夜）。故进入收夜先强制同步补跑一次；仍失败 → **fail-closed 中止收夜**（夜保持开、显眼提示可重试，同超时熔断语义）。暂存动作从不走叙事抽取链、与提交点无关（cmr R5 澄清仍立）。
- **抽取进度确定性可判**：哪些已持久化回话已抽取过账必须可确定性判定（如账目关联源对话轮、或按夜记抽取水位——编码归切片），补跑既不重复抽也不漏抽；补跑落账的**时序键绑定源对话轮的原始时序**、不用补跑执行时刻（否则历史账落在后续轮之后，时间轴颠倒——cmr R7 钉）。
- **单轮抽取落账事务原子（cmr R3）**：一轮抽取产出的多条账在**同一事务内全有或全无**落库（同 ADR 0008 事务纪律）——该轮抽取状态因此二元（已抽/未抽），杜绝「写一半崩溃 → 补跑把已写的那条重复落账」。
- **丢失回话的恢复形态**：崩溃时正在生成的大臣回话丢弃；玩家最后那句已发问话仍在记录里、不消失，重开后在它上面给**重试**（重新生成回话），不让玩家重打一遍、对话记录里不出现两句一模一样的话。此重试是系统层恢复动作（同「密令下达失败」的原对话重试语义），不是给皇帝的内容选项按钮（不碰角色保真线）。
- **普通故事即时抽取；收夜一次 endorsement-only 成功才封夜（#612 Owner 方案 A）**：每轮回话后的普通 story/presence **即时**落账，不因已应允 pending 延迟。收夜可先把已应允旨意耐久写成 draft 案卷前提，再在最终案卷 identity 与 surviving source turns 快照完成后，夜级**一次** endorsement-only 批绑定；LLM 不持 DB transaction / runtime write gate，仅可与不依赖背书、不落终局状态的收夜准备（如收尾 beat 纯生成）并发。**只有背书批成功**才允许判官/公开明发/终局效果/CLOSED。失败 → 夜保持 OPEN、游标重开、draft identity 与已同意项保留、无需重新 consent；重试幂等（唯一键 + 每夜单一 bound 水位）。边界钉死：仍守 ADR 0070 新指旧、不造待背书关系表、普通抽取不写 endorsement。跨轮普通补跑按源对话轮串行；单轮与夜级争用均 single-flight 有限返回，不另立 Future/结果登记。

## 为什么

连场夜是长会话（半小时起）、最容易中途关档；「重开=夜落幕」恰恰在最贵的体验（北极星连场）上装易碎开关。账本模型（ADR 0035）使续夜天然便宜：账本即存档，P1「restore 只读 DB 无损接续」满分。用户 2026-07-02 拍 1 并加重试按钮设计。锚点从「最后一笔完成账」修正为「最后一条持久化对话轮」：PRD 发布前北极星冷查（2026-07-02）抓出原口径在纯奏对长段会整场蒸发（奏对不产账目），且「回话已展示、抽取未落」的崩溃窗口会让对话与账本分叉。补跑失败降级与抽取水位两条为 cmr R1 追加：补跑若进启动致命路径，持续失败=存档锁死循环；账↔对话轮无确定性关联则补跑判定歧义（重复抽/漏抽）。

## 否决的备选（防日后重议）

- **重开 = 夜自动落幕**（已落账保留但夜结束）：惩罚玩得最投入的时刻，连场后半晚蒸发、现场气氛（王绍徽被逼到墙角）散掉。
- **恢复到软段边界、作废进行中软段**：软段无硬边界，「作废进行中的段」在账本模型里定义不清。
- **让玩家把最后一句重打一遍**：记录里出现两句相同的话，脏且没必要。
