# 召对夜 restore = 回到最后一条持久化对话轮续夜；落账即史实；丢失回话给重试不重打

Status: Proposed（2026-07-02 #470 grill 结晶；评审闸在 to-prd 之后）

## 决定

- **夜跨进程存活**：关档/崩溃后重开，回到那一夜**最后一条完成并持久化的对话轮**接着聊（续夜），不自动落幕。对话轮持久化即史实——纯奏对长段（杨嗣昌四轮问对零账目）寸步不丢；LLM 对话现场从账本 + 对话记录确定性重建。
- **落账即史实**：已落的账与已持久化的对话轮永不因重开回滚；restore 只影响「没落完的那半句」。
- **对话记录与账本的崩溃一致性**：叙事抽取落账以**已持久化的回话**为重试真源（同 ADR 0008 delta ready=1 断点续跑先例）——重开时发现已完成回话但账未抽取（站台/进出账丢在崩溃窗口里），**补跑抽取**，不回滚对话；两个 store 永不分叉。
- **补跑失败不锁档**：restore 时补跑抽取失败（持续畸形输出/接口故障）不得中止恢复——夜照常续、该段账标「待补」、给玩家显眼提示可原地重试（同「密令下达失败」的显眼提示+重试+不阻塞语义）；响亮错误包照发，但**永不进启动致命路径**（否则每次重开都在初始化阶段崩溃 = 存档锁死循环）。
- **抽取进度确定性可判**：哪些已持久化回话已抽取过账必须可确定性判定（如账目关联源对话轮、或按夜记抽取水位——编码归切片），补跑既不重复抽也不漏抽。
- **单轮抽取落账事务原子（cmr R3）**：一轮抽取产出的多条账在**同一事务内全有或全无**落库（同 ADR 0008 事务纪律）——该轮抽取状态因此二元（已抽/未抽），杜绝「写一半崩溃 → 补跑把已写的那条重复落账」。
- **丢失回话的恢复形态**：崩溃时正在生成的大臣回话丢弃；玩家最后那句已发问话仍在记录里、不消失，重开后在它上面给**重试**（重新生成回话），不让玩家重打一遍、对话记录里不出现两句一模一样的话。此重试是系统层恢复动作（同「密令下达失败」的原对话重试语义），不是给皇帝的内容选项按钮（不碰角色保真线）。

## 为什么

连场夜是长会话（半小时起）、最容易中途关档；「重开=夜落幕」恰恰在最贵的体验（北极星连场）上装易碎开关。账本模型（ADR 0035）使续夜天然便宜：账本即存档，P1「restore 只读 DB 无损接续」满分。用户 2026-07-02 拍 1 并加重试按钮设计。锚点从「最后一笔完成账」修正为「最后一条持久化对话轮」：PRD 发布前北极星冷查（2026-07-02）抓出原口径在纯奏对长段会整场蒸发（奏对不产账目），且「回话已展示、抽取未落」的崩溃窗口会让对话与账本分叉。补跑失败降级与抽取水位两条为 cmr R1 追加：补跑若进启动致命路径，持续失败=存档锁死循环；账↔对话轮无确定性关联则补跑判定歧义（重复抽/漏抽）。

## 否决的备选（防日后重议）

- **重开 = 夜自动落幕**（已落账保留但夜结束）：惩罚玩得最投入的时刻，连场后半晚蒸发、现场气氛（王绍徽被逼到墙角）散掉。
- **恢复到软段边界、作废进行中软段**：软段无硬边界，「作废进行中的段」在账本模型里定义不清。
- **让玩家把最后一句重打一遍**：记录里出现两句相同的话，脏且没必要。
