# 四层架构：账本、中间层、使用者、前端

Status: accepted（2026-10-18 owner grill 定；2026-10-21 owner 定结构六条；2026-10-30 补记；2026-10-31 owner 认可架构四条）

旧引擎越写越复杂，北极星两场走不完一个月（ADR 0159）。owner 定下四层：账本只存事实，中间层是账本唯一的门，使用者按顺序调模型，前端只显示与交互。owner `3b6d86c0-fa66-48cd-8b13-6391a6e6093b`：「对，骨架对：四层、只往下依赖、账本一个门、使用者只经账本交接」。

分层与规矩逐字抄自 #1943 条款 1；过月步骤此后由 ADR 0163 重排，以 0163 为准。

| 层 | 干什么 |
|---|---|
| 账本 | 只存物理事实：人物、地区、账户等实体（开局从 `content/` 建）；游戏里发生了的事（任免、拨款……）作为事件记在所涉的实体上，陕西赈灾这类跨月的事是事务，人物的事件即履历、账户的事件即财政流水；文字事实是所描述实体上带自由文字的事件（ADR 0156），公开说法与人物见闻按其法源记录。只管存取；不知道模型存在。 |
| 中间层 | 账本唯一的门。往外：按身份把事实选出、排版成可读材料。往里：转译模型把自由文字说成声明，代码只分派、按声明校验、核算、落账。 |
| 使用者 | 召对、过月（以后的新玩法同层）：按顺序调模型（场景演戏、外廷准驳、推演、邸报），向中间层要材料、把结果交给中间层记。 |
| 前端 | 只显示与交互。读走中间层往外的门（身份＝皇帝，P4 由同一套按身份供料管住）；写与动作走使用者。 |

规矩：①代码不判断——只有模型判断，代码分派、按声明校验、核算、落账（P6）；②只往下依赖，不反向、不跨层（前端读走中间层是唯一例外）；③账本只有一个门，使用者不直接碰账本；④使用者之间不直接调用，只经账本交接。

三处钉死：
- **clamp**：模型提的数原样记成名义数（ADR 0073），实数由引擎按账本实有封顶并双边扣账（ADR 0153 2026-09-10 注记），实数作为事实回给后续调用；代码不改模型的字，也不静默丢任何一项。对账本事实的存在性核对（查无此人、库无此账）是事实核对：核不上先带可操作反馈回模型重交，用尽落成事实。
- **材料只选不编**：中间层按事实字段筛选、按固定格式排版；不摘要、不概括文字。数值到定性档位的固定对照（ADR 0143）保留。
- **中间层只许三样**：每种事实一进一出的分派；对账本事实的校验；本票点名法源里、且北极星路径会走到的确定性核算（拨款按账本实有封顶）。0153 举过的火耗、押解折损等，路径没走到的不在本票实现，也不作废。判断意思、意图、该不该的代码，删或交模型。

## 结构决定（2026-10-21）

owner `c487b564-511f-4e6d-bfca-5f37016bef55`「结构上这6个问题先改在做」。以下逐字抄自 #1956；同票的批红规矩已由 ADR 0163 重排，不在此抄。统管模块归层由下文「架构四条」定。

- **中间层只留四个通用口**：按身份读、在实体上记事件、转译、唯一落账口（ADR 0159）。
  - 带过月词汇的方法全归过月使用者 `Month`：本月产物、轮次、奏疏、何时落账。落账本身仍由 Month 调中间层那一处去落。
  - 呈现用的状态（face、running、failure）不留在 `Court`，归下面的统管模块。
- **月份阶段是有名字的一步**：开月由 Month 明确记一笔，冻结皇帝视图是这一笔的产物；「本月进行中」由这一笔回答。读取函数不写账本。
- **玩家动作由一个统管模块管**。把现在 `Web` 里不属于 HTTP 的部分抽成包内模块，网页与命令行都只做薄壳调它。它不是第三个使用者，位于入口与使用者之间。它负责：
  - 按顺序调召对、过月：退朝后后台预推（取代 `precompute`），过月前先等整夜转译做完。
  - 动作受理那一刻就记一笔「进行中」，带重放所需的全部参数（说话：原话与夜；批红：奏疏与选项）；失败时只改状态、补原因。错误日志路径只算一次。
  - **进程中断，重开后一律自动接着做未完成的部分，已落的不动**。说话、批红、过月、整夜转译都一样：被中断的那句召对回话，用受理时记下的原话自动重新生成。
  - **只有模型调用真失败（自动重试用尽）才停住**，记失败、给重试按钮；玩家点了重试，才续未成的部分。
  - **夜里预推失败照旧不拦过月**：不出提示、不给重试，过月时补跑这道旨。
- **转译整夜只留一处**（召对使用者），退朝后与过月前都由统管模块调它，它的进行与失败按统管规则记。`Month` 不再自己转译。
- **重试只有一种**：所有模型调用一共试 3 次，429 不重，500 一类与超时 5 秒后重（陛下 `0a7169fc`）。前后台的区分和 `background` 参数整条删去。夜里预推失败由调起它的那一处接住、记错误日志。
- **建模型调用只有一个入口**：instructions、output_type、tools 一次交给它，由它同时接到 Agent 和适配器上。
  - 它同时也是唯一的模型工厂，后端与模型名一起定。
  - 设置里选 Claude 命令行后端、没填模型名时，不向 CLI 传模型参数，由 CLI 自己的默认决定；代码不写死默认模型名，也不加保存校验（陛下 `01e8f037`）。
  - `Unhandled` 归声明模块。
- **每一步是一个具名、只建一次的模型调用**（外廷议处、推演、邸报、场景、整夜转译、月末转译），身份经 deps 传入，读材料的工具按本次调用的身份供料。测试用 pydantic-ai 原生的 `Agent.override(model=…)` 给每一步配替身，不按调用先后、也不按提示措辞认步骤。补上带旨意过完一个月的测试。

## 架构四条（2026-10-31）

结构重排（#1996–#2000）审出的细节题，根子是流程状态不在账本。owner `d461c971-0896-4467-9765-a91606db1ab4`：「太细节了。先把你架构问题搞清楚。就不应该有这些细节问题」。runner `1c887cce-c683-4f8f-9028-6ffb92522a55` 呈这四条及其推论、问「这四条对吗？」，owner `622bed3d-7242-4181-afc7-19caf9c1c215`：「看起来好像是对的」。

- **进度只看账本**：走到哪一步、完成没有，都由账本回答，不留第二份状态（ADR 0155、0166）。
- **中间层不懂玩法**：过月、批红这些词都归使用者；含义在产生时写成事实，中间层只读事实。
- **玩家动作只做一件事**：把动作记成事实，再让使用者接着补缺口。失败也是一条事实，进程重开走同一条路。
- **这轮不改玩家体验**：#1996–#2000 只改结构，玩法和付款结果都不变。

由此定：

- 统管模块（`Game`）留在使用者层，当召对、过月共用的入口，只负责收动作、叫召对和过月；它不是第三种玩法，四层不变。
- 「中间层只留四个通用口」按分工读：过月的步骤和产物含义归 `Month`；查询、校验、核算留在中间层内部，不暴露给使用者；纯转发的方法删掉，不为凑够四个另造分派。
- 动作的完成以业务产物为准，不另留一份完成状态，也不事后对账。
- 批红的选项与处置在 `Month` 内只有一处定义；选项含义在生成奏疏时写成事实，选定后都读这份记录，中间层不靠选项文字或追加顺序认含义。
- 月末声明存档是事实，保留；校验与落账共用一次结果，中断后从存档重新核算，不再问模型。
- 落账不留独立预读清单：核算需要什么就读什么，同次操作里已读到的复用，不造依赖描述。
- 皇帝的月初冻结只冻普通事实；奏疏、批红、回报照现行规则显示。
- 代码异常照 ADR 0158 决定 6：停下来，显示真实原因和日志，可以重试。
