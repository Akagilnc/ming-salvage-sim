# 账本＝实体＋事件；旨意落账、重交与接不住

Status: accepted（2026-10-18 owner grill 定）

旧引擎把旨意后果拆进几十种落库字段，越写越复杂，北极星两场走不完一个月。重写后账本只有两样东西，落账只有一种写法，模型写错就让它补交，代码不判断。

- **实体**：人物、地区、账户、军队等，开局从 `content/` 一次建好。每个实体现在什么样＝开局的样子加上记在它身上的事件。
- **事件**：游戏里发生了的事（任免、拨款、受伤……），记在它涉及的实体上。人身上的事件就是他的履历，账户身上的事件就是流水。无固定格式的实况（「右臂受伤，仍能指挥」）是带自由文字的事件。
- **事务**（陕西赈灾、畿辅试点清丈）：跨人物、钱粮、月份的一件事，事件指向它所属的事务。
- **旨意**：下旨 → 外廷判 → 落账 / 接不住。分类照旧分交办与拨款。
- **同一次提交**：事件与人物表、账户表等普通表在同一个事务里写入，要么全落、要么全不落；一局一个 SQLite 文件，每次落账即提交，不另做存档。
- **名字对账本**：转译交来的人名、官名、账户名必须是账本正名；官名只写官衔，地区单独一栏。对不上就带上「哪个字段、现值、账本里的正名与别名、该怎么改」回给模型重交整份；只有一层重试。用尽就记一条「接不住」，附模型原文与失败点，不崩，流程照走。
- **新官上任**：引擎自动罢免同官同地的原任；`content/` 里标为「多员」的官不罢免。
- **撤回本轮**：不做。

## 皇帝看得见什么

人名、官职、所在、在不在任。裸数值和国库真数不给，由大臣奏报口吻转述。

## 考虑过、没选

- eventsourcing 自己维护查询表：它的投影运行器在 SQLite 上不能用（`SQLiteApplicationRecorder.subscribe` 不支持），所以人物表、账户表由落账代码在同一事务里直接更新。
- 每类事实一个全局聚合：不选，一个实体一个聚合。
- 一刀切单一旨意格式：搁置，遇到问题再拆。
