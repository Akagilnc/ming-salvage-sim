# 账本＝实体＋事件；旨意落账、重交与接不住

Status: accepted（2026-10-18 owner grill 定）

旧引擎把旨意后果拆进几十种落库字段，越写越复杂，北极星两场走不完一个月。重写后账本只有两样东西，落账只有一种写法，模型写错就让它补交，代码不判断。

- **实体**：人物、地区、账户、军队等，开局从 `content/` 一次建好。每个实体现在什么样＝开局的样子加上记在它身上的事件。
- **事件**：游戏里发生了的事（任免、拨款、受伤……），记在它涉及的实体上。人身上的事件就是他的履历，账户身上的事件就是流水。无固定格式的实况（「右臂受伤，仍能指挥」）是带自由文字的事件。
- **事务**（陕西赈灾、畿辅试点清丈）：跨人物、钱粮、月份的一件事，事件指向它所属的事务。
- **旨意**：#1947 v10 替代交办／拨款分类：领旨者拟成正式圣旨、皇帝认可才成，退朝整夜转译记录定稿全文、来历与涉及的人；没表态为默拒。待执行后果由 #1948 外廷判、月末通用实体字段声明落账 / 接不住。依据见 [0155](0155-v2-single-scene-llm-with-complete-perspectives.md)。
- **同一次提交**：一次落账的全部事件、库的投影策略写的读表行、以及 tracking，在同一个事务里写入，要么全落、要么全不落；一局一个 SQLite 文件，每次落账即提交，不另做存档。读表由谁写、怎么读见 [0160](0160-read-tables-by-library-projection.md)。
- **名字对账本**：转译交来的人名、职位名、账户名必须是账本正名（或开局数据里写明的别名）。对不上就带上「哪个字段、现值、账本里的正名与别名、该怎么改」回给模型重交整份；只有一层重试。用尽就记一条「接不住」，附模型原文与失败点，不崩，流程照走。账本里没有的职位不新建，照此退回（owner 2026-10-23 `6e4331f1` 题7 甲）。~~官名只写官衔，地区单独一栏。~~（2026-10-23 取代：该句无 owner 原话；见下条「职位」，owner `6e4331f1` 题1 乙。）
- **职位**（2026-10-23，#1943 v9，owner `6e4331f1`；`e2666634`「人本来就可以任多个职位。这和某些职位只能是一个人一点也不冲突」）：一个职位一个实体，名字就是职位名（兵部尚书、陕西巡抚、大同巡抚、蓟辽总督、内阁大学士……）；辖区、所属衙门、单员或多员都是职位上的数据，不参与身份；不是官的身份不建职位。在任者只记在职位上（单员一人，多员一份名单）；人物身上不存任职字段，「某人任何职」「在不在任」由查询得出。任免是职位在任者字段的一次通用变更，同时记进所涉人物的履历。一人可任多职。
- **新官上任**：单员职位写入新人即替换原任，原任只失去这一个职位，得一条履历事件；他的其余职位、在场与行程都不动。下狱、致仕、离场由模型声明，引擎不因罢免改人物状态（owner `6e4331f1` 题4 乙：「人退场明显是你们加戏。我可没说过。还有起复呢对吧」）。起复与任免是同一种声明：给职位写入在任者。多员职位不罢免。
- **钱粮往来**（2026-10-23，#1943 v9）：每笔钱只声明一次（付方的增减加上收方），收方不论是不是账户，另一边由引擎按封顶后的实数记；不要求模型两边各写一遍。
- **拒收只许三类**（2026-10-23，#1943 v9）：声明结构不合、账本引用查无此物、落账执行缺必需项（如钱没出处、单员职位写了两人）。其余一律夹范围或原样落账。
- **撤回本轮**：不做。

## 皇帝看得见什么

人名、官职、所在、在不在任。裸数值和国库真数不给，由大臣奏报口吻转述。
