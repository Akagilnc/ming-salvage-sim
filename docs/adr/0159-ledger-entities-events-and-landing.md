# 账本＝实体＋事件；旨意落账、重交与接不住

Status: accepted（2026-10-18 owner grill 定）

旧引擎把旨意后果拆进几十种落库字段，越写越复杂，北极星两场走不完一个月。重写后账本只有两样东西，落账只有一种写法，模型写错就让它补交，代码不判断。

- **实体**：人物、地区、账户、军队等，开局从 `content/` 一次建好。每个实体现在什么样＝开局的样子加上记在它身上的事件。
- **事件**：游戏里发生了的事（任免、拨款、受伤……），记在它涉及的实体上。人身上的事件就是他的履历，账户身上的事件就是流水。无固定格式的实况（「右臂受伤，仍能指挥」）是带自由文字的事件。
- **事务**（陕西赈灾、畿辅试点清丈）：跨人物、钱粮、月份的一件事，事件指向它所属的事务。旨意所建事务可带**按月专款**（每月数额、出款之库、止于某月），引擎从声明当月起每月照现有按月付款规则付，库银不足照欠；到止期后应付为零。减额、暂欠复用现行付款政策（其止期到期回原额，与专款止期是两回事）；首次声明时排到出款库付款顺序末尾，以后改序照现行由旨意声明（#1977 runner 依常令裁定 Q3–Q5、F1）（2026-10-25 北极星终验 B 案「每月国库拨你五十万两」只扣一次；owner `32325ca9-4f6a-4fdd-a0a4-55065e88ae6f`「这不就是建立的事务/事件吗？这是一个最明显的bug」）。
- **旨意**：#1947 v10 替代交办／拨款分类：领旨者拟成正式圣旨、皇帝认可才成，退朝整夜转译记录定稿全文、来历与涉及的人；没表态为默拒。密令另由夜间转译照整夜戏文声明唯一一位**承办人**（账本正名，领旨去办的那一人），涉及的人原义不动；密奏以承办人一人的立场说话、用他的身份读账，密报与未发觉的密办后果也只归他取阅；旨文知情、暴露度、推演泄露仍按涉及的人加成旨时殿上名单。缺承办人或非账本正名，照现有落账核对退回转译重交，引擎不代挑（#1977 runner 依常令裁定 Q1、Q2；owner `277ec950-b6ca-4923-8b1a-999790689842` 所答「密令必须有一个点了名的承办人，月末由他一个人回禀」「旁听的人……不替承办人回禀」，`ebc2fa27-c9a3-4728-92a8-a3b1cfc9f73b`「密令就是密令」）。待执行后果由 #1948 外廷判、月末通用实体字段声明落账 / 接不住。依据见 [0155](0155-v2-single-scene-llm-with-complete-perspectives.md)。
- **同一次提交**：一次落账的全部事件与落账代码写的读表行，在 eventsourcing-sqlalchemy 的同一个事务里写入，要么全落、要么全不落；一局一个 SQLite 文件，每次落账即提交，不另做存档。读表由谁写、怎么读见 [0160](0160-read-tables-by-library-projection.md)。
- **名字对账本**：转译交来的人名、官职与属地名、账户名必须是账本正名（或开局数据里写明的别名，解析回账本键）。对不上就带上「哪个字段、现值、账本里的正名与别名、该怎么改」回给模型重交整份；只有一层重试。用尽就记一条「接不住」，附模型原文与失败点，不崩，流程照走。账本里没有的官职或属地不新建（在任记录由引擎在首次任职时记），照此退回（owner 2026-10-23 `6e4331f1` 题7 甲）。~~官名只写官衔，地区单独一栏。~~（2026-10-23 取代：该句无 owner 原话；见下条「官职、属地与任职」。）
- **官职、属地与任职**（2026-10-23，#1943 v9；owner `6e4331f1` 题1 乙，`4ecee17a`「西安府知府 和 xx府知府 还是两个不同的官？我觉得不能把」，`3d0bac67`「官职 知府 属地 西安 别名 西安知府」，`a0dce7f8`「正常不就是 官职+属地 两个。组合虽然多。但是单看官职没多少啊」，`02163ec0`「按照史实的情况来。而不是在那里自己发明机制」，`0477a7b6`「啥叫按缺？我咋觉得你们把实体有总结出了新名词」；`e2666634`「人本来就可以任多个职位。这和某些职位只能是一个人一点也不冲突」）：数据只有官职表、属地表两张。官职一个一个实体，名字就是官名、不带地名，所属衙门与员额（一员或多员）是它的数据，照《明史·职官志》；京官无属地，南京诸衙门照史单列、官称带「南京」（卷75「在南之官加『南京』字於職銜上」），外官按属地设。属地一处一个实体（两京、省、府州县、边镇、督抚辖区），别名与所属账本地区是它的数据。任职关系＝谁现任某个「官职＋属地」（京官只有官职）：组合不预先列举，某组合第一次有人任职时，引擎记一条在任记录，键为（官职，属地），在任者（一员一人，多员一份名单）只记在这里；它是「在任者不记在人身上」的必然落点，不是第三张表或新概念。人物身上不存任职字段，「某人任何职」「在不在任」由查询得出。任免是在任记录的通用字段变更，同时记进所涉人物履历。一人可兼多职。转译照史书叫法写：京官写官名（含「南京户部尚书」这类），外官写「属地名或属地别名＋官职名」（如「陕西巡抚」「西安知府」）；中间层按两张表精确对照，解析出唯一组合才算对上，两张表对不上或解析不唯一即退回，不另设组合限制；地名与别名照史料收集。开局人物数据照史实修正，逐条附出处（owner 687f205d「开局数据问题不改。留着谁改？」）。不是官的身份不建官职。先例调研见 vault `raw/ming-llm-runner/2026-10-23/office-model-prior-art.md`。
- **新官上任**：一员的官职在同一属地写入新人，只替换这一「官职＋属地」的原任；同官别的属地不动。原任只失去这一职，得一条履历事件；他兼的其余职、在场与行程都不动。下狱、致仕、离场由模型声明，引擎不因罢免改人物状态（owner `6e4331f1` 题4 乙：「人退场明显是你们加戏。我可没说过。还有起复呢对吧」）。起复与任免是同一种声明：给「官职＋属地」写入在任者。多员不罢免。
- **钱粮往来**（2026-10-23，#1943 v9）：每笔钱只声明一次（付方的增减加上收方），收方不论是不是账户，另一边由引擎按封顶后的实数记；不要求模型两边各写一遍。
- **拒收只许三类**（2026-10-23，#1943 v9）：声明结构不合、账本引用查无此物、落账执行缺必需项（如支出没写收方、一员的职写了两人）。其余一律夹范围或原样落账。
- **撤回本轮**：不做。

## 皇帝看得见什么

人名、官职、所在、在不在任。裸数值和国库真数不给，由大臣奏报口吻转述。
