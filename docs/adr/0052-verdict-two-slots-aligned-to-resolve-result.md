# 0052: 案卷判决=两格——颁布格+执行格，schema 对齐 0011-5，认账不设格

Status: Proposed（决策：2026-07-03 #474 设计闸 grill Q2/Q3 用户拍「两个格子，不多备」+「效果/参与人照记」）

每份案卷带两个判决格：**颁布格**（顺颁/打回/中旨强颁＋卡在票拟/批红/封驳哪层＋一句缘由）与**执行格**（执行中/兑现/打折走样/烂尾＋走样说明＋结案回合）。格子语义=0011-5 ResolveResult 的子集（outcome/blocked_layer/exec_fidelity），M12 resolve_core 落地后接管填值、**表结构不改**（interim 由软判填，0057）。「认不认账」不设第三格——那是大臣读前两格照账演戏的读端行为（D5-11＋见闻），立格即造第二真源。预留扩展口：**legal_reason_code** 空槽（M12 **依律集专用**、扩 0009 enum；污名不入此槽——STIGMA 走 0051 中旨标记字段＋独立常量表，恪守 0011-2/0011-5 码集二分，cmr R3 校正）＋JSON 扩展袋（pending_actions payload_json 先例）。消费方：批红页打回抉择（0055）、大臣认账话术、回声/起居注（#478 家族）、#476 到期复核（**裁判权归 #476、落点在本格**——两边 ADR/issue 互指，防 #486 watch-item 点名的「谁都以为别人 own」黑洞）、#479 关系账。P4：格子对玩家只经定性叙事呈现，系统词与枚举值永不裸露。
