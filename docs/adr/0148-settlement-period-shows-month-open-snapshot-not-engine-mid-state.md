# 0148 — 结算未完成时皇帝看见月初快照与核账叙事，不看引擎半程状态

Status: proposed（陛下 2026-08-16 拍：mock 四版比选取「丙」）

## 决定

**结算期的可见面是服务端相位的函数，内容为月初快照 + 核账叙事。** 自玩家点颁布/退朝起、至本月 `next_period` 完成止，顶栏的钱与民心皇威**冻结在月初值**，年月位置标核账态，并以王承恩递话呈现「事情在办」；这段封锁与进度**由 `turn.phase` 驱动，跨刷新一致**，不得依赖客户端会话变量。期间封「会推进或改写本月」的入口（拟诏、退朝、召对发言），保留只读浏览。不加进度条、百分比或剩余秒数。

## 为什么

引擎为崩溃续跑设了检查点：`pre_settle` 的固定财政流水自带事务先提交（[ADR 0008](0008-settlement-transaction-boundaries.md)），而月份推进在管线末尾的 `next_period`。撞上亲裁决策点时管线停在 `awaiting_decision`，于是皇帝看见「钱已经动了、月份没过」——2026-08-15 QA 实测国库 320→335 万、内库 440→462 万、民心 50→58 而日历仍在十月（[#1201](https://github.com/Akagilnc/ming-salvage-sim/issues/1201)）。**这是引擎检查点泄漏到呈现层**，不刷新也看得见。

同时封锁只活在客户端 `busy === "月末结算"`，刷新即归零，服务端相位当时只被用作崩溃恢复入口；玩家刷新后看到完整可操作界面加「待你批红、钱没扣」，合理推论是没批成、想再批一次（[#1203](https://github.com/Akagilnc/ming-salvage-sim/issues/1203)）。ADR 0036 已为召对夜拍过「关档/崩溃后重开接得上」，理由是长会话最容易中途关档；结算期是同一件事的另一半。

取月初快照而非标注未过账：**标注只是把不自洽标出来，冻结才消除它**。取叙事而非进度条：P4 定「DB 有数、皇帝无表」，而「户部还在核这个月的账」本身就是可叙事的——这 60–70 秒是真实存在、有戏的一段。

## 边界

- **不动 [ADR 0008](0008-settlement-transaction-boundaries.md) 的事务决定**：`pre_settle` 照旧先提交、崩溃续跑照旧不重跑 LLM。本 ADR 只约束这些中间态**对皇帝的可见性**。
- 冻结是呈现层的事，DB 与引擎读的仍是活值。
- 失败态（结算真挂了）的呈现不在本 ADR，另议。

## 否决的备选（防日后重议）

- **显示新数但标「未过账」**：多一套视觉语言要玩家学，世界仍不自洽、只是标注了出来。
- **数值区整块让位给叙事**（核账期连数都不报）：角色感最强，但批红常常就是在决定花多少钱，看不到国库余额会真碍事。
