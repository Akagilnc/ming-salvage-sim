# 测试的公共前置一次运行只建一次，各测试从私有副本起跑

Status: accepted（2026-10-22 owner grill 定：「明明可以把公共的步骤跑一次。别的步骤也跑一次。而不是 公共步骤跑几百上千次，这也是一种违反dry的行为吧」；答题 `206ec85f`「2 肯定是2， 公共的节点就该只跑一次」「4 不缓存」「5 肯定是1」，`d279b4a1`「Q3 ok。同意」，`68b80bd4`「确实应该引入测试框架。而不是什么都自己手写。」，`048053f5`「adr里面为什么要写清单？adr不是这样用的吧」，`c8b273c5`「1B 2A 正常流程本来就是设计先落地再开工。」；spec #1960）

`ming/` 的测试几乎每条都从新开局起跑，过月、批红类还要把夜、召对、退朝重跑一遍才到要测的那一步；新开局一次要导入上千个实体，同一段前置在一次运行里重复几十次（#1959 后全量 66 条 104 秒）。原则是 Meszaros 的 Immutable Shared Fixture，随 #1960 写入全局硬规 #13 第⑥条；本篇定它在本仓怎么落。

## 决定

- **公共前置只建一次**：多条测试共有的前置，一次测试运行内只经真实入口建一次，建成即只读。
- **测试的真实输入不被替换**：共用前置不能改变任何一条测试原本的输入。哪些测试共用哪个节点，由施工按测试事实确定，本篇不预设判等规则。节点由它的父节点经真实入口建出，节点之间长成一棵树。
- **各测试从私有副本起跑**：同一节点下分出的走法互斥（同一夜退朝与接着召对不能同时发生），每条测试拿该节点产物的一份私有副本，只跑自己那一步，互不可见。
- **以某一步本身为被测行为的测试**（如开局导入）仍从它的父节点真跑这一步。
- **用测试框架现成的共享夹具**，不手写调度；前置建立失败交框架原生处理：依赖它的测试不运行、报准备出错，原因相同。
- **不跨测试运行缓存**：每次运行从头建一遍树。
- 节点清单只在测试夹具里，本篇不列。

## 考虑过、没选

- **每条测试从零自建（现状）**：同一段前置重复几十上百次，违 DRY，测试慢到没人愿意常跑。前置便宜时它仍是对的，本篇只管前置贵且多步的情况。
- **共享但不拷贝、按固定顺序串着跑**：一条测试的写入会被后面的测试看见，结果随顺序变；文献里这是测试时红时绿的头号成因。
- **按游戏步骤认节点、不管输入**：会逼着测不同情况的测试共用同一段模型回话或同一份开局数据，改了测试的输入。
- **在 ADR 里预先固定判等规则（如「录制回话相同才算同一节点」）**：只点名部分输入会漏掉其余输入（如开局数据），且把会随测试变化的实现细节写进了决定。
- **跨运行缓存局面**：代码一改旧局面就可能过期，要另造「输入变了就重建」的失效机制。
