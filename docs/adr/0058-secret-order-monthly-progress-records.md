# 0058: 长差密令月度进展记录——逐月落库，月报推送与垂问拉取同数据

Status: Accepted（2026-07-04 随 PR #573 合入；决策：2026-07-03 #474 设计闸 grill Q6 用户拍「月度进展记录没问题」）

〔2026-09-30 后出注记（#1895，与本 ADR 同送票庭重审）：密令承办人本月执行态与进展改由 #1843 步骤 4a 整月供料 run 里的**模型选择**产生（见 [0157](0157-v2-month-waits-for-exhausted-model-call-recovery.md) 与 [0120](0120-secret-order-covert-errand-merge.md) 同日两段），代码不再按共用意愿底档把执行态折成固定增量；**本 ADR 的逐月落库、restore 无损、月报推送与垂问拉取吃同一份进展全部保留**——载体仍属**待建**（勿当现成表直接 SELECT）。密奏可汇总多路、进展为叙事容器，机械对账差额仍不以进展记录为真源。〕

护行/稽核类长差密令案卷下挂**月度进展记录**（回合、进展档、密奏一句），引擎按月触发（人物在途 transit_nudge 先例），**逐月落库而非结案一笔**——P1 判据：月中 restore，护行走到哪、对过几次账无损接续（现状 secret_orders 全靠自由文本承载，「护行」在 *.py 零命中，restore 后只剩一段字=实测 P1 漏洞）。月报**推送**（密奏进殿/邸报侧条目）与 #463 垂问**拉取**（王承恩代有司查访即答）=两条呈现管道吃同一份进展数据，不建两套。称病告假掩护不建新结构（知情圈＋叙事装得下，0037 不预建）。#467「先核 schema 装不装得下」的核查结论就此落：secret_orders 现表（扁平文本＋tags）装不下→护行子结构按本条＋0053（参与人/委派人）＋0054（关联槽）补；排除名单真源仍归 #489（native blocked-by 已建）。机械对账差额**不以进展记录为真源**——逐月逐路落**被护案卷侧对账记录**（0054 逐路原则，S12 own；有/无护行同一存储），进展记录为叙事容器、密奏可汇总多路（一令护三路时三路机械差额各自可查、进展条目仍每月一条——cmr R11 划界）。
