# 人事档案 applier 契约（C1）

Status: proposed（待评审；实现等 PR #90 合入 + M0 收口）

人物状态的写路径现状：35 个写点散在 4 文件，≥5 个高危「仅 DB」点（db.py:1604/1609/1653、issues.py:707/1359、web_app.py:2331），DB `characters` / 内存 `content.characters` / registry Agent 三面各写各的。实证灾害：毛文龙 dead 仍挂官位（#12）、客氏出宫 status 仍 active（#11）、袁崇焕 office 文本「(在途)」与 location 空串与密令叙事三处矛盾（#86）、钱龙锡 office=「前礼部尚书,罢居松江」而 status=active（状态挤在名分文本里的同款病）、动作闸门 PR 五轮评审反复抓漏同步。

本 ADR 是 **ADR 0003（单 key + 显式动作意图）的实现契约**，并作为 **ADR 0008（C2 落库拒收契约与事务边界）的第一块旗舰 adapter**。范围拍板记录：拒绝 1–2 天快速补丁路线（治 90% 症状但 bug 类不死），深做单一入口，该类灭绝（2026-06-11）。

## 决定 1：动作枚举七个，按级联差异分立

`人物变更` 每项必带 `动作` ∈ **{任命, 罢黜, 调任, 处置, 易主, 册封, 行止}**。

- 分立判据=**级联不同**：任命（绑名分+顶替派生+可触发起复/昭雪派生）/ 罢黜（清名分+贬义+派系连动）/ 调任（旧解绑+新绑定，**含降职**——左迁贬谪级联同平调，贬义归派系层）/ 处置（status 迁移族：下狱/流放/致仕/放归/赐死/起复/昭雪/夺情，原「存殁」更名——该词装不下下狱与致仕）/ 易主（翻 power_id+换名衔）/ 册封（后宫专线）/ 行止（仅去向，见决定 5）。
- 边界判据：**有旧名分且有新名分=调任；无新名分=罢黜；从无职到有职=任命**。
- 弃案：合并任免=任命+罢黜 → 回到「靠 payload 有无 new_office 反推意图」，斩毛 bug 死因重演；第八个「降职」动作 → 级联与调任全同，违反「意图集保持小」。
- 复杂场景**不进枚举，进组合**：同一回合 `人物变更` 数组**按序执行**（顺序有语义，先放人再任命）。

## 决定 2：级联 = 原语复用 + 派生事件

所有级联分解为同一套原语：解绑名分 / 绑名分 / status 迁移 / 派系连动。**任命的级联不是特殊代码，是内部递归**：被顶替者作为**派生事件**走同一管线（→ 听用候铨，见决定 10），**继承触发项的 source（C2 Provenance）**，另带 `derived_from` 指向触发条目——来源通道与派生因果是两根轴，审计链完整。

- **派生事件执行序**：前置类派生（放归/起复/昭雪/夺情）紧贴其触发条目**之前**执行；后果类派生（顶替离任）紧贴**之后**。整体仍在数组序内。
- **派系连动的强制范围只有易主**（决定 3）；罢黜/处置（赐死重臣等）的派系反应由裁判视情产出，applier 不强制。
- 弃案：顶替者在任命级联里就地处理（现状 displaced 字符串列表）→ 同步责任散落，正是本 ADR 要灭的类。

## 决定 3：易主必填「方式」，换名衔，反噬强制配对

`易主` 必填 `方式` ∈ {主动投敌, 被俘而降, 被掳} ∪ {不明}（「不明」为 alias 翻译专用值，新路径出现= `invalid_enum` 拒收）。

- 级联：翻 power_id + 解绑本朝名分 + **绑新名衔**（payload 可选，缺省「降臣」）——人仍 active（在敌方任事），不变式 1 不破。
- **被掳而未降 ≠ 易主**：人仍是明臣，走 `处置(下狱→imprisoned, reason=陷虏)` 一类表达（洪承畴被俘到降隔了数月，两段是两个事件）。
- 派系后果天差地别（主动投敌=派系之耻），落库走本仓既有「**引擎强制配对、数值 LLM 给、代码 clamp**」族（#45/#46 同款）：易主条目必须伴随派系反噬条目方可收，治 B1（阉党 leverage 不联动）类。缺「方式」= `missing_field` 拒收。

## 决定 4：处置无回滚，出狱永远是新动作

下狱=革职拿问（清名分，明制逮问先削职）。**放出不是撤销下狱，是新组合**：官复原职=`处置(放归)`+`任命(原职)`（史实「起复」本就是新诏）；贬庶民=`处置(放归→dismissed)`；官降三级=`处置(放归)`+`任命(低阶官)`（放归后无旧职可解绑，按决定 1 边界走任命而非调任）。「戴罪视事/革职留任」不扩枚举——任命即默认可任事，风味归叙事与大臣系统线（#89）。

## 决定 5：行止与去向模型（#86 收编）

去向两态：**驻于某地 / 在途向某地**。存储 `location`（当前/最后已知 region_id，上游 c4929e4 初始化数据可参照）+ `transit_to`（非空=在途）。`行止` 覆盖启程/抵达/移驻，级联只动去向字段。

- **调任不自动产生在途**——官印和人腿是两个系统（实证：袁崇焕领旨数月未动身）。启程/抵达由裁判按叙事产出，**不做距离/ETA 计算**——「距离」（人物行程/军队移动/政令时滞）是独立大阶段，占位 #93。
- 弃案 B（去向只当调任参数）：被标本证伪——纯移动事件无家可归；弃案 C（去向另开通道）：亲手复活 C1 要消灭的多路径病。
- 第七动作不违反「意图集保持小」：判据从来是级联差异，行止的级联与谁都不同且无法由组合表达。

## 决定 6：三面同步——DB 真源，受影响集从 applied 推导

applier 在 C2 事务内写 DB（单一真源），**commit 成功后**同步内存 `content.characters`（失败走 PR1 既有 `atomic + reload_state_from_db` 兜底，不发明新机制）。

- **与 C2 签名零摩擦**：adapter 返回值就是冻结的 `SectionResult{applied, rejected}`——**派生事件全部作为 applied 条目落**（带 derived_from），「受影响人物集」由 helper 从 applied 推导，不改签名。契约义务表述为：**所有发生写入的人物（含派生）必须出现在 applied 中**，调用方据此刷新。
- Agent 刷新归调用方——对话路径即刻刷（v0.7.1.0 模式），结算路径下月重建。依赖方向单向：session → applier **绝不反向**（`_commit_office_action` 的 lazy import 分层倒置在契约层判死，C3 搬家时清除）。注：C2 `ApplyContext` 已注入 registry，adapter 内顺手刷属实现自由度，非契约义务。
- 弃案 A（applier 全包三面）：db 层 import session=分层倒置；弃案 C（DB-only+失效标记）：月内对话脏读窗口正中靶心。

## 决定 7：写路径全收口 + 围栏

月末 delta / 对话闸门 / 国策结案效果 / web 直写 / 杂项散点**全部过单一入口**；只豁免开局 seed 与旧档迁移（豁免路径不产 RejectedItem，无需扩 Provenance 枚举，与 PR2 零协调）。来源映射：闸门动作=`player_decree`、结案效果=`system_simulation`、月末 delta=按来源灌注。

**围栏**：静态扫描（applier 模块之外对 `characters` 的 SQL 直写 / `content.characters` 字段直改即红，allowlist=applier 本体与豁免路径）为 best-effort 第一道，**契约测试为互补**（每条写路径的端到端断言）。深模块靠围栏不靠自觉：否则第 36 个写点明年照样长出来。

## 决定 8：拒收语义——全拒收无 clamp + 状态机两档制

人物操作是分类型，**全拒收无 clamp**（唯一例外：决定 3 的派系反噬数值走 clamp 族）。类别词表 = C2 的 {hallucinated_id, invalid_enum, missing_ref} + **{invalid_transition, missing_field}**。

**状态机两档制**（防弱模型把「狱中拜将」玩死）：

- **档一·可推导前置 → 自动补全为派生事件**。判据：声明意图对前置状态**有且只有一种合法解读**。`任命(imprisoned)` → 派生 `处置(放归)`；`任命(retired/offstage)` → 派生 `处置(起复)`；`任命(dismissed·获罪)` → 派生 `处置(昭雪)`；`任命(丁忧)` → 派生 `处置(夺情)`（见决定 10 的起复阶梯——派生本身落库，政治后果裁判照例发挥）。弱模型说一句，代码落两条，derived_from 可审计——**说全义务从 LLM 移给代码**，P1 更满足。与 ADR 0003 反对的「字段袋反推意图」方向相反：意图是声明的，推导的是其合法前置如何成立。
- **档二·无解读/多解读 → 响亮拒收**（`invalid_transition`）：任命死人（幻觉或重名，必须响）/ 放归未押者（状态已漂，正该响）/ 行止囚犯。

人物必须已存在：名字不在 `characters` → `hallucinated_id`（sim 幻觉人事正面围堵）。后宫候选创建沿现状；「立传」（新人物入场）不在本契约，需要时另案。

## 决定 9：status 七值枚举 + 两条不变式 + 消费者纪律

**不加新值**，钉死现有七值（models.py:76）。**office 字段语义钉死为「当前名分」**（职官/位号/功名/外臣名衔/差遣——实档佐证：史可法「诸生」、皇太极「后金汗」、刘鸿训「册封朝鲜使归途」，active 者名分全员非空）：

`active` 在事（含在朝任职、听用候铨、外臣在其位）/ `offstage` 居家（致仕外的赋闲、出宫+reason、自请归里）/ `dismissed` 获罪罢斥（削籍闲住，起用须昭雪）/ `imprisoned` 在押（含陷虏 reason）/ `exiled` 流放 / `retired` 致仕 / `dead` 殁。

- **不变式 1**：`office`（名分）非空 ⟺ `status=active`，由原语保证，围栏断言（#11/#12/钱龙锡 = 该不变式三个方向的违例）。
- **不变式 2′**：`dead` 无 status 出边（不复活）；**不动 status 的操作不受此限**——追谥/追赠只动 metrics/派系/叙事，不进本管线；荣衔结构化等有消费者再说。
- **消费者纪律**：无消费者的字段不准进 schema——字段跟读取端同 PR 闭环进（`location` 空置 26 回合酿成 #86 = 本仓自产反例）。
- 实现期数据清洗：扫 office 字符串里的状态词（「前」「罢居」「在途」等）归位到 status/location；`_STATUS_CN` 补 offstage；现存 offstage 人物语义核对。

## 决定 10：离任来历、人才池与起复阶梯

「不在任上」不是一个状态，是一张谱系；「启用被错误排挤的有才之士」是核心玩趣，机制必须让池子**可发现、有来历、起用有政治分量**。

- **被顶替（无过错）→ 听用候铨**：active + 名分「听用候铨」（office_type `待铨`，实档现成约定）。人留在可用池，再任命零摩擦、无派生。
- **`status_reason` 半结构化**：新增机读 `reason_code` ∈ {被顶替, 获罪削籍, 致仕, 丁忧, 自请, 出宫, 陷虏, …}（自由文本照旧并存）。读者有二：人才池视图 + 起复派生逻辑（决定 8 档一按 reason_code 选派生）。
- **起复阶梯**（全部由两档状态机推导，零新动作）：候铨→直接任命；致仕/赋闲→派生 `起复`（温和）；**获罪削籍→派生 `昭雪`**（翻案=政治事件，裁判照例产派系风暴，昭雪本身落库——你平反过谁，史官记得）；丁忧→派生 `夺情`（清流哗然）。
- **人才池视图 = 读取端**：`(active+待铨) ∪ (offstage/retired/dismissed 在世者)` 带 reason_code，接进盘面 TSV——裁判与玩家都看得见「某公，因忤逆案削籍，居家」。此视图同时就是 reason_code 与 transit_to 的消费者（消费者纪律闭环）。

## 决定 11：旧 key 退场

**总则（2026-06-11 拍）：旧有/上游机制能用不是坏事，但若成为改进的绊脚石，果断踢开——不为将就吞技术债。** alias 的存在理由只有「重放正确性」（ADR 0008 ready=1 重试真源 + 历史 delta 文件），不是对旧 key 的敬意；哪天碍事，一次性迁移脚本洗旧数据 + 删 alias，不背永久房租。新管线设计永远不为旧 key 语义弯腰。

- 保守固定翻译住 sanitize 层（`TOP_LEVEL_ALIASES`）：office_changes→任命、character_status_changes→处置、character_power_changes→易主(方式=不明)、appointments→册封。
- alias 保留但**不写文档**：DELTA_SCHEMA 重写后只记载 `人物变更`；旧 key 永不获得新能力（调任/行止/方式/reason_code 仅新 key），自然枯死。
- 迁移打包进实现 PR 不分阶段（新旧并存的中间态是 #13 温床）：applier adapter + 4 个 score_extractor prompt + 产 delta 手册 + DELTA_SCHEMA 重写 + 围栏/契约测试一次带齐。

## Consequences

- `人物变更` 成为人物写路径唯一文档化入口；DELTA_SCHEMA 人物条目整段重写；CONTEXT.md 收词：人物变更/动作/处置/行止/在途/听用候铨/昭雪/派生事件。
- **读取端同 PR 闭环**（消费者纪律）：location/transit_to 与人才池视图（含 reason_code）接进 `build_simulator_context` 盘面 TSV。
- ADR 0003 加一行指针「实现契约见本 ADR」；其「最终枚举待实现时定」由决定 1 兑现。
- Issue 簿记：#13=实现载体（维持）；#86 被收编；#11 答案=S9；#21（HITL 状态门）排本契约落地之后；#23 不变式⑤进测试集；与 PR2（#91）零耦合。
- 测试集骨架 = 验收场景 S1–S13 + 七动作级联各一 + 两条不变式 + 围栏 + alias 翻译。
- schema 增项仅二：`transit_to`、`reason_code`——两者读取端均在本 PR 内闭环。

契约先行（本文档）；实现等 PR #90 合入 + M0 收口，作为 C2 契约的第一块旗舰 adapter 落地，顺带 C3 的 `_commit_office_action` 搬家。
