# 0053: 参与人=可追加名单——机械三档+职分文字+委派人，主办可多人，深网归关系层

Status: Proposed（决策：2026-07-03 #474 设计闸 grill 用户拍，北极星实录校正「主办一定单一吗」）

案卷参与人=可追加名单，每条 **(人物 id, 机械档∈{主办,协办,知情}, 职分文字, 委派人 id·可空)**（「人物 id/委派人 id」=人物主键引用——现库 characters 以 name 为主键，字段类型循库实际主键、S2 落定，cmr R9 防 INTEGER 误设）。**主办可多人**（北极星实证：倪元璐＋黄道周合力试点清丈畿辅）；协办含跨衙门接应（杨嗣昌「户部接应钱粮、账目盯着」）与大臣自遣之人；知情只喂见闻派生（参与即知，#485/#489），不进追责链。**委派人**=连坐与责任上溯的机械依据（徐光启「门生听调」所点学生、毕自严遣门生张缙彦持密令押解——所遣之人办砸，全权者背锅；走样判定据此区分主办自砸与所遣人砸）。名单可追加：皇帝未点名而大臣自行拉人的，月末推演出场时由 extractor 追加、委派人填该大臣（P1 当回合更新）。「门生听调」类**授权本身**不长在案卷上——走 #513 interim（grant_skill）/#460 授权槽既有口径。树不做：师徒/门生故吏/座主同年网归人物关系层（#479/#89），案卷只记本案角色，引擎判定时拿人物 id 去关系层查（防双真源、防快照腐化）；机械三档管账、职分文字管戏（「监军」「参赞机务」，LLM 读、引擎不解析）。#474 body 的经手/知情人名单字段义务由本结构承接；密令排除名单真源仍归 #489（native blocked-by 已建），不在通用名单重建。
