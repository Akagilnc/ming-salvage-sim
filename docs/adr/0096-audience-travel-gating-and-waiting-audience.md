# 0096: 召对入口 travel-gating 与候见制

Status: Proposed（2026-07-07 #475 设计闸 grill Q3 用户拍 A1B1、Q4 拍清词；**显式推翻 2026-06-15「接触距离 gating 暂不做」拍板**〔#93 评论 4705580008/4705622174〕）

推翻理由：原拍板的底层关切是「实际距离模拟收益小代价大」；北极星把「远近之别」演成戏眼（#93 2026-07-01 评论已要求升级为召对入口实际 gating 依赖），0094/0095 把代价降到内容级——收益与代价两侧同时反转，原拍板的权衡不再成立。闸形态：**在京**（location＝京）宣入、即时开殿（现状不变）；**场外**传召→行止(启程)＋0095 倒数在途、**本回合开不成召对**→**抵京＝候旨召见**：候见入账＋邸报/王承恩递话报到，**皇帝哪月宣入哪月开殿**（候见制而非顶出制——召对发起权是皇帝主权，且防同月多人抵京自动顶出塞爆回合）；pending-arrival 场景态归 #470 状态机（#497 接缝③预留位）。**起复传召＝玩家一个动作、机制两段账**：起复明文当月生效〔官印〕、启程在途照 0095〔人腿〕——不逼皇帝拆两道旨。**在途不可改道**（剩余距离是标量、引擎无中途定位；改道/召回归 #93）。书信/密疏通道照 0011 三通道保留——闸只管殿上召对，皇帝与在途者密疏往来照旧。**叙事用词废「飞鸽传书」**（信鸽单向归巢、带玺文书驮不动伪造不起——国家通信从来跑驿传，史实穿帮点），一律「密疏/专差/驰递」，prompt 按正向表述落（「书信往来以密疏专差行之」）。
