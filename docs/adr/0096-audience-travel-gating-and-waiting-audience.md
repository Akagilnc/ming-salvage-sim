# 0096: 召对入口 travel-gating 与候见制

Status: Proposed（2026-07-07 #475 设计闸 grill Q3 用户拍 A1B1、Q4 拍清词；**显式推翻 2026-06-15「接触距离 gating 暂不做」拍板**〔#93 评论 4705580008/4705622174〕）

推翻理由：原拍板的底层关切是「实际距离模拟收益小代价大」；北极星把「远近之别」演成戏眼（#93 2026-07-01 评论已要求升级为召对入口实际 gating 依赖），0094/0095 把代价降到内容级——收益与代价两侧同时反转，原拍板的权衡不再成立。（推翻面仅「在途时间/距离 gating 不做」那半——location 层接触闸方向 0011 决定 8 同日已拍，本闸不是从零开闸，而是把它落成机制、加上时间维，兑现 FF-4 defer 的「召对 location 闸」切片。）闸形态：**在京**（「在京」口径循 0011 决定 8：location＝'beizhili'〔京师/北直隶同 region_id〕；**空 location 视同在京，fail-open**——开局种子多数朝臣无 location、建档写空串，fail-closed 会把新档殿门锁死，宁可放行不可锁殿，在途拦截另走 transit_to 不受此影响）宣入、即时开殿（现状不变）；**闸启用前提（seed 数据面，归 gate 切片验收）**：开局种子补齐在朝大臣 location＝'beizhili'、点名场外者补真实所在省；**场外**传召→行止(启程)＋0095 倒数在途、**本回合开不成召对**→**抵京＝候旨召见**：候见入账＋邸报/王承恩递话报到，**皇帝哪月宣入哪月开殿**（候见制而非顶出制——召对发起权是皇帝主权，且防同月多人抵京自动顶出塞爆回合）；pending-arrival 场景态归 #470 状态机（#497 接缝③预留位——该接缝原以 2026-06-15 拍板为前提写「M11 不实现 travel-gating」，前提随本 ADR 推翻，预留位〔「传召已发、人在途」账＋人不在场名单＋态可后加〕由本闸激活；#497 侧回注随闸收敛落）。**起复传召＝玩家一个动作、机制两段账**：起复明文当月生效〔官印〕、启程在途照 0095〔人腿〕——不逼皇帝拆两道旨。**在途不可改道**（剩余距离是标量、引擎无中途定位；改道/召回归 #93）。书信/密疏往来照 0011 决定 8「场外 actor 接触模型」保留（召对之外的旨意中介/密疏通道不断）——闸只管殿上召对，皇帝与在途者密疏往来照旧。**传召此刻已在途者**：不改道不叠账（「在途不可改道」的推论）——旨意照常记档，判官以「俟抵某地后奉诏赴京」承旨；其抵达原目的当月起，由未结传召记档引导判官续启新程赴京（照 0095 常规倒数，无需皇帝重颁）。**候见账生命周期**：**宣入开殿即消费候见账（转结）**——这是主转移，召见过的人不留在候见汇总里（同一人再候见须再次抵京入账）；未宣入者不设上限不自动过期（人到了就是到了；散去/告病是叙事事件而非定时器），呈现走邸报人事节＋王承恩递话汇总——P4：不做候见名单面板/按钮。**候见不变式**（0009 不变式 3 同款设计语言）：候见 ⟹ `status=active` 且在京（location 口径同上）——迁出 active（卒/下狱/罢黜）或再奉旨离京（新行止启程）者自动出候见账，不留幽灵候见。**叙事用词废「飞鸽传书」**（信鸽单向归巢、带玺文书驮不动伪造不起——国家通信从来跑驿传，史实穿帮点），一律「密疏/专差/驰递」，prompt 按正向表述落（「书信往来以密疏专差行之」）。
