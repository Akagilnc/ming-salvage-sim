# 财政 cutover hub：国库入账口径、京运补分层、中央漏损与退役 calc_province_fiscal 的并轨边界

## Context

#261 是 cutover epic（#258）的 keystone（第 4 个也是最后一个 grill 点）——让省级 settle 基座真正驱动国库、退役旧 `calc_province_fiscal`。[ADR 0019](0019-fiscal-cutover-all-province-seed-hub-split.md) 已把「hub 本身的拆法」显式留作独立设计、本 ADR 展开。本 ADR 钉死：退役旧路径后国库的省税收入怎么形成、京运补怎么发、中央层漏损怎么建、cutover flip 怎么单向切。**只定设计决策，确切键名 / schema / 管线落点 / flag 机制留 `/tdd`。**

## 决定

1. **京运补分层（D1）。** 京运补（朝廷按史实年例从国库拨给边镇的军饷）= **#261 确定性史实年例基线 + #260 玩家拨饷偏移**，与 [ADR 0020](0020-fiscal-levy-effect-channel-event-driven.md) 已立的「饷率通道基线 + #260 offset」同构。使 #261 在未定型的 #260/#150 缺席下能独立闭环（边镇有史实注入、不空转死亡螺旋），又给皇帝拨饷干预留叠加口（守「皇帝只经下旨影响世界」铁律）。

2. **盐税 / 商税走中央旁路（D2）。** 旧 `calc_province_fiscal` 的国库收入含「田赋 + 辽饷 + 盐税 + 商税」四项，而省级基座只建模田赋 + 三饷（#70 明文不收盐 / 商）。退役旧路径会让国库凭空掉盐 / 商两块，违 #261 自标的「不跳口径」。**决定：盐 / 商税不进 settle 块，走独立中央旁路、与 Σ起运并轨入国库；cutover 当下冻结为史实定额线**。随局势波动的盐 / 商玩法 defer 为后续单独工作项（类比 #259 的「先冻结、波动后补」）。

3. **国库省税入账口径 + 跨省守恒（D5，纠正）。** hub 守恒不是「钱不漏」，而是 **全系统（含漏损 sink 账户）钱不凭空增减**——漏掉的钱进可追踪的 C_ sink、不静默蒸发。各省「起运到京」已是扣净省级四段漏损（漂没 / 截留 / 中饱 / eff 损耗，均在 settle 块内由 G1–G22 oracle 守住）后的净额，故：
   - **inbound 不变式**：`Σ各省起运到京 == 国库省税入账 + 太仓亏空`
   - **outbound 不变式**：`国库京运补拨出 == Σ各省实收京运补(拨付gross) + 京运转运损耗`
   立一条跨省 hub 守恒断言（沿用基座那套**独立 oracle** 方法学，只从 tick 输入重算、绝不读结算中间量），防 hub 层静默丢钱 / 重复计——这也是退役旧路径后国库唯一省税来源的机械防线。

4. **中央层漏损：两段、不对称（D5b + b 扩展）。** 省级四段漏损齐全，但中央太仓本身的漏损此前无建模。决定在中央层（区别于省级）建**两段独立漏损**，均**不对称**（挪用 / 克扣部分可「追赃」回收 = 皇帝破局杠杆、动作走 #260；纯亏空 / 运损部分为不可回收 sink）：
   - **太仓亏空（inbound）**：银到京后中央太仓自身的亏空 / 挪用——发生在「省级在途漂没」之后。
   - **京运转运损耗（outbound）**：国库拨京运补 → 边镇**途中**的克扣 / 运损——发生在「边镇收到拨付gross」**之前**，与省级已建的「拨付gross → 中饱」（到镇后克扣）是不同阶段、不双算。
   四段漏损前后相接、各自独立：省级在途漂没 → 中央太仓亏空 → 中央京运转运损耗 → 省级到镇后中饱。率基用**中央级 corruption 参数**（seed 定、史实校准），**暂不挂未设计的大臣系统（#89）**；「户部官员个人贪腐 → 太仓漏多少」的挂法留作 #89 上线后的耦合。

4b. **漏损可压低、手段开放（贯通四段、合 ADR 0007 上行软判）。** 每段漏损的「人为分量」（截留 / 中饱 / 克扣 / 挪用）率**可被开放手段压低**——#261 只把这些率建成可调（留 hook）、保证「可压低」，**绝不规定手段**（派锦衣卫护送 / 清丈 / 追赃 / 换官 / 监军… = #260 + LLM 软判 + 玩家自寻）；「自然分量」（漂没 / 运损 / eff 损耗）为**结构地板、不可清零**（survival 压力存活）。省级此通道已具（ADR 0007「上行交 LLM 软判」），#261 把同原则延伸到中央两段新漏损。

5. **cutover flip 失败分层（D6）。** shadow 期是「跳过坏省、不炸结算」（不驱动国库故无所谓）；flip 后基座真驱动国库，保护取消。失败分两类、粒度不同：
   - 省「被义军夺 / 失地」= 剧情正常态，按 ADR 0019 动态成员谓词**静默出列**、不算失败。
   - 省 settle「守恒破 / 数据坏」= 真 bug / 灾难，**月级 SettlementAbort 响亮中止**（守 [ADR 0008](../SETTLEMENT_FLOW.md) 的「shape 垃圾响亮中止、绝不让坏账静默漏进国库」）。

6. **cutover flip 是经双轨对账验证的单向门（D7）。** 不一次性硬删旧引擎；**cutover 当月新旧两路并跑、断言国库总数一致（isclose）才正式 flip 切 fail-loud**；旧 `calc_province_fiscal` 验证收敛后**另起 commit 删**（守「评审轮 = 独立 commit」过程史）。flip 单向不可逆。ADR 0019 已排除逐省渐进 cutover。

## Consequences / 落位边界

- **单一预算源（D3，实现层）**：国库收入仍走「唯一预算源」契约，只把内部税收来源从 `calc_province_fiscal` 换成「Σ各省起运 + 盐商旁路 − 中央漏损」；落账 / 皇帝看的预算表 / 存档摘要三处读同一处、不各自重算——守 **P4 呈现层**：cutover 后国库收入明细仍以定性叙事呈现、不跳口径、不暴露裸数值。
- **京运补时序（D4，实现层）**：跨省汇总放「全省 settle 跑完之后」的全局聚合步；京运补当月拨给边镇**当月生效**（像 ADR 0020 §6 把饷率结局前移那样在 settle 前置），不留 off-by-one。
- **#265 转 native blocked_by（D8）**：#265（收复省补 settle 基座）转成 #261 的 native `blocked_by`——否则退役旧引擎后被收复的省拿不到 settle 基座、进不去动态成员谓词、财政瘫痪。#265 具体修法（on_restore hook 补建 vs 模板预配）留 #265 实现期定。
- **实现留 `/tdd`**：确切键名 / schema / 管线落步 / flag 存储机制 / oracle 断言写法本 ADR 不展开。
