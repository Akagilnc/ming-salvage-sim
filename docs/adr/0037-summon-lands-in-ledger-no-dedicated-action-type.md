# 皇帝发起召对：入账即入机制，不另立 summon 动作类型

Status: Proposed（2026-07-02 #470 grill 结晶，了结 #468 分叉；评审闸在 to-prd 之后）

## 决定

发起召对（宣入/传召/越次点名）是玩家口令，按 ADR 0035 **确定性落账**：一条账写清谁被召、怎么召的。下游全部读账——关系账（方向 10）读「越次擢用」、见闻派生（#459）让在场者知道、restore 知道这夜怎么开的。**不新增独立 summon 动作类型/表。**未来出现带新机械需求的发起变体（如**密召**：要瞒人、要见闻排除）时再评估立专门机制，不预建（用户 2026-07-02：目前感觉不到单独立的好处）。

## 为什么

单一真源：#468 的两个诉求（落库供消费、restore 知道是否越次）被账本天然满足，零新增机制。消费方（关系/声望）本来就是 LLM 软判，读日记式账目正合适。

## 否决的备选（防日后重议）

- **纯叙事不落记录**：违 P1 与「restore 后知道是不是越次发起」。
- **现在预建 summon 动作表**：与账本双真源、两处对齐；为还没设计的消费方预付结构，违背「开放不设死」（ADR 0035）。
