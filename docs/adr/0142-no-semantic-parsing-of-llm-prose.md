# 0142 LLM 自由文本零解析：结构化事实只走显式结构化契约

Status: Accepted（决策：2026-07-18 owner 两案连判——P4 中文数词 regex 族=refute/over_defense「引擎不该管 LLM 的文字细节」；潜台词关键词 parser=地雷「正常措辞一变就静默误判，测试还把错误的关键词解释钉成正确行为」）

引擎不得用关键词、正则或规则从 LLM 的**自由散文**（回话、邸报叙事、旁白等）抠取语义或结构化事实。结构化事实进出引擎只走**显式结构化契约通道**：tool call / `pending_action` / extractor 按 schema 交付的 delta JSON——那是 LLM 按契约产结构，不是引擎猜散文。方向相反的分工同样成立：**LLM 演绎结构化事实**（读心/呈现层拿结构化底账产叙事）是正道，引擎当搬运工，理解与措辞归 LLM。推论：此类 LLM 叙事的输出对引擎同样零解析零管辖，需要结构化后果时从调用的结构化输入侧取，不从文字输出侧反推。

弃案：继续扩词表/regex 适配措辞变体（无界打地鼠，14 例才能证明的修法=过拟合；两条独立评审线一日内同判死）；给散文解析加测试护栏（测试会把错误解释钉成「正确行为」，负收益）。
