# 省级财政基座 · 第三轮外部评审(codex)

> 对象:FISCAL_PROVINCE_SUBSTRATE.md(v3,spine 两表)。codex exec,2026-06-09。原文如下。

---

结论：**v3 还不能锁 spine**。方向已经对了，但还有几处会让两个实现者写出不同引擎，尤其是“收入口径”和“欠账/拨付口径”。

**1. 两张 spine 表够不够直接写引擎？**

还差 4 个硬点：

1. **火耗是“应派”还是“实收”没拆。**  
   现在第④步直接把 `正赋应征 × 火耗率` 进 `地方截留` stock，但第⑦步才算逋赋。这样高逋赋时，没收上来的火耗也会沉淀成截留银。应拆成：
   `火耗应派` 进民负担，`火耗实收` 才进地方截留。  
   还要定：火耗实收是否跟正赋同逋赋率，还是单独 collection rate。

2. **第⑧步“实征 → 起运池 + 省内池”缺精确分配规则。**  
   是起运定额优先？省内军饷优先？两池按比例？短缺时谁先欠？有余时归哪里？  
   这里必须变成付款 waterfall 表：`预算头 / due_formula / priority / paid / arrears_stock / repay_priority`。

3. **中央拨付的 gross/net 口径错位。**  
   第⑩说中央拨付到地方会被中饱吃掉；第⑫却用“中央拨付到手”从国库扣。国库应扣 **gross 拨付额**，地方只收到 **net 到手额**；中饱差额是损失/赃银/sink，不能让腐败反而减少中央账面支出。

4. **action/clamp schema 还不是机器 schema。**  
   `effect_vector` 现在是人读短语，不是 canonical field path。`requested_delta / applied_delta` 也像单值，但一个 action 会改多个字段。建议至少定成：
   `field_path -> {op, amount, unit, duration_months}`。  
   另外临时效果、持续支出、一次性支出要进 schema，否则 `专员押解`、`养廉银`、`赈灾` 三类会被写成三种不同生命周期。

**2. r2 六条真闭了吗？**

- **单位 /12：基本闭了。** 亩额改名为“税额”很好。剩余小口是 action 里的“银”要标一次性/每月。
- **waterfall 先分后损：概念闭了，机械没闭。** 漂没只吃起运池是对的，但第⑧分池规则和第⑫ gross/net 会导致账不一致。
- **火耗落账 stock：只闭了一半。** 有 `地方截留` 对象了，但现在落的是应派火耗，不是实收火耗。
- **欠账 stock 累进/偿还：没真闭。** 累进写了；偿还仍是“有余款+旨意→偿还”，而且待精验里自己还列了“欠账偿还细则”。需要各 stock 的偿还优先级、是否可蠲免、是否可追缴旧欠。
- **reason_code 枚举：半闭。** 枚举有了，但 schema 说 clamp 必返其一，表里又有 `—`。要么加 `NONE/APPLIED/AI_DILEMMA`，要么规定非 clamp action 不走 clamp_return。多约束同时触发时也要定 primary reason 选择规则，或改 `reason_codes[]`。
- **漂没/中饱拆：位置闭了，账本口径还差一步。** 二者对象已拆清，但中饱差额去哪、中央扣 gross 还是 net 必须锁。

**3. 会不会逼回来改架构？**

有一个隐藏 spine 问题：**三本账必须正式分层**。

- 官方月流：正赋、三饷、起运、省内支出、中央拨付。
- 欠账 stock：军饷欠、宗禄欠、官俸欠、民欠旧赋。
- 灰账/损耗：地方截留、漂没损失、中饱损失/赃银。

现在这些概念散在表里，但还没成为引擎不可绕开的 ledger shape。补上这个，不需要推翻 v3；不补，写到结算和追赃时一定返工。

所以我现在的判定是：**spine 方向可定，但还不可锁；补火耗实收、付款 waterfall、gross/net 拨付、typed clamp schema 后，可以开写引擎。**
