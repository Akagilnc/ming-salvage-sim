# r5 · codex(v5)

结论：**v5 的 spine 方向可锁，但还差最后一页“执行归一化表”才到两个实现者必然同 tick。** 这不是再改架构，是把几个现金入口/出口和 modifier 顺序钉死。补完后我会说：**spine 可锁，可开写引擎**。

**1. 还差哪一步**

差的是明确 tick transition contract：

- `拨付gross[t,省]` 是省级 tick 的外部输入，不能由省级算；全局国库只在所有省跑完后更新 hub stock。
- action 银成本从哪里扣、什么时候扣，要入 invariant。现在 ⓪ resolve 了，但钱没有进账本公式。
- `清欠`、`C→A追赃` 不能写成“实征↑”就完事，必须规定进入哪个现金池。
- duration modifier 栈要规定同字段 `set/scale/delta` 的应用顺序、过期时点、同 tick 多 action 排序。
- 多 effect 原子性要说清：只有资金不足同比缩，还是任一 effect 被 clamp 后整组也同比缩。

最小补丁是一条总公式：

`省内可支 = 省内池 + 上月省库库银 + 拨付net + 清欠入库 + 追赃入库 - action银成本`

然后再进 ⑪ 付款、偿还、结转。这样账本闭合。

**2. r4 项是否真闭账**

- **省库 stock：基本闭账。** 已经解决跨期结余和平准。只差把 action 成本、清欠入库、追赃入库纳入省库现金流。
- **国库全局边界：概念闭账。** “国库不是省级 tick 一步”这条是对的。小缺口是 `拨付gross` 必须声明为全局预先给省级的输入，否则 ⑩ 和 ⑫ 会被人写成循环依赖。
- **民欠语义：语义 bug 已闭，但入账口径没闭。** “无官偿还民欠”正确；但“清欠→实征↑”仍危险。旧民欠追回应是 `B.民欠旧赋↓ + A.清欠入库↑`，不该污染本月 `应征 = 实征 + 民欠新增`。
- **多 effect 原子性：只闭了资金不足场景。** “付不起同比缩、不白嫖”闭了；非资金 clamp 是否拖累整组，还没锁。
- **duration modifier 栈：架构闭了，执行细节未闭。** 只读基线+modifier 栈是正确方案；还需钉死 modifier 合成顺序。
- **C 可追回：分类闭账，回流路径未闭。** `地方截留/中饱` 可追回、`漂没` sink 这条对；但 `C→A` 到省库、当前省内池、还是起运池，必须指定。建议进 `追赃入库`，作为省库可支现金，不重跑起运分池。

**3. 会不会逼回来改架构**

没有看到需要推翻 spine 的隐藏问题。大架构已经成立：省级 A/B/C + 省库 stock + 国库 hub + action modifier 栈是正确骨架。

但现在还不能严谨地盖“两个实现者同结果”的章。最后要补的不是新架构，而是**账本入口/出口归一化**。尤其是：旧 B 回收、C 回收、action 成本，三者都必须显式进同一张现金流公式。补完这页，v5 就可以锁 spine，开写 tick 引擎。
