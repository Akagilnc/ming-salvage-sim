# 游戏架构重构讨论

状态：设计讨论中，未完成详设，未授权施工。更新至 2026-09-09 本轮对话。

「V2」是本轮重新思考架构的历史称呼，不是另做一款游戏；文件名与分支保留该称呼只为延续引用。目标是重构现有游戏，不预设第二运行入口、第二套存档或两代产品并行维护。

并明确：

## 模型调用耗尽的选择

2026-09-09，Q3 以补饷、任命已记好而赈灾未处理完为例，询问留本月补好还是先进入下个月。第一种方案原文：

> 已成功的保留，只重试失败的事情，不让玩家进入一个缺着后果的下个月。

owner 先限定场景：

> 你想说的是。同样一个模型。别的成功了。这条上失败了并且重试了3次都失败？

助手确认讨论的是同一个模型下其余事项成功、单件反复失败且自动重试耗尽，并明确「3 次」不是已定次数、剧情中赈灾办砸不属于此类故障。owner 最终回答：

> 真要这种小概率事件，那就是模型调用错误。这种错误重试耗尽。可以选第一种

决定见 [0157](../adr/0157-v2-month-waits-for-exhausted-model-call-recovery.md)；不得将这次授权扩大为数据库损坏、数值核算异常等所有错误的统一政策，也不增加模型之外的剧情裁判或重试上限。

## 记忆供料保持简单

2026-09-09，Q4 曾建议完整保留原始记录、由 LLM 整理较久的经历后再供料，并以未来多年记录可能过大为理由。owner 明确否定：

因此首期不引入长期记忆整理、摘要或因假设容量压力而预建的供料优化；后续是否需要改进，以实际出现的上下文影响为前提。此取舍并入 [0155](../adr/0155-v2-single-scene-llm-with-complete-perspectives.md)，不是授权删除现有实现中的历史摘要功能，也不改变角色可见范围。

owner 随后澄清「提供」与「读取」的区别（保留原字）：

> 因为你提供在哪里。不代码llm要马上读啊。llm就像你现在工作一样。你会马上把仓库的所有东西都读一次嘛？但是想读的时候自己可以去读

所以材料备齐只表示在其可读范围内可用，LLM 想读时自行读取；不要求开场把全部原文载入上下文。此前助手在 ADR 0155 写入「不采用按需检索往返」是错误转述，现已删除；这是对原意的纠正，不是 owner 推翻先前决定。此处允许自主取阅，不据此预设搜索服务、向量库或某种文件/工具接口，仍不让角色越过中间层直接读取全局 DB 实况。

## 任职交接的基本语义

2026-09-09，Q5 以毕自严接任户部为例，提出「公事档案随职位可查，私人经历与秘密留在人物身上」；旧账册可能是假账，不是引擎真账，继任者不自动获得前任受贿、串通或私下听过密令的记忆。原任透露或继任者查出内情，仍由 LLM 演出、记录。

owner 答：

> 这是理所当然的

将其作为既有角色见闻与人物/职位区分的基本语义，补入 CONTEXT「公事档案（V2）」，不另建 ADR，也不据此扩建一套交接流程或调查系统。

owner 回答（保留原字，按问答上下文指第一种）：

决定并入 [0154](../adr/0154-v2-affairs-unify-story-and-isolate-progress.md)。统一的是记录入口，不是让中间层接管剧情判断；不规定结构化格式，也不要求将原话中的每个意思都变成字段。

## 语义转译仍归 LLM

2026-09-09，owner 针对助手的「也不增加另一个 LLM 来翻译」明确质疑：

> 啥意思，不用llm你怎么翻译？你别告诉我你又想用代码来解析llm的意图

不能把选择统一入口理解为授权代码猜自然语言意图，或禁止中间层使用转译 LLM。语义理解和转译仍由 LLM 承担，代码接明确变更后分派、核算、存储；转译不能擅自重判推演结果。该责任边界修正于 0153，0154 引用它；「推演者不操心底层」与「中间层内部存在 LLM」并不冲突，具体由哪次调用承担尚未定。
