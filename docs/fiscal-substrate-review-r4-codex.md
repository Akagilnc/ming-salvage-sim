# 省级财政基座 · 第四轮评审 · codex(v4)

> codex exec,2026-06-09。判定:spine 可锁,只差执行契约附录。原文:

---

结论：**spine 可锁，可开写引擎**。没有看到会逼你回去重改架构的隐藏问题。  
但如果标准是「两个实现者不沟通也写出同一个 tick 结果」，v4 还差几条**执行契约**，不是架构重做。

**1. 现在还会分歧的地方**

会分歧的主要不是三本账，而是 tick 细节：

1. **action 生效时点**  
   action 是在月结 ① 前生效，还是 ⑥ 逋赋率前、⑧ waterfall 前、或下月生效？必须固定。

2. **duration_months 语义仍有歧义**  
   `0=一次性`清楚；但 `1=持续/月` 和 `N=临时N月`冲突。建议改成：  
   `duration_months: 0` 一次性；`N>0` 覆盖本月起 N 个 tick；`null/ongoing` 才是持续月额。

3. **起运定额不足时怎么处理**  
   需要写死：`起运池=min(实征, 起运定额)`，`省内池=max(0, 实征-起运池)`。中央侧短解是否进独立 stock，不应让省内池变负。

4. **本月缺口进入 B 的时点**  
   现在 ⑧ 说短缺累 B，⑪ 又说先抵本月缺口。实现者可能一个先入 B 再冲销，一个先挂 pending 再月底入 B。最终也许相同，但中间事件不同。建议设 `current_due_gap` 临时池，tick 结束后净额入 B。

5. **火耗欠归属**  
   你写“火耗欠随逋赋，不单列，计入民侧未收”，但 B 的 `民欠旧赋`公式目前只算正赋+三饷。这里要一刀切：  
   要么火耗欠只是民负担诊断项，不进 ledger；要么 B 民欠包含官方税欠和火耗欠两个子项。

6. **C 灰账是纯 sink 还是可追回 stock**  
   如果“清账追赃”能把赃银追回入 A，就要允许 `C.stock -> A.flow` 的 recovery 事件；如果不能，C 就声明为 audit sink。否则追赃类 action 会分歧。

7. **clamp 的事务语义**  
   多 effect action 是逐条 clamp、整体按资源比例缩放，还是任一关键 effect 不成立则整 action fail？尤其 `银-` 不足时，政策效果是否同比缩水，要写死。

**2. r3 四硬点 + 三本账是否闭账**

大体闭上了，但有几个“最后一厘米”。

- **火耗应派/实收**：核心修对了。火耗不进国库、实收进 C，这个闭账；只剩火耗欠是否进 B/诊断项要明说。
- **付款 waterfall**：方向闭了。优先级、资金池、欠账 stock 已经可实现；但起运不足、本月缺口与拨付补缺的事件顺序还要锁。
- **gross/net 拨付**：闭了。gross 是中央 A 出，net 是地方 A 入，差额进 C。建议补一句：地方可支配现金只认 net。
- **typed schema**：形状闭了，但还没完全 contract 闭合。`duration_months`、多 effect clamp、reason 优先级、派生字段是否可直接写，都要收口。
- **三本账分层**：架构闭了。A/B/C 的边界已经足够支撑引擎，不需要第四本账；只需给 C 的 recoverability 一个明确口径。

**3. 是否还有会逼回架构的隐藏问题**

没有。  
剩下的是 spec 锁口，不是 spine 返工。

我建议你把 v4 再补一个很短的“执行契约附录”：action phase、duration 语义、waterfall 短缺规则、B 入账时点、C recovery、clamp transaction 六条。补完后可以正式写：

**spine 可锁，可开写引擎。**
