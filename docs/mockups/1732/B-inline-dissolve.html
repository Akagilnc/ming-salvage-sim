能不弹就不弹：在动作原位收掉确认

核心判断：凡页面已经有一整块说明 + 按钮的（回到主菜单 / 重开 / 退出等）， 那块面板本身就是确认——再弹第二次是冗余。就地把「要做什么、后果、可否撤销」写进面板或行内条， 点一次即执行。只在没有既有说明面的动作（列表删除、召对撤回、拟诏 failed-only、alert）才展开贴身确认条。

场景：回到主菜单 · 面板已含后果说明 → 按钮直接执行，零第二次确认

B 取向要点：有面板的动作（主菜单 / 重开 / 退出）= 单次就地确认，票面 confirm 原句并入面板作后果句； 无面板的动作才长出贴身条。双重确认被结构性拆除。代价是交互形态不统一（面板 / 行内 / 页脚 / 深色菜单卡 多套）。

9+1 文案在本取向中的落点

全部使用票面原句；无 lorem。

  • 回到主菜单 → 并入既有面板，按钮直接执行
  • 重开新局 → 并入既有面板 + 手打「重开」解锁，按钮直接执行
  • 退出游戏 / 加载存档说明类 → 同形并入面板（退出文案见下）
  • 删除 N.db / 删除存档「X」→ 行内展开
  • 覆盖主进度 → 主菜单深色就地卡
  • 撤回召对 → composer 上方就地条
  • 拟诏无参 confirm → 页脚展开，补退朝语义
  • 上传失败 alert → 画面内告警条，单钮知悉

退出游戏票面原句（并入面板示范，与重开同形）：「退出整个游戏？前后端进程都会关闭，未保存的进度会丢失。」
