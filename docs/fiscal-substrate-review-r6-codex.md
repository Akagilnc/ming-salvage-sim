# r6 · codex(v6)

结论：**spine 可锁，可开写引擎**。不需要第七轮架构返工。

1. **能锁吗？**  
达到了主标准。两个不沟通的实现者，在主线 tick 上会写出同一个引擎：action 先结、成本只看上月省库、modifier 单公式、清欠/追赃只作一次性本月入库、拨付 gross 外部输入、付款偿债纯代数。  
只建议补 4 条“实现锁边界”，不是架构问题：

- `k = ΣCost == 0 ? 1 : min(1, Stock_start / ΣCost)`  
- `省库库银_post = Stock_start - k * ΣCost`，比 `max(0, Stock_start - ΣCost)`更直接。
- 明确 action 银 `amount` 是“每 tick 成本”还是“duration 内总成本/摊销成本”。
- 多个 active `set` 同时作用同一 field 时：禁止，或定义确定性优先级。
- `追赃 X / 清欠 Y` 必须 clamp 到对应 C/B stock，不得扣负。

2. **r5 公式闭账了吗？**  
闭了。总现金流闭合；action 成本断循环闭合；modifier 叠加和衰减时点闭合；C→A 追赃、B→A 清欠不重跑起运/应征，闭合；付款/偿还 waterfall 用 `min(Pool, Due)` 和余额还旧债，闭合。  
唯一需要文字精修的是把“应征”明确写成“正税应征=正赋+三饷”，避免有人把火耗未收也塞进 B。你正文已有注释说明火耗不积欠，补变量名即可。

3. **还有隐藏架构雷吗？**  
没有会逼回来改架构的隐藏问题。剩下是实现约定、边界 clamp、测试样例，不是 spine 设计。  

我的判定：**v6 的财政 spine 可锁；可以开始写 tick 引擎。**
