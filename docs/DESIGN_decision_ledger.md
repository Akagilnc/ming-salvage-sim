# 决策与状态模型 — 探针 step1 复盘的设计结论

> 这是一个 **LLM 主导的历史模拟游戏**——不退回"引擎算一切"的常规游戏那套。

## 1. 缘起:探针 step1 暴露的两类病

崇祯二年续局(context-restore 之后),玩家连续发现自己创造的东西蒸发/失真:

### 果(证据清单——只记录,不逐个手工补)
- **天雄军 / 卢象升**:玩家记忆=卢开口要 20 万/月、说练 3000、提"多给多训练"、皇帝给 **100 万/月**、许 **"大明的刀"**。DB 现状=兵额 18000(agent 臆造)、**无月饷线**、**"大明的刀"零字**、"多给多训练"机制丢失。
- **秦军 / 孙传庭**:玩家记忆=固原练秦兵、**分一千去边境**。DB=**无秦军军籍**、孙传庭仍 seed 的 `永城知县`、"分一千"全库零痕迹。
- **袁可立复职**:蒸发。
- **喜峰口诸隘**:之前拨款已报**修好**;restore 后被重新叙述成"破口又要修"(**既成事实被回退**)。
- **李若琏**:说好**下月**任锦衣卫指挥使;过半年纹丝不动,玩家问了才提(**排程决策无人执行**)。
- 太学府经费 500/月、卢象升/孙传庭调任:立项/任命只在叙事,没落库。

### 两类病
1. **蒸发 / 回退**:玩家创造的东西只活在对话语境,没成持久状态 → checkpoint 一过就没、甚至被重新叙述回退。
2. **冻结**:带未来时点 / 应自主演进的决策,没机制到期执行 → 世界停摆,全靠皇帝追问才动。

---

## 2. 因:缺的不是"少用 LLM",是缺三样

错误诊断会得出"让引擎算"——**错。** 真正缺的:

1. **持久状态**:东西活在对话、不活在存档。
2. **因子锚点**:LLM 判数值时没有依据可锚 → 飘、不一致。
3. **强制一致**:落库靠 agent 自觉 → 必漏(这局八回合实证)。

---

## 3. 最终模型

### 3.1 万物皆有状态的实体
- 实体类型:**事件、人物、军队、工事/地点(喜峰口)、机构(太学府)**。
- **状态字段就是真相**:funding、头衔、履历、loyalty、阶段、修缮度… 状态摆在 DB,扮演者只读它 → **忘不掉、读不错**。
- **实体自带钱粮**(根治太学府/天雄军坑):太学府是实体→自带月耗 500;天雄军是实体→自带军饷 100万/月。**建实体 = 钱粮一起生出来**,不存在"另记一笔月支"这个会被忘的步骤。
- **给钱方式 = 事件的一个属性**:`{一次性 | 按月, 给多久(默认:到事情办成)}`。"1/2/4 类钱"不是三类,是一个属性。
- **头衔 = 人物的一个字段**(如"大明的刀"):纯素材、不影响机制,来历在召对存档里(可在头衔挂指针指向那条对话)。不需要任何承诺/信任子系统。

### 3.2 职责划分(LLM 主导,别越界)
- **引擎只管**:① 存状态 ② 把"大因子"摆给 LLM(复用 `agents.build_simulator_context` 盘面→TSV 那个口)③ 卡一致性 ④ 按状态确定性 tick(补欠饷 / issue 惯性 / 排程到期自走)。
- **LLM 主导**:所有**数值与后果判断**——loyalty 怎么变、谁会不会降清、邸报怎么写。
- **不写死规则**:引擎本就**没有** "loyalty→降清" 公式;降清是 **LLM 判**(`character_power_changes`),哗变走**事件/issue**。保持这样,别加公式。

### 3.3 大因子框架(LLM 判断的锚,不是公式)
loyalty/信任 这类判断,引擎**surface 几个大因子**给 LLM 当锚:**欠饷状态、朝廷信任、上司关系(如袁可立↔毛文龙)**…
→ LLM 据因子 + 叙事判具体数值,**有锚不飘、又不写死**。规则写不完,只立大框架。

### 3.4 流程(邸报后置,显示=回读)
1. **我(主)产意图**:召见 / 拟旨 / 产 delta(皇帝决定了啥)。
2. **sub 负责**:核一致 → 跑结算(应用到 DB)→ **从 settled DB 生成邸报**(照原版 `season_simulator` 章法,把真实数字写得有声有色、但咬死事实)。
3. **显示 = 回读**:给玩家看的邸报,是从 DB 读回来的 → "你看到的"恒等于"库里存的",物理上不能分叉。
4. 邸报后置(先结算、后出报)**顺手修了原版 bug**:原版"邸报先写、delta 再从邸报抽",两套输出天然分叉(merged #5/#6 修的就是这);倒过来,分叉从源头消失。

### 3.5 瘦裁判(折进结算 sub,硬闸)
- 裁判**只信 DB**(乙基准:不信 agent 嘴)。它握【玩家旨意=chat_messages/拟旨】+【我的 delta】+【结算结果】。
- 只问一句:**这个决策,有没有落到对应实体的状态上?** 对不上 → **拒绝结算、报错**(硬闸:没落库就走不下去,不靠我善意)。
- 检查重点(从这局栽过的坑提炼,本质都是"实体状态有没有被决策更新"):
  - **钱**:月度 vs 一次性——判定规则写死(出现「每月/按月/岁/常设/月饷」→ 月度;否则一次性)。
  - **兵**:建军(new_armies)/ **调兵分兵**(army_delta,如"分一千去边境")。
  - **人**:任命(office_changes)/ **去职**(character_status_changes)/ 履历追加 / 头衔。
  - **召对落库**:本轮有召对叙事 → chat_messages 必须增行。
  - **既成单调**:任何 resolved/已成 → active 必须有明确"重启"旨意,否则报错。
  - **排程 flag**:提了"下月/择日"却没排程登记 → 警告。

---

## 4. 关键不变式

1. **决策即落库**:叙事是 DB 的渲染,DB 是唯一真相。
2. **显示 = 回读**:能给玩家看的,只有从 DB 读出来的。
3. **restore 无损**:只读 DB 即可重建"玩家在玩的那个游戏",不靠 agent 记忆。
4. **既成单调不回退**:resolved 的事实只能在其上前进,不得回退/重述成待办。
5. **世界有惯性、皇帝非保姆**:带未来时点 / 应自走的,排程到期自动执行并主动汇报。
6. **引擎不算判断、只摆因子 + 卡一致**:数值与后果归 LLM。

---

## 5. 查证事实(锚定,防再凭印象)

- `loyalty`(人物+军队)在引擎里**零触发**:无任何 `loyalty<X` 判定。纯状态/显示数。
- **降清/叛/归正** = LLM 经 `character_power_changes` 判(db.py:1518 "据 extractor 输出改 power_id");**哗变/兵变** = 事件/issue。**都不是 loyalty 公式触发。**
- 原版**无**忠诚自动漂移(drift/decay/inertia 全空)。人物忠诚连 delta 入口都没有;军队忠诚只能手动 army_delta 写,不派生。唯一自动财政联动是**补欠饷**(`_auto_pay_arrears_by_priority`),但补了**不自动涨忠诚/士气**。
- 原版**召对对话是真存的**:`chat_messages` 表(`append_chat_message` / web_app.py:398 "持久化在 chat_messages,启动恢复")+ `chat_turns` 可撤回(merged #10)。**我们 probe.db 这三表全 0 行**——step1 在 Claude 对话里演、没写库,自废了引擎已有的持久化。
- 上游 open PR:#9「事件多阶段推进 + 军事指令结算 + 天灾 + 收件箱」(870 行、未合并、第三方)——其 `EventPhase`(分阶段、到时自动推进)是我们"排程自走"的迷你参考;不整包拉(冲突 + 净重写债)。

---

## 6. 乙(子系统/公式)——已化掉

钱/兵/官/工事/名号/召对,全归"有状态的实体 + 字段 + 对话",**没一样需要独立的承诺/信任子系统**。
唯一残留的"信任随厚待/冷落涨跌、久冷降敌"这类**动态**,也不是公式,而是 **3.3 的大因子喂 LLM 判 + 落库**。
玩家定调:这类动态**效果导向——好才要,不好不如没有**。先不做,要做也是"加因子 + 调 prompt",不是加数据结构。

## 8. 第二条设计线:90 分体验续命(scenario)

> 缘起:玩家实测——昨天那局(session ae148299)整体 **90 分**;`context-save → clear → restore` 落到本 session 后,开头掉到 **70 分**,还冒出一堆"没记录"的 bug。线 2 = **保住 90 分的 Claude-session 沉浸式玩法,同时改下层让压缩/restore 不崩。**

### 8.1 两条线分工(2026-06-07 厘清)
- **线 1**(另一 session,已落地):agy 替 api key + 机制改动 + **web 上玩**。脱 key、durable,但 immersion 可能 ≤70(agy 中文叙事弱,大概率更"播报")。
- **线 2**(本 session,在设计):**就在 Claude 对话里像昨天那样 90 分地玩**,体验不变;下层机制要改,否则 context 一压缩就**体验塌成仪表盘 + 一堆没落库的 bug**。
- **两线共用同一持久后端**(probe.db + 场景库)——同一 backend 的两个前端(web/agy 演、Claude-session 演),共享状态 + 场景。

### 8.2 90→70 的根:restore 保状态、不保声音
- 实测对比:**90 分**(昨天,如孙传庭初次面圣"绿袍洗得发白 / 膝盖触地极稳 / 眼神直不闪不躲",有身体、世界观、政治潜台词) vs **70 分**(本 session restore 后,我演成"国库表 + issue bar 列表 + 选择题"的仪表盘)。
- checkpoint 存住了 **state**(盘面 / issue / 决策)= 事实;**没存住 voice / embodiment / 那个活着的朝堂**。有事实没手感 → 最省力就是摆仪表盘。
- 一句:**restore 保得住"发生了什么",保不住"怎么演的";而 90 分的魂,全在"怎么演"里。**

### 8.3 scenario 才是单元(不只是对白)
- 90 分**不只在对白,更在环境 / 动作 / 神态描写**。`chat_messages` 只存 role/content 的**对白**,接不住这层戏。
- 要存的是 **scenario = 整场戏(环境 + 动作 + 神态 + 对白)**,作为**一等的、可回读的持久单元**。
- **残酷 tradeoff**:产出 90 分 scenario 的形态(**自由叙述的 LLM**)正是**最不持久**的;而持久形态(引擎 / agy 大臣 = 工具问答式对白)**演不出那层舞台**。要两者兼得,只能把"演整场戏"做成**显式步骤 + 落库**。

### 8.4 核心机制:`commit_turn`(=#1,待细化)
- 每回合 = 一次 **`commit_turn(scenario, 在场人物[], delta, 是否主线节点)`**。
  - **scenario** = 我演的整场戏原文 → **一段文字三用**:① 给玩家看 ② 存场景库 ③ restore 回读重新附身。一次产出,物理上不可能分叉。
  - **delta** = 这场戏的机械后果(任命 / 拨饷 / 建军…) → 落 probe.db(走真引擎结算)。
  - **跳过 commit = 这回合不存在**(硬结构,不靠 agent 善意——这是治"演了不落库"的根)。
- **状态:#1 要想清楚再动**(scenario 存哪:probe.db 新表 / 场景文件?delta 怎么和真引擎结算接?)。#3 的回读需求已替它框了该打的标签(在场人物 / 是否主线节点)。

### 8.5 一致性裁判(=#2,缓,效果导向)
- hook / 瘦裁判:校验"scenario 里演了 X(授某职 / 给某饷),delta 里有没有对应落库",对不上 → **拦下回合**。就是 §3.5 那个裁判,落到线 2。
- **玩家定:#1 完成后看效果再决定要不要**(不好不如没有)。

### 8.6 回读模型(=#3,可先做,大半引擎已有)
- **按人物分**:每人一条 scenario 流 → 召见某人时回读**他这条流的几场戏** → 他怎么走进来 / 怎么说话,**不违和**。≈ 把**已是 per-minister 的 `chat_messages`** 升级成"每人的场景流"。
- **总叙事主线**:记**重大决策与走向** → 整体节奏的**连续性**。≈ **章节记忆**(`event_memories` chapter_summary,每回合一段)+ `IMPERIAL_NOTES` 的精炼主线。
- **落地最轻**:加厚已有两层,非从零建。

### 8.7 线 2 实现次序(待 #1 想定)
1. #3 回读模型(加厚 per-character 场景流 + 主线汇总)——最轻,可先做。
2. #1 `commit_turn`(scenario 落库 + 接真引擎结算)——硬骨头,想清楚再动。
3. #2 一致性裁判 / hook——#1 完成、看效果后再定。
