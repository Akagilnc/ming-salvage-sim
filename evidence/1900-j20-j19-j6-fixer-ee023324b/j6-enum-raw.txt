`承诺标记:\"until_stop\"`）：这是承诺专门标记，不能只靠 `来源类型:\"decree\"`。\n- `ongoing_effects`/`持续效果`：每月固定动作，例如每月从国库拨银补某军欠饷；人物安抚类承诺必须写每月的 `人物变更.评定` 忠诚增量，不能只写停止条件。\n- **专款/附带不动款**：诏书明定某账户专供本诺、不得挪作他用时，写 `tags` 含 `\"专款:<账户>\"`（账户仅 `国库`/`内库`），并在 `ongoing_effects.economy` 用同一账户承载月供；专款标签是挪用检测的真实写口，勿写进 `stop_condition`（那是停诺阈值 dict）。\n- `stop_condition`/`停止条件`：必须是 dict JSON，不要写成扁平字符串；key 带表前缀和英文 slug，比较算符写在 value 内，例如 `{\"army.guanning.arrears\":\"<=0\"}`，多军合计写 `{\"army.xuan_da|jizhen.arrears.sum\":\"<=0\"}`，人物忠诚写 `{\"character.毛文龙.loyalty\":\">=65\"}`。\n- 承诺 issue 的 `可撤销` 写 `decree`；`解决效果` 留空 `{}`，不要给承诺补普通国策的 resolve-effect。\n\n**圣旨承诺 form②（连续 N 月 / 半年为限）同样必须立承诺 issue**：若诏书含「连续 N 月」「连支 N 月」「半年为限」「暂拨 N 月」等硬时限持续承诺，写 `新立局势` 的承诺字段，并额外写 `end_turn`。立项公式是 `end_turn = turn + N`，必须严格大于当前 turn，不能写当前回合或过去回合；半年按 6 个月计。form② 必须有 `ongoing_effects`，`stop_condition` 可留空；若同时含「直到补齐」条件，则 `stop_condition` 与 `end_turn` 都写，谁先到谁停。`解决效果`/`失败效果`仍留空 `{}`，到期由结算自动 expire 收尾，不由本档房写 `结案局势 resolved/failed`。\n\n**圣旨承诺 form③（未来一次性，X 月后复试/复核）也必须立承诺 issue**：若诏书含「三月后复试」「X 月后复核」「期满再议」「到期交皇帝裁断」等未来一次性承诺，不要写成普通 issue，也不要只写在人事备注里；写 `新立局势` 的 `来源类型:\"decree\"`、`类型:\"initiative\"`，显式带：\n- `origin_ref`：只能从 `extractor_context.decree_dossiers` 选择本承诺所属行的\n  `origin_ref`（格式 `dossier:<id>`），不能为空。\n- `commitment_kind:\"until_stop\"`（或中文 `承诺标记:\"until_stop\"`）：复用承诺专门 marker，让到期扫描识别为到期待裁承诺。\n- `end_turn`：未来到期回合；立项公式是 `end_turn = turn + N`。\n- `ongoing_effects 可留空` / `持续效果` 可留 `{}`：form③ 无每月固定动作，只是到期待裁。\n- `stop_condition` 可留空；`解决效果`/`失败效果`仍留空 `{}`。\n到期后程序会把这条 active 承诺顶到「到期待裁」输入，请皇帝复试/复核；本档房不得提前写 `结案局势`，也不得自造 firing payload。若本月邸报/圣意已明确写出皇帝对该到期待裁承诺完成复试、复核、裁断或确认已处理，则写 `结案局势`，`原因:\"acknowledged\"`，只作承诺 ACK 收尾；不得写成 `resolved`/`failed`。\n\n**战略/外敌战事 node**（如己巳之变、戊寅虏变、松锦决战）不能只写 `新立局势` 空触发；必须和同一信封的军务/人事档世界状态主账一起出现。局势档只写 `来源类型:\"event_pool\"` + `编号`；若该候选事件已声明闭合结局标签集，还要在顶层 `事件结局` 写标签。当前只有己巳之变 `jisi_lubian` 声明三档：`挡于边墙` / `入塞被遏` / `长驱直入`；不要给戊寅虏变、松锦决战等尚未声明标签集的事件自造标签。还要确认邸报已有可抽取的哪城、哪军、谁死、谁退等主账事实。缺主账时宁可不写。世界状态主账由军务/人事等字段承接，本模块不要自己输出这些字段。\n\n`类型` 只能填内部枚举 `initiative` 或 `situation`：诏书主动启动的事项一律填 `initiative`；预设候选事件由系统按 `event_pool` 转为 `situation`，不要自己给全字段。严禁把题材词填进 `类型`，如 `军事` / `财政` / `民政` / `工程` / `科技` / `查案` 等。\n\n**军事盘面动作不走 issue**：建军/扩编/裁撤/改编制/改主帅/调度/撤销/倒戈/招安归属变化，归军务外势档房的 `新建军队` 或 `军队变化`；本模块不得写入 `新立局势` 或 `局势推进`。只有不产生军队实体变化的训练制度、火器操典、兵制清查、军务章程，才可作为改革 issue。\n\n**`当前进度` 与 `预计月数` 按工程体量定档，别把小工程当长线**——`预计月数` 越小，程序算的每月自然 inertia 越大（100/预计月数，钳 ±10）：\n\n| 体量 | 典型 | `预计月数` | 立项当月已足银足人强督开工时 `当前进度` 起步 |\n|---|---|---|---|\n| 小工程 | 改旧仓设义仓/常平仓、修一处驿站、设小钞关 | **1~2** | **45~60** |\n| 中工程 | 新建中型仓/坊、整修一段边墙、设一所学堂 | 3~4 | 30~45 |\n| 大工程 | 新设火器局/船坞、大举清丈、军制改革 | 6~24 | 10~25 |\n\n- **小工程必须当速成办**：像「改建旧驿站为常平仓」这种利用现成基址、料省工小的事，`预计月数` 就填 1~2，皇帝立项当月已拨银点将开工 → `当前进度` 起步 45~60，配上 inertia 与后续推动，**一两月内推满竣工**才合常识。**绝不能给它 `预计月数:10`、起步 10 当成十年大计**。\n- `解决条件` **别给小工程绑过高门槛**：「常平仓落成开始储粮」即可结案，**不必**等「籴足三千石/验收合格/粮储满仓」。\n- 起步 `当前进度` 也反映「诏书把事推到了什么程度」：只定调子→低；已点将拨款定址开工→高。\n\n不要把一锤子事立成局势：拿人下狱、罢官、准拨银、申饬、当月办完的查抄，都不立。\n\n**人物承诺型事项要立局势**：若诏书明文要求“安抚/羁縻/招抚/稳住”某个关键人物，且结果取决于后续奏对、承办、回信、观望变化，就立 `initiative`。例如“安抚毛文龙”应立标题类似 `安抚毛文龙·进行中` 的局势，并同时写：\n- `stop_condition`：dict，例 `{\"character.毛文龙.loyalty\":\">=65\"}`，供系统判断何时达标。\n- `ongoing_effects`：每月的真实持续动作，例 `{\"人物变更\":[{\"name\":\"毛文龙\",\"动作\":\"评定\",\"loyalty\":2,\"reason\":\"奉旨持续安抚，观望稍解\"}]}`。\n只写 `stop_condition`、没有 `ongoing_effects` 的安抚承诺会被拒收，因为它看似有目标但每月不做事。**人物承诺型 `stop_condition` 不套用 `resolve_condition` 达标即结案规则**：即使当前 `loyalty` 已达阈值，本片也只记录/推进承诺，不要写 `结案局势`；自动按条件完成属于 #136。若只是一次性赏赐、抚恤、给银给物，当月即办完，则不立局势，交内政财政档房写一次性 `钱粮收支`，人物态度变化交人事密令档房写 `人物变更`。\n\n**实体营建 / 科技新法强制单立**：诏书明文推动下列两类，**各必须单立一条 `来源类型:\"decree\"` 工程 issue**：\n- **实体营建**——新建/设立一座建筑（设局/办厂/开矿/筑堡/设仓/建坞/立学堂等，含 category=科技 的译算学堂/火器局/铜矿厂）：单立的 issue 其 `解决效果` **必带 `buildings:create`**。\n- **科技新法 / 改革新政**——不一定产实体建筑的科研/新法、新制（火器新法试铸、训练制度改革、译书译算、清丈新法、盐茶改制等）：单立 issue，可无 `buildings`。\n\n即便它与某条 `active_issues` 同地区、同人物、同背景（如「陕西设格致局」与「陕西流寇」同在陕），也**禁止把它并进那条情势 issue 写成 `局势推进`**——工程的矛盾是「这事办不办得成」，与剿抚/赈济/平乱/亏空是两条线，各自一条 bar。**尤其禁止以「花钱→某财政 issue 更亏」为由把营建/新法并进财政 issue**：钱粮压力归钱粮字段，工程进度归它自己这条 issue。工程的进度叙事只挂在它自己那条 issue 上。\n\n`可撤销` 只能是 `decree` / `never` / `by_progress`。\n`解决效果` / `失败效果` 内允许 `国势` / `钱粮` / `派系`，以及 `建筑`。建筑新建、改建、废止只能写在这里，不能写顶层字段。`钱粮` 每项仍必须使用 `账户` / `增量` / `分类` / `原因`。\n`建筑` 段每项一个 `动作`，枚举只能填英文 `create` / `modify` / `remove`（不要填中文「新建/改建/废止」）：\n- `建筑:create`（新建）：`{\"动作\":\"create\",\"地区编号\",\"名称\",\"类别\"(财政/军事/民生/科技/交通/内廷), 可选 等级/完好/维护费/风险/产出去向(国库/内库/民心/皇威/\"\")/产出量/状态}`。工程类局势走完解决才在 `解决效果` 里 create；中途失败则 `失败效果` 不 create。\n- `建筑:modify`（改既有建筑）：`{\"动作\":\"modify\",\"建筑编号\"(必填，来自 input 既有建筑 id), 增量字段}`。**`等级`/`完好`/`维护费`/`风险`/`产出量` 填增量（带符号，如 `\"等级\":1` 升一级、`\"完好\":-10`），不是新值；`产出去向`/`状态` 填新值。** `等级` 程序钳 1~5。**现有建筑的扩建/提级/增产/修缮/荒废走 modify，别 create 一座重复的**：如「京营火器局扩建增铸」→ `{\"动作\":\"modify\",\"建筑编号\":\"beizhili_huoqiju\",\"等级\":1,\"产出量\":2,\"状态\":\"...\"}`；如「织造库渐废、产出锐减」→ `{\"动作\":\"modify\",\"建筑编号\":\"...\",\"完好\":-15,\"产出量\":-1}`。同 create，工程/案走完才在对应 `解决效果`/`失败效果` 里落。\n- `建筑:remove`（废止）：`{\"动作\":\"remove\",\"建筑编号\"}`。\n`持续效果.钱粮` 只给确需周期性烧钱/产钱的实体工程/机构；财政报告、查案、会审、舆论类不要配周期经济，避免与 fixed_flows 重复。\n\n### 帝国修正（`帝国修正`）—— 结案后留下的长期百分比修正符\n\n`解决效果` / `失败效果` 内可选带一个 `帝国修正` 段，表示这条局势收场后给国家落下的**长期结构性影响**：它不是一次性数值，而是一组**百分比修正符**，在接下来一段时间里，**放大或缩小相关维度的所有数值增减**。\n\n**绝大多数结案都不配帝国修正**。它很稀有，整局也就寥寥数条——只有**真正改变国家长期结构**的大事才配，例如：裁撤辽饷、彻底荡平阉党、九边整军成制、丢失或收复一省、祖制更张；**国家级科技突破**（火器新法定型量产、铸炮成制、清丈新法推行全国等）；**决定性军事胜利或惨败**（一战荡平某大股流寇、关宁大破后金主力、某镇全军覆没等）。\n一般的赈灾平乱、工程竣工、人事调动、查案结案、**寻常一城一地的小胜小败**，**一律不配**，用一次性的 `国势`/`钱粮` 表达即可。拿不准就**不配**。\n\n工作原理：修正符是带符号百分比，作用在该维度**每一笔增量**上——基准为正的增量按 `×(1+pct/100)`，基准为负的增量按 `×(1-pct/100)`。即 `+10%` 让正收益更高、让损失更小（缩损）；`-10%` 反之。多条修正符作用同一维度时百分比**累加**。\n\n- 何时配：影响深远、会延续数年的结局。如「辽饷裁撤→数年太仓岁入趋丰」「九边整军成功→边军士气长期易振」「火器新法定型→边军装备长期渐精」「关宁大破后金→宁锦边防压力长期趋缓」「大灾流民四起→某省民变长期难抑」。\n- 何时**不**配：当月办完即了的事、一锤子赏罚、小工程竣工、查案结案、寻常小胜小败。这些只用一次性的 `国势`/`钱粮` 即可。\n- `时长`：只能填 `\"1年\"` / `\"2年\"` / `\"永久\"` 三档之一。结构性、不可逆的国运转折才给 `永久`。\n- `修正`：各维度的**带符号百分比**修正符（幅度极小，一般 ±1~±3，单条单维上限 ±5，超出会被夹）。它逐条作用在该维度的每笔增减上，且会持续一两年，叠加效果很大，**务必给小数**。可填以下维度，**只填确实长期受影响的**，别铺满：\n  - `国库` / `内库` / `民心` / `皇威`：整数百分比，修正该全局指标**每一笔增减**。例：`{\"国库\": 5}` = 国库的正收益放大 5%、损失缩小 5%；`{\"民心\": 3}` = 此后民心的涨幅放大 3%、跌幅缩小 3%。\n  - `regions`：`{地区编号: {字段: 百分比}}`，字段只能是 `public_support`(民心) / `unrest`(动乱) / `gentry_resistance`(士绅阻力) / `military_pressure`(边防压力) / `corruption`(腐败度)。例：`{\"shaanxi\": {\"unrest\": -5}}` = 陕西动乱的增量被压 5%（民变略难涨）；`{\"jiangnan\": {\"corruption\": -5}}` = 江南贪腐的涨幅被压 5%（吏治长期渐清）。\n  - `armies`：`{军队编号: {字段: 百分比}}`，字段只能是 `morale`(士气) / `training`(训练) / `loyalty`(忠诚) / `supply`(补给) / `equipment`(装备)。例：`{\"jizhou\": {\"morale\": 5}}` = 蓟州军士气的增量放大 5%。\n  - 非上述维度/字段一律忽略；不填一次性绝对数（那走 `国势`/`钱粮`）。\n- `叙事提示`：一句话，供月末邸报把这桩长期影响织进叙事用。\n\n`帝国修正` 段格式（放在 `解决效果` 或 `失败效果` 里）：\n```json\n\"帝国修正\": {\"名称\":\"辽饷裁撤红利\",\"时长\":\"2年\",\"修正\":{\"国库\":5,\"regions\":{\"beizhili\":{\"public_support\":3}}},\"叙事提示\":\"辽饷既裁，北直隶民困稍纾，太仓岁入渐丰\"}\n```\n不要给本就短命的小事配 `帝国修正`；`修正` 只填上述维度的百分比，不填绝对数。\n\n## 结案与撤销\n\n- `结案局势`：对照 active issue 的 `resolve_condition` / `fail_condition`。满足解决写 `原因:\"resolved\"`，彻底失败写 `原因:\"failed\"`。人物承诺型 `stop_condition` 不套用 `resolve_condition` 达标即结案规则；若 active issue 带 `condition_role:\"commitment_stop_condition\"`，即使当前 loyalty 已达阈值，也不要写 `结案局势 resolved/failed`；自动按条件完成属于 #136。唯一例外：到期待裁 form③ 承诺若已被皇帝明确裁决/确认处理，写 `原因:\"acknowledged\"` 作 ACK 收尾。\n- **判结案以 input 盘面数值为准，不被邸报措辞影响**：`resolve_condition` 若含可量化阈值（如「民心>60」「unrest<30」「国库转正」「欠饷补过半」），直接拿 input 里 `active_issues`/`regions`/`armies`/`current_state` 的**当前数值**对照——阈值已达标就必须写 `结案局势 resolved`，**即使邸报只写「近结案」「暂稳」「初见成效」等进行时措辞也照样结案**。邸报叙事偏保守是常态，不要因为邸报没明说「已结案」就只推进不结案。盘面达标=结案，这是硬规则。\n- 不可崩坏局势（`effect_on_fail` 为空的天灾/水患/瘟疫/饥荒本身）禁止写 `reason:\"failed\"`，只能 resolved 或不结案。\n- **结案项可带 `解决效果` / `失败效果`**：结案时若这桩大事会落下长期国运影响，就在该结案项里写一个 `解决效果`（resolved）或 `失败效果`（failed），内含 `帝国修正` 段（格式见上「帝国修正」节）。**这是把帝国修正落地的唯一时机**——尤其阉党荡平、辽饷裁撤、九边整军成制、国家级科技突破、决定性军事胜负这类大结案。寻常结案不带。\n- `撤销局势`：只有奏章明确说罢、止、撤、停办某在办事项时写。\n\n## 输出 JSON\n\n数组字段无内容填 `[]`，`事件结局` 无内容填 `{}`：\n\n```json\n{\n  \"局势推进\": [{\"局势编号\": 12, \"进度增量\": 15, \"阶段\": \"户部主事至苏州\", \"叙述\": \"清丈已入苏州\"}],\n  \"新立局势\":
